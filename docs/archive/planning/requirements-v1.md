## 1. 제품 목적과 가치관

계획한 시간과 실제 작업·휴식·중단의 흐름을 세로 타임라인으로 기록하고, 회고에서 얻은 생각을 다음 계획 전에 다시 확인하는 개인 시간 기록장이다.

- 계획과 실제의 차이를 관찰할 정보로 다룬다.
- 기록이 실행을 방해하지 않도록 반복 입력과 필수 질문을 줄인다.
- 사용자의 원문과 판단을 보존한다.
- 통계 숫자는 근거 기록으로 추적할 수 있어야 한다.
- 자동 시간 제안, 생산성 점수로 평가하기, 회고 강요를 하지 않는다.
- 개발자 전용 사유를 강요하지 않는다. 공부·운동·업무·창작 등 여러 활동에 사용할 수 있어야 한다.

초기 실제 사용 사례는 사용자의 ‘플랜두씨 다이어리 1 제작’이다. 실제 활동을 기록하며, 예시나 추정 시간을 실제 실행 기록으로 꾸며 넣지 않는다.

## 2. 범위와 예산

### 2.1 이번 버전에 포함

계획과 수정 이력, 계획 상태·전체 삭제, 할 일 관리, 매일 루틴, 일간 세로 타임테이블, 주간 요약, 간단한 월간 캘린더, 작업 타이머와 수동 기록, 휴식·중단 구분, 직접 관리하는 중단 사유, 돌아보기 집계, 선택적 회고, 책갈피, 다음 계획으로 회고 전달, 30일 휴지통, 요약 PDF, 전체 JSON 백업, 실제 서버 DB 저장, 공개 안내, 과제 검증 및 제출 자료. 매일 루틴의 합의 범위는 18절, 핵심 데이터 설계안은 `core-data-design-v1.md`에 기록한다.

### 2.2 이번 버전에서 제외

- 외부 LLM 호출 및 AI 자동 분류
- 공개 모델의 자체 호스팅, 모델 학습·추가 학습
- 회원가입·로그인·초대·이메일 확인·계정 활성화·최초 비밀번호 설정·비밀번호 변경·비밀번호 재설정
- 네이티브 모바일 앱, 잠금 화면 제어, 위젯, 기기 알림
- 오프라인 동기화, 외부 캘린더 연동, 팀 협업, 결제, 복잡한 반복 규칙(매일 루틴은 별도 추가 요청)
- 자동 시간 추천 및 자동 일정 변경
- JSON 파일 가져오기·자동 복원

- 타이머만으로 실제 인지적 집중 상태를 측정한다고 주장하는 기능

### 2.3 비용 제약

- 외부 LLM 사용 예산은 0원이다.
- 무료 체험·무료 크레딧·무료 API 한도를 핵심 기능의 전제로 삼지 않는다.
- API 키 구매, 유료 AI 구독, 사용량 초과 결제, 자체 모델 운영을 전제로 진행하지 않는다.
- 중단 사유의 직접 입력·선택·수정과 일반 DB 집계로 기능을 완성한다.
- AI는 향후 검토 항목일 뿐이며 과제 7의 확정 제공 기능이나 출시 약속이 아니다.
- DB·호스팅 제공자와 운영 비용은 아직 미정이다. AI를 제외했다는 이유로 전체 서비스 운영비도 0원이라고 단정하지 않는다. 기술 선정 시 무료 운영 가능 범위와 한도를 확인한다.

## 3. 공개 범위 및 권한 요구

### PUB-01 공개 안내

첫 화면에 다음 문장을 그대로 표시한다.

> 지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다. 남이 봐도 괜찮은 내용만 넣으세요

- 신문형 상단의 발행 문구 자리에는 `공개 다이어리 · 링크를 아는 사람은 누구나 보고 수정할 수 있음`을 함께 표시한다.
- 추후 로그인·회원가입과 소유권 검증을 구현한 버전에서는 이 짧은 문구 자리를 현재 사용자 정보·계정 메뉴로 바꾼다. 과제 6에서는 사용자 정보가 있는 것처럼 꾸미지 않는다.

### PUB-02 과제 접근성

- 결과물과 소스 URL은 새 시크릿 창에서 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 열린다.
- 과제의 생성·수정·삭제·기록·회고 기능은 로그인을 요구하지 않는다.
- 비공개 개인 작업공간이나 사용자별 보호가 구현된 것처럼 표현하지 않는다.
- 실제 입력 자료는 공개 가능한 사용자의 활동만 사용한다. 타인의 이름·연락처·회사 내부 정보·민감한 회고를 넣지 않는다.
- 하나의 공개 다이어리에 방문자의 편집을 서버 저장한다. 새로고침으로 초기 예시로 되돌리지 않는다.
- 다른 창에서 같은 자료가 바뀌면 최신 내용을 확인하도록 안내하고 작성 중 입력을 보존한다. 오래된 수정으로 최신 저장값을 덮어쓰지 않는다.

### PUB-03 향후 인증과의 경계

회원가입과 로그인은 데이터별 접근 권한 검증을 대체하지 않는다. 추후 비공개 전환 시 서버의 기록 소유권 검증과 기존 공개 자료의 처리까지 따로 검증한다. 이미 공개한 내용은 로그인 도입으로 소급해 비공개가 되지 않는다.

## 4. 계획과 할 일

### PLAN-01 계획 필드

계획은 고유 ID, 제목, 기간, 우선순위, 성공 기준, 예상 시간을 갖는다. 계획 기간의 시작과 종료를 저장한다.

### PLAN-02 계획 수정 이력

- 수정해도 계획 ID는 유지한다.
- 처음 계획과 이후 버전의 내용·수정 시점을 조회할 수 있다.
- 현재 값과 이전 버전을 구분해 저장한다.
- 실행 기록 저장으로 계획 값이나 이전 버전을 덮어쓰지 않는다.

### TASK-01 기본 관리

- 할 일은 계획에 연결한다.
- 생성, 수정, 완료, 완료 취소, 휴지통 이동이 가능하다.
- 마감일, 우선순위, 사용자 태그, 예상 시간을 저장한다. 태그는 과제 필수 저장 항목이므로 제거하지 않되 고정 분류를 제공하지 않고 할 일 편집의 보조 입력으로 둔다.
- 할 일 태그와 중단 사유는 별도 개념으로 다룬다.

### PLAN-03 계획 상태

- 진행 중·마무리·보관 상태를 제공한다.
- 계획 마무리가 할 일을 자동 완료시키지 않는다.
- 보관은 기본 목록에서 숨기는 동작이며 자료와 통계는 보존한다.
- 마무리·보관한 계획을 다시 진행할 수 있다.
- 계획도 연결 자료와 함께 휴지통에 이동할 수 있다. 독립된 일간 회고 전체를 연쇄 삭제하지 않는다. 상세는 18절 P-02와 핵심 데이터 설계안을 따른다.

### TASK-02 검색·필터·정렬

- 검색, 조건 필터, 정렬을 제공한다.
- 현재 적용한 필터·정렬 기준을 화면에 표시한다.
- 같은 값의 할 일도 순서가 매번 바뀌지 않도록 마지막 동률 해소 기준을 둔다.
- 검색은 할 일 제목·설명을 대상으로 한다. 태그는 기본 검색·필터와 목록에서 노출하지 않는다.
- 첫 버전의 기본 필터는 완료 여부만 제공한다. 선택한 상태와 초기화를 표시한다.
- 기본 정렬은 완료 여부와 관계없이 마감 가까운 순이며 동률은 우선순위 높은 순·생성순·ID로 해소한다. 마감 없는 항목은 마감일순의 뒤에 둔다.
- 완료·완료 취소는 현재 정렬 기준 안에서 할 일의 위치를 바꾸지 않는다. 사용자가 정렬 기준을 직접 바꿀 때만 목록 순서를 다시 계산한다.
- 추가 정렬은 우선순위순·최근 추가순이다. 임의 드래그 순서와 예상 시간순은 이번 범위에서 제외한다. 일정은 시작 시각순이다.

## 5. 타임테이블과 캘린더

### TIME-01 일간 기본 화면

- 시간은 위에서 아래로 흐른다. 시간을 확인하기 위한 가로 스크롤을 기본 사용 방식으로 삼지 않는다.
- 계획과 실제를 같은 시간축에서 비교한다.
- 계획 배치에는 시작 예정 시각과 예상 시간을 사용하고 종료 예정 시각은 계산한다.
- 시간을 정하지 않은 할 일은 ‘미배치 할 일’로 표시한다.
- 계획이 겹치면 충돌을 안내하고, 사용자가 확인하면 겹친 계획을 저장할 수 있다.
- 기본 표시 범위는 오전 6시부터 다음 날 오전 3시까지다.
- 표시 범위 밖의 새벽 기록도 입력·조회할 수 있다. 기본 표시 범위를 기록 제한으로 사용하지 않는다.
- 모바일은 일간 중심으로 날짜를 이동한다.
- 날짜 띠와 주간 화면의 요일 순서는 일요일부터 토요일까지로 통일한다. 1주는 7일이므로 `일·월·화·수·목·금·토` 한 번씩만 표시한다.
- 하나의 할 일을 여러 날짜·시간 블록으로 나누어 배치할 수 있다. 블록이 여러 개여도 할 일 개수와 예상 시간은 중복 집계하지 않는다.
- 할 일 예상 시간과 배치 시간 합계가 다르면 차이를 보여주고 예상 시간을 자동 변경하지 않는다.
- 예정하지 않은 작업은 기존 할 일을 선택하거나 사용자 확인으로 새 할 일을 만든 뒤 실행에 연결한다. 관계 없는 실행이나 임의의 계획을 생성하지 않는다.

### TIME-02 표시 밀도

- 기본 작업 블록에는 작업명, 시작~종료 시각, 상태를 표시한다.
- 집중 기록·휴식·중단 시간과 이유는 상세보기에서 확인한다.
- 휴식·중단의 세부 구간 표시 방식은 와이어프레임에서 검증하며 기본 화면에 모든 수치를 나열하지 않는다.
- 색상 외에도 라벨·선·상태 표시로 계획과 실제를 구분한다.
- 접힌 시간대는 누르면 같은 `시간·계획·실제` 3열 구조의 시간 행으로 펼쳐진다. 기록이 없는 시간도 빈 행으로 보여 시간축이 건너뛰지 않았음을 알리고, 다시 접을 수 있다.

### TIME-03 주간·월간

- 주간은 날짜별 요약과 계획 목록을 제공한다.
- 월간은 날짜 탐색용 캘린더로 제공한다. 오늘, 기록 유무, 주요 마감을 간결하게 표시한다.
- 월간은 선택한 달의 1일부터 마지막 날까지 모두 표시하며 요일 머리글은 일요일부터 시작한다. 첫째 주 앞쪽과 마지막 주 뒤쪽은 빈 칸으로 정렬한다.
- 월간에서 날짜를 선택하면 해당 일간으로 이동한다.
- 가까운 날짜 띠와 주간의 날짜도 선택하면 해당 일간으로 이동하며, 날짜 띠는 선택한 날짜가 속한 일요일~토요일을 다시 표시한다.
- 선택 날짜와 서울 기준 오늘을 별도로 표시한다. 오늘이 아닌 날짜를 보고 있을 때에는 `오늘로 돌아가기`를 제공한다.
- 과거 일간은 그 날짜에 배치했던 계획 블록·실행 기록·회고를 조회하고 잘못 입력한 실행 기록을 정정할 수 있다. 과거 시점의 데이터 전체 상태를 재현하는 기능은 아니다.
- 미래 일간은 미리 세운 계획·자동 배치된 루틴을 조회·수정할 수 있으나 실제 기록 시작은 허용하지 않는다. 실제 영역에는 아직 기록할 수 없는 미래 날짜임을 표시한다.
- 월간에서 시간 구간 편집이나 다수의 통계를 동시에 노출하지 않는다.

## 6. 실행 기록과 타이머

### DO-01 시작·멈춤·재개·종료

- 작업 시작, 잠시 멈춤, 다시 시작, 이번 기록 마치기를 제공한다.
- 한 번에 하나의 작업 타이머만 진행한다. 중단·휴식 중인 열린 기록도 종료하기 전에는 다른 기록을 시작하지 않는다.
- 다른 작업에는 현재 기록을 종료한 뒤 시작할 수 있다는 이유를 표시한다.
- 잠시 멈추면 즉시 미분류 멈춤 구간을 시작하고 화면에는 ‘다시 시작’과 ‘이번 기록 마치기’만 둔다. 휴식·예상하지 못한 중단 분류와 이유 메모는 재개 후 또는 기록 상세에서 선택적으로 정정한다.
- 짧은 멈춤도 사용자가 기록했다면 보존한다. 임의로 작업 시간에 합치지 않는다.
- 한 할 일을 나누어 진행하는 경우에는 열린 실행을 장시간 멈춤으로 유지하지 않는다. 현재 실행을 종료하되 할 일은 진행 중으로 남기고, 나중에 같은 할 일에서 새 실행을 시작한다.
- ‘추후 다시 진행 예정’은 막힘 사유가 아니라 할 일이 아직 완료되지 않았다는 상태다. 이를 막힘으로 집계하지 않는다.

### DO-02 기록 종료와 할 일 완료의 분리

- ‘이번 기록 마치기’는 이번 실행만 끝내며 할 일 상태를 자동으로 바꾸지 않는다.
- 처음 누른 시각을 종료 후보 시각으로 고정하고 가까운 확인 영역에 ‘계속 기록’과 ‘기록 마치기’를 제공한다. ‘계속 기록’은 후보 시각을 버리고 같은 실행을 이어가며, ‘기록 마치기’는 처음 누른 후보 시각으로 저장한다. 확인에 머문 시간을 작업 시간에 더하지 않는다.
- 확인 영역이 열려 있는 동안에는 다른 작업을 시작할 수 없다. 확인 요청과 저장 요청은 각각 중복 처리되지 않아야 한다.
- 저장 실패 시에는 기록 상태와 입력, 종료 후보 시각을 보존해 다시 시도할 수 있게 한다.
- 할 일 완료는 오늘 할 일 목록이나 작업 상세에서 별도 행동으로 제공한다. 실행 종료 화면에 ‘이 할 일도 완료’ 체크박스를 넣지 않는다.
- 실수로 종료한 기록은 기록 수정에서 시작·종료 시각과 구간을 정정한다. 실행 기록 수정과 할 일 완료 취소를 서로 다른 동작으로 유지한다.
- 잠시 멈춤은 버튼을 누른 시각부터 작업 시간에서 제외하며, 분류를 나중에 정정해도 원래 시각은 유지한다.

### DO-03 시간 정의

- 전체 경과 시간: 실행 시작부터 종료까지의 시간.
- 집중 기록 시간: 사용자가 작업 중으로 기록한 구간의 합. 실제 인지적 집중 여부를 측정한 값은 아니다.
- 휴식 시간: 사용자가 휴식으로 지정한 구간의 합.
- 중단 시간: 사용자가 예상하지 못한 중단으로 지정한 구간의 합.
- 미분류 멈춤 시간: 사용자가 구분하지 않은 멈춤 구간의 합. 집중 기록 시간에 포함하지 않는다.
- 과제의 실제 시간은 집중 기록 시간을 사용하며 화면과 계약에 그 정의를 표시한다.
- 전체 경과 = 집중 기록 + 휴식 + 중단 + 미분류 멈춤이 되도록 시간 구간을 중복 없이 저장·계산한다.
- 막힘 이유는 시간 구간과 별개다. 문제 해결을 계속하고 있었다면 작업 시간에 포함하면서 막힘 이유를 적을 수 있다.

### DO-04 저장·수정

- 각 실행은 해당 할 일에 연결하고 시작, 종료, 실제 시간, 막힘 이유를 별도로 저장한다.
- 하나의 할 일에 여러 실행 기록을 연결할 수 있다.
- 예를 들어 1시간으로 계획한 할 일을 30분씩 두 번 수행하면 같은 할 일에 종료된 실행 기록 두 건을 연결하며, 그 사이 시간은 실행 기록이나 막힘 시간으로 자동 포함하지 않는다.
- 타이머와 직접 입력을 지원한다. 수동 입력에도 같은 시간 검증을 적용한다.
- 시작·종료·휴식·중단과 이유를 정정할 수 있고 이전 값은 이력으로 보존한다.
- 저장 실패 시 입력과 타이머 상태를 잃지 않고 재시도할 수 있다.
- 새로고침·백그라운드 전환 후 저장된 시각으로 상태를 복원한다. 화면의 숫자 증가에만 의존하지 않는다.
- 브라우저를 닫거나 다른 앱으로 이동해도 기록을 자동 종료하거나 휴식으로 변경하지 않는다. 다시 열 때 진행 중 기록을 복원하고 계속하기·종료 시각 정정을 제공한다.
- 종료한 실행만 확정 집계와 PDF에 포함한다. 열린 실행은 현재 기록 중인 시간으로 따로 표시한다.
- 종료가 시작보다 앞선 구간, 실제 실행끼리 중복되는 구간, 실행 범위 밖의 휴식·중단은 오류 위치를 안내하고 저장을 막는다. 계획의 겹침 허용과 구분한다.
- 앱 공통 영역에서 작업명·분 단위 경과·종료 동작을 제공하고 ‘화면을 닫아도 종료할 때까지 시간이 계산됩니다’를 안내한다. OS 알림이나 백그라운드 프로세스 동작 보장을 구현한 것처럼 표현하지 않는다.
- ‘실행 기록 수정’은 실제 시작·종료 시각, 작업·휴식·중단 구간과 막힘 사유를 정정하며 실제 시간 집계에 영향을 준다. ‘할 일 정보 수정’은 제목·설명·마감일·우선순위·태그·예상 시간을 바꾸며 과거 실행 시각을 바꾸지 않는다. 완료·완료 취소는 할 일 상태 동작으로 별도 유지한다.

### DO-05 중복 및 동시성

- 연속 클릭·요청 재시도로 실행 종료와 완료 기록이 중복 생성되지 않는다.
- 버튼 비활성화뿐 아니라 서버의 같은 요청 식별과 DB 제약으로 보장한다.
- 완료 집계는 현재 완료 상태인 할 일을 한 번씩 센다.
- 완료 취소 후 다시 완료한 경우에도 현재 완료 수는 해당 할 일에 대해 최대 1이다.
- 여러 탭에서 타이머를 시작·종료하는 경우를 테스트한다.

## 7. 중단·막힘 사유: AI 없이 완성

### REASON-01 원문과 사용자 분류

- 사유는 자유롭게 작성할 수 있고 원문을 보존한다.
- 분류는 선택사항이며 미분류 상태로도 저장할 수 있다.
- 사용자가 만든 사유 목록에서 기존 사유를 선택하거나 새로운 사유를 만든다.
- 개발 관련 사유를 기본 정답으로 강요하지 않는다.
- 한 기록의 사유 선택 변경과 사유 이름 전체 변경을 구분한다.
- 사유 이름 변경은 연결된 기록의 표시에도 영향을 준다는 안내를 제공한다.
- 사유 보관 시 새 선택 목록에서 숨기고 기존 기록의 연결은 유지한다.
- 사용자의 확정값을 자동으로 변경하지 않는다.
- 이번 버전은 텍스트 검색·선택·일반 집계를 사용한다. 의미 이해를 수행하는 AI라고 표현하지 않는다.

### REASON-02 미래 확장 원칙

AI를 향후 검토하더라도 원문·제안·사용자 확정값을 분리하고, 사용자 승인 전에는 제안을 적용하지 않는다. 분석 도중 사용자가 바꾼 기록을 오래된 제안이 덮어쓰지 못하게 한다. 지금은 AI 기능·외부 전송·모델 학습·AI 운영용 테이블을 구현할 필요가 없다.

## 8. 돌아보기 집계

### SEE-01 과제 집계 공식

집계 대상으로 선정된 계획의 삭제되지 않은 할 일 집합을 T로 둔다. 기본은 ‘선택한 계획·전체 기간’이며 해당 계획의 모든 유효한 할 일을 포함한다. 기간을 제한하면 마감일이 해당 기간인 할 일만 포함하고, 그 할 일의 종료된 유효 실행 전체 시간을 사용한다. 마감일 없는 할 일은 전체 기간에는 포함하되 마감 기간 필터에서는 제외한다. 화면·서버·PDF·근거 목록에 같은 규칙을 적용한다.

| 항목 | 정의 |
|---|---|
| 계획 수 | T의 할 일 수. 상위 계획 문서 개수가 아니다. UI에서 ‘계획한 할 일’ 등으로 의미를 명확히 한다. |
| 완료 수 | T 중 현재 완료 상태인 할 일 수 |
| 지연 수 | T 중 미완료이며 마감일이 서울 시간 기준 오늘보다 앞선 할 일 수 |
| 막힘 수 | T 중 유효한 실행 기록에 비어 있지 않은 막힘 이유가 하나 이상 있는 할 일 수. 이유가 여러 건이어도 할 일은 한 번만 센다. |
| 예상 시간 | T의 할 일 예상 시간 합계. 상위 계획 예상 시간과 중복 합산하지 않는다. |
| 실제 시간 | T에 연결된 유효한 실행 기록의 집중 기록 시간 합계 |
| 차이 | 실제 시간 − 예상 시간 |

- 대상 자료가 없으면 숫자는 0이다.
- 완료한 할 일을 지연으로 중복 집계하지 않는다.
- 휴지통의 할 일과 실행 기록은 일반 집계에서 제외한다.
- 할 일 완료 여부와 실행 기록의 존재를 동일한 개념으로 취급하지 않는다.
- 과거 마감 기간을 선택하더라도 완료·지연은 현재 상태와 서울 기준 오늘을 사용하고 ‘현재 상태 기준’을 표시한다. 과거 시점 상태를 재현하는 기능은 이번 범위에서 제외한다.
- ‘계획 결과’와 ‘날짜별 시간 사용’을 구분한다. 후자는 선택 날짜에 실제 발생한 시간 부분만 합산한다. 오늘 마감 작업을 어제 30분·오늘 30분 했다면 계획 결과 실제 시간은 60분, 오늘 시간 사용은 30분이다.

### SEE-02 근거 추적

- 각 집계 숫자를 누르면 같은 필터를 적용한 근거 기록으로 이동한다.
- 할 일 개수는 할 일 목록, 시간 합계는 관련 할 일·시간 구간으로 추적한다.
- 차이는 예상·실제의 구성 기록을 함께 확인할 수 있게 한다.
- 필터·단위·집계 범위를 화면에 명시한다.
- 타임테이블의 특정 날짜 작업 시간과 과제의 대상 할 일 전체 실행 시간 집계를 혼동하지 않는다. 필요하면 이름과 범위를 구분해 표시한다.

## 9. 선택적 회고와 책갈피

### REVIEW-01 하루 마무리

- 사용자가 ‘오늘 마무리하기’를 눌렀을 때 회고 여부를 묻는다.
- 단계는 ‘열린 기록·미완료 일 확인 → 선택적 회고 입력 → 완료’로 단순화한다.
- 별도의 ‘나중에’, ‘기록하지 않기’, 마지막 단계의 ‘닫기’ 버튼은 두지 않는다. 흐름을 중단하려면 우측 상단 X로 닫는다.
- 회고 입력이 공백이어도 ‘마무리하기’로 완료할 수 있다. 이는 회고를 강요하지 않기 위한 동작이며 누락을 실패로 표시하지 않는다.
- 마지막 단계에는 지난 기록을 확인하는 선택적 이동만 제공한다. 하루 마무리 완료를 별도의 닫기 버튼에 의존시키지 않는다.
- 일간 회고는 날짜당 한 개를 기본으로 하고 수정 가능하다. 마감·건너뛰기 이후에도 기록과 회고를 추가·정정할 수 있고 집계를 갱신한다.
- 진행 중 타이머가 있으면 먼저 종료 여부를 안내한다. 하루 마감을 자료 잠금으로 사용하지 않는다.

### REVIEW-02 질문

첫 버전의 하루 마무리에서는 질문을 하나만 제공하며 답변은 선택사항이다.

> 다음 계획 전에 기억하고 싶은 것은?

계획과 실제의 차이·잘 흘러간 부분은 사용자가 이 한 문장 안에 자유롭게 적을 수 있다. 질문을 여러 개로 늘리거나 필수 입력으로 만들지 않는다.

### REVIEW-03 다음 계획과 책갈피

- 사용자가 선택한 회고 문장만 다음 계획 시작 전에 보여준다.
- ‘이번 계획에 붙이기’, ‘책갈피만 유지’, ‘넘기기’를 제공한다.
- 붙이기를 선택하면 새 계획의 참고 메모로 저장하고 원본 회고와의 연결을 남긴다.
- 예상 시간 제안·자동 변경을 하지 않는다.
- 회고 전체 또는 특정 문장에 책갈피를 붙일 수 있다.
- 날짜와 계획 이름으로 책갈피를 찾을 수 있다.

## 10. 삭제와 복원

### TRASH-01 30일 휴지통

- 계획·할 일·실행 기록 삭제는 먼저 휴지통으로 이동한다.
- 삭제 직후 일반 목록과 집계에서 제외한다.
- 삭제 후 30일 동안 복원할 수 있고 기한을 표시한다.
- 할 일 삭제 시 연결된 실행 기록을 함께 처리해 관계가 끊어진 기록을 만들지 않는다.
- 복원 시 함께 삭제된 관계를 복구한다. 별도로 먼저 삭제했던 기록까지 잘못 복원하지 않도록 삭제 범위를 추적한다.
- 휴지통에서 사용자가 영구 삭제를 선택할 수 있다.
- 기한 만료 후 영구 삭제를 실제 수행하는 처리와 검증을 구현한다. 숨김을 영구 삭제라고 부르지 않는다.
- 삭제 이력·백업에 개인정보 원문이 무기한 남는지, 만료 처리 주기와 복원 경계는 데이터 설계에서 명시한다.

## 11. 내보내기

### EXPORT-01 사용자용 요약 PDF

사용자가 기간을 정하고 ‘내보내기(PDF)’를 누르면 앱에서 정한 구성의 요약 보고서를 받는다. 사용자가 수십 개 필드를 조합하도록 요구하지 않는다. 전체 원문과 이력은 PDF에 모두 넣지 않는다.

아래 구성과 분량 제한은 사용자의 ‘정해진 항목으로 요약 보고서 제공’ 요구를 구체화한 v1 편집 기준이며 디자인 단계에서 시각 검증한다.

| 구성 | 내용·분량 원칙 |
|---|---|
| 보고서 정보 | 제목, 선택 기간, 생성 시각, 시간대, 적용한 계획 필터 |
| 핵심 수치 | 계획한 할 일·완료·지연·막힘 수, 예상·실제·차이 |
| 시간 사용 | 집중 기록·휴식·중단·미분류 멈춤 시간. 대상 범위를 명시 |
| 주요 막힘 사유 | 사용자가 분류한 사유별 집계 상위 5개와 나머지 합계, 미분류 별도 표시. AI 생성 아님 |
| 회고 | 해당 기간의 최근 작성 회고 1건을 발췌. 각 답변은 최대 200자, 긴 내용은 ‘이하 생략’ 표시 |
| 다음 계획 메모 | 해당 기간에서 사용자가 선택한 최근 전달 문장 1건, 최대 200자. 없으면 ‘선택한 메모 없음’ |
| 하단 설명 | 실제 시간의 뜻, 요약본이라는 안내, 상세 자료는 앱·전체 백업에서 확인 가능 |

- 기본 목표는 A4 1~2쪽. 데이터 양이 늘어도 원문 전체를 이어 붙여 무제한으로 길어지지 않게 한다.
- 생성 문장은 고정 서식과 실제 집계로 구성한다. AI 호출이 필요하지 않다.
- 회고가 없으면 ‘작성한 회고 없음’으로 표시하고 임의의 회고나 조언을 생성하지 않는다.
- 사용자 분류를 그대로 사용하고 사유 개수의 집계 기준을 명시한다. 과제의 ‘막힌 할 일 수’와 다른 지표라면 이름을 구분한다.
- 한글 폰트, 긴 제목, 음수·0·큰 숫자, 페이지 넘김, 스크립트 모양 글자를 출력 검증한다.
- 화면과 PDF는 동일한 집계 규칙을 사용한다.
- PDF 출력 엔진은 기술 설계에서 정한다. 유료 변환 서비스를 필수 의존성으로 두지 않는다.

### EXPORT-02 전체 JSON 백업

- 모든 자료를 파일 하나로 내보낸다.
- 계획, 계획 이력, 할 일, 실행 구간, 수정 이력, 사유, 회고, 책갈피, 다음 계획 연결을 포함한다.
- 휴지통에 남아 복원 가능한 자료도 삭제 상태·기한과 함께 포함한다. 영구 삭제된 자료는 포함하지 않는다.
- ID·관계·원본 날짜·단위·시간대·형식 버전을 유지한다.
- 비밀키·서비스 인증 정보는 포함하지 않는다.
- PDF는 요약 열람용이고 JSON은 과제의 전체 자료 내보내기용이다.
- 이번 범위에 JSON 가져오기 기능은 없다. 복원이 된다고 표현하지 않는다.

## 12. 데이터·시간·안정성

### DATA-01 서버 저장

계획·할 일·실행 기록·회고와 연결 관계를 실제 서버 DB에 저장한다. 브라우저 저장만으로 과제 저장 기준을 충족했다고 판단하지 않는다. 새로고침 후 저장한 ID·날짜·값·단위를 비교한다.

### DATA-02 개념 관계

- 계획 → 여러 계획 버전과 여러 할 일
- 할 일 → 여러 실행 기록
- 실행 기록 → 여러 작업·휴식·중단·미분류 멈춤 구간
- 실행 기록 → 막힘 원문 및 사용자가 선택한 사유
- 회고 → 날짜·관련 계획, 책갈피, 다음 계획에 전달한 메모
- 할 일·실행 기록 → 휴지통 상태와 삭제 시각

실제 테이블·필드명·제약은 아직 설계되지 않았다. 구현 후 최종 구조와 날짜 규칙을 `contracts/pds-schema-v2.json`에 작성하여 소스에 포함한다. 현재 명세서를 실제 DB 계약처럼 취급하지 않는다.

### DATA-03 합의한 시간 규칙과 남은 상세 설계

- 화면·마감일·오늘·회고 날짜는 서울 시간 기준이다. 마감일은 시각 없는 날짜이며 해당 날짜가 지난 미완료 할 일만 지연이다.
- 일간 통계와 회고는 자정 기준이다. 전날 시간표 하단의 다음 날 새벽에는 실제 날짜를 표시하고 다음 날 통계에 반영한다.
- 선택 날짜의 00:00~06:00 기록은 접힌 이른 시간 구간에서 조회할 수 있다.
- 자정을 넘긴 실행은 원본 한 건을 보존하고 날짜별 통계에서 시간 부분만 나눈다. 휴식·중단도 실제 발생 시각으로 배분한다.
- 열린 실행은 확정 집계에서 제외한다. 저장 실패 시 입력은 보존하고 재시도한다.
- 화면은 분 단위까지 표시하고 원본 시작·종료 시각은 정밀하게 보존한다. 1분 미만은 별도 표기하며 요약은 원본을 합산한 뒤 표시한다. 구체적 반올림 규칙은 핵심 데이터 설계안에서 검토한다.
- 저장 시간대·DB 자료형·요청 중복 방지·다중 탭 충돌 등 실제 기술 설계는 아직 이루어지지 않았다.

사용자 합의와 후속 기술 설계를 구분한다. 규칙이 정해져 있어도 코드로 검증되지 않은 동작을 보장한다고 보고하지 않는다.

### SAFE-01 입력 및 비밀값

- 스크립트 모양 글자는 저장과 재표시 후에도 실행되지 않고 원문 텍스트로 보인다.
- 브라우저 코드·배포 파일·네트워크 응답·콘솔·Git 기록에 비밀키 원문이 없어야 한다.
- 클라이언트에서 비밀키로 DB를 직접 관리하는 구조를 사용하지 않는다.
- 빈 상태·로딩·저장 실패·재시도·삭제 확인을 설계한다.
- 서버 저장 실패를 성공으로 표시하지 않는다.

## 13. 디자인 방향과 진행 순서

- 시각 방향은 두 시안 중 최종 선택 전이다. 1안은 조선일보명조를 본문·제목에 사용한 회색 신문형, 2안은 고운돋움을 사용한 따뜻한 아이보리형이다.
- 현재 제품 가치와 사용자의 취향을 기준으로는 1안이 우선 권장안이다. 이는 확정 결정이 아니며 최종 디자인 시작 전에 선택한다.
- 1안은 회색 종이·잉크의 낮은 채도를 기본으로 하고, 중요한 차이·선택·예외에만 선명한 형광펜 색을 제한적으로 사용한다. 노랑 `#fee85c`는 유지하며 나머지 보조색은 조화와 대비를 확인해 조정한다.
- 1안의 신문 의도는 상단 제호, 날짜·호수 정보, 얇은 이중선과 하단 면수·발행 정보로 분명하게 드러낸다. 특정 지역판 표기는 사용하지 않는다. 본문은 신문식 다단 편집으로 바꾸지 않고 일정 도구의 읽기 순서와 조작성을 유지한다. 정식 제품명 확정 전에는 임시 제호를 사용한다.
- `시간보`, `시간지`처럼 뜻이 바로 전달되지 않는 조어 대신 `일일 기록지`처럼 익숙한 표현을 사용한다.
- 일간·주간·월간 선택선은 탭 아래 구분선에 수평으로 맞춘다. 손그림 효과를 이유로 기울이지 않는다.
- 2안은 아주 옅고 따뜻한 아이보리 배경과 조금 더 친근한 보조색을 사용한다.
- 글자 대비·포커스·상태 구분은 유지한다. 옅은 색 때문에 읽기 어려워지지 않게 검증한다.
- 여백·얇은 구분선·절제된 움직임을 사용한다. 상태 변경 때 넓은 면적이 번쩍이는 애니메이션은 오류처럼 보이므로 사용하지 않는다.
- 손그림 느낌은 잉크 동그라미·밑줄·평평한 형광펜처럼 의미가 분명한 강조에만 쓴다. 끊겨 보이는 대각선 무늬와 블록 전체 채색은 피한다.
- 계획·실제·중단·예외 범례의 선 방향은 모두 가로로 통일한다. 색만으로 구분하지 않고 라벨과 선 형태를 함께 쓴다.
- 미완료·지연·회고 생략을 비난하는 표현이나 경쟁 점수로 강조하지 않는다.
- 반응형 웹을 먼저 만들고 네이티브 앱은 후속 범위로 둔다.
- Figma는 필수가 아니다. 와이어프레임 단계에서 도구를 선택한다.

### IA-01 합의한 메뉴와 동선

| 메뉴 | 포함 내용 |
|---|---|
| 일정 | 일간 타임테이블, 오늘 할 일(시간 배치됨·미배치), 주간 요약, 월간 캘린더, 현재 타이머. 최초 접속은 오늘 |
| 계획 | 계획 목록·상세, 할 일 관리, 계획 수정 이력 |
| 돌아보기 | 계획 결과, 날짜별 시간 사용, 근거 기록, 과거 회고, PDF 내보내기 |
| 보관함 | 회고 책갈피, 보관한 계획 |
| 상단 설정 | 휴지통, 중단 사유 관리, 전체 JSON 백업. 일상 주요 메뉴와 분리 |

- 일간 화면의 현재 작업 영역은 선택한 할 일 요약·타이머·핵심 행동을 하나로 합친다. 별도의 멀리 떨어진 작업 상세 영역을 동시에 노출하지 않는다.
- 상세는 현재 작업 영역 바로 아래에서 펼쳐지는 방식이 기본이다. 상세에서 할 일 정보·상태, 계획 배치, 실행 기록, 시간·막힘·수정 이력을 본다.
- 다른 일정 블록을 선택하면 현재 작업 영역의 제목·상태·행동과 상세 내용이 함께 바뀌며, 선택된 블록에는 색 이외의 잉크 외곽선 등 명확한 선택 표시를 제공한다.
- 직접 링크와 새로고침으로 작업 상세를 복원해야 하는 경우에는 일간 화면으로 이동한 뒤 해당 작업을 선택하고 상세를 펼친 상태로 복원한다.
- 집계 숫자는 근거 목록으로, 목록은 작업 상세로 연결한다. 닫으면 이전 필터와 스크롤 위치를 복원한다.
- 루틴 생성·수정의 위치는 핵심 데이터 설계안의 페이지 연결표를 기준으로 와이어프레임에서 검토한다.
- ‘오늘 마무리하기’는 돌아보기 조회 화면과 분리된 단계형 흐름으로 제공한다. 미완료·열린 기록 확인 → 선택적 질문 → 완료 순서이며, 회고 문장은 공백으로 마칠 수 있고 전체 흐름은 X로 중단할 수 있다.
- 일간 화면에는 가까운 날짜 띠와 오늘로 돌아오는 동작을 제공한다.
- 계획·돌아보기·보관함·관리처럼 긴 글과 목록이 중심인 화면은 넓은 창에서도 본문 최대 폭을 약 940px로 제한하고 가운데 정렬한다. 일간 타임테이블은 비교를 위해 더 넓은 작업 폭을 유지한다.

진행 순서: 요구사항 기준선 → 기능·권한 상세 및 집계·시간 규칙 → 정보구조·페이지 목록 → 데이터 설계 → 와이어프레임 → 디자인 → 구현 → 검증·제출. 정보구조와 데이터 설계는 서로 맞춰 검토한다.

과제의 8~10시간은 제공된 과제의 계획 시간이며 확장 기능 전체를 그 안에 완성한다는 보장이 아니다. 범위·소요 시간의 충돌이 확인되면 필수 기준을 누락시키지 않고 사용자에게 단계 조정안을 제시한다.

## 15. 제출물과 증거

- 로그인 없이 열리는 실제 결과물 URL
- 로그인 없이 열리는 최종 소스 URL
- 최종 소스에 `contracts/pds-schema-v2.json` 포함
- 확인 방법 4줄: 어디로 가는지 / 세 단계 안에서 무엇을 하는지 / 통과 시 보이는 것 / 실패 시 보이는 것
- AI와 내 판단 3줄: 개발 과정에서 AI에게 맡긴 일 / 사용자가 직접 판단한 일 / AI 제안을 따르지 않은 일과 이유
- 제출문의 AI는 개발을 도운 AI를 뜻할 수 있다. 앱에 LLM 기능이 없다는 사실과 혼동하지 않는다.
- 계획 저장·수정 이력, 할 일 조작·검색·필터·정렬, 실행 연결·중복 방지, 집계·근거 이동, 회고 전달의 화면과 결과
- 실제 데이터 최소 수량, 첫 화면 공개 안내, 전체 JSON 파일, PDF 요약 보고서 검증
- 새로고침 전후 비교, 스크립트 입력 미실행, 비밀값·공개 URL 확인 결과

증거는 실제 실행·검증 후 수집한다. 미구현 기능을 통과했다고 표시하거나 실행하지 않은 검사를 완료했다고 적지 않는다.

## 16. 다음 단계의 설계 과제

사용자 제품 결정은 이 문서를 기준으로 이어가며 이미 합의한 내용을 반복 질문하지 않는다. 다음은 구현 상태가 아니라 후속 설계 과제다.

1. 18절의 추가 결정은 사용자 동의로 확정되었다. 이미 합의한 여섯 항목을 반복 질문하지 않는다.
2. 핵심 데이터 관계와 삭제·루틴 변경 경계의 구체적 설계는 `core-data-design-v1.md`에서 검토한다. 세부 설계안을 사용자 승인된 요구나 실제 구현으로 혼동하지 않는다.
3. `page-map-v1.md`의 페이지별 정보 우선순위와 와이어프레임으로 데이터 관계를 함께 검증한다.
4. 실제 DB·호스팅 선택 전에 무료 제공 범위, 과제 접근 조건, 저장·삭제 작업 지원 여부를 확인한다.
5. 일간 핵심 화면에서 합의한 통합 작업 영역을 다른 화면에도 일관되게 연결한다.
6. 요약 PDF의 1~2쪽 구성과 긴 한글 텍스트 처리를 디자인 단계에서 검증한다.

## 18. 추가 합의 사항 — 사용자 전체 동의 반영

사용자가 여섯 권장안에 모두 동의했으므로 제품 요구사항으로 채택한다. 아래에서 데이터 설계로 남겨 둔 구현 세부는 별도로 구체화하고, 실제 구현 완료로 표현하지 않는다.

### P-01 공개 데이터는 새로고침 후에도 유지

새로고침 때 초기 예시로 되돌리면 T06-C35와 실제 기록 축적 목적에 맞지 않는다. 공개 편집을 서버에 유지하고 삭제는 휴지통, 계획·실행 정정은 이력으로 추적한다. 복원 기능은 악의적인 편집을 막는 접근 제어와 다르다. 다른 창의 수정은 최신 버전을 확인하도록 하고 작성 중 입력을 보존한다. 자동 초기화 체험장은 현재 범위에 없다.

### P-02 계획 전체 삭제 추가

보관과 별도로 계획을 휴지통으로 이동한다. 삭제 확인에는 연결된 할 일·실행·루틴에 미치는 영향을 표시한다. 연결 루틴의 추가 생성을 중단하고, 함께 삭제한 자료만 복원한다. 계획이 삭제되더라도 일간 회고 원문 전체를 무조건 연쇄 삭제하지 않는다. 독립 회고와 연결 메모의 처리 경계는 데이터 설계에서 검토한다. 영구 삭제는 휴지통에서 별도 확인하며 공개 버전에서는 방문자도 할 수 있다는 한계를 명시한다.

### P-03 매일 루틴 최소 범위

- 입력: 루틴명, 소속 계획, 시작일·종료일, 매일 시작 시각, 예상 시간. 루틴 기간은 소속 계획 기간 안에서 설정한다.
- 날짜마다 독립된 할 일과 계획 블록을 만든다. 월요일 완료가 화요일에 이어지지 않는다. 루틴은 실행 기록이나 완료를 자동 생성하지 않는다.
- 일·주·월 화면에 루틴 배치를 보여주며 구체적 생성 시점은 데이터 설계에서 정한다. 같은 루틴·날짜는 중복 생성되지 않아야 한다.
- ‘이 날짜만 수정·건너뛰기’와 ‘이후 반복 변경·중단’을 구분한다.
- 지난 날짜·실행을 시작한 날짜의 계획과 실행 기록은 이후 루틴 변경으로 덮어쓰지 않는다.
- 일정 충돌은 기존 합의처럼 안내하며 자동으로 다른 시간에 옮기지 않는다.
- 첫 버전은 매일 반복만 지원하고 요일별·격주·공휴일 제외는 후속 검토한다.
- 집계와 미래 날짜 작업 생성 범위, 건너뛰기의 상태·집계 처리, 루틴 수정의 적용 날짜는 핵심 데이터 설계안에서 구체화한다.

### P-04 분 단위 UI와 원본 시간 분리

사용자 화면은 분 단위까지 표시하고 초 표시를 하지 않는다. 원본 시작·종료 시각은 정밀하게 보존해 짧은 멈춤이 사라지지 않게 한다. 요약 표시의 반올림 규칙과 1분 미만 표기를 정의하며 원본 합산 후 표시한다. 분 단위로 원본을 잘라 저장하는 것과 분 단위로 보여주는 것을 구분한다.

### P-05 정렬 단순화

- 일정 화면: 시작 시각순 고정.
- 할 일 목록: 기본은 완료 여부와 관계없이 마감 가까운 순이다. 완료·완료 취소만으로 현재 위치를 바꾸지 않는다.
- 추가 선택은 우선순위순·최근 추가순으로 단순화한다.
- 마감일이 같으면 우선순위 높은 순·생성순·ID로 안정적으로 정렬한다. 마감일 없는 항목은 마감일순의 뒤로 보낸다.
- 임의 드래그 순서와 예상 시간순은 첫 버전에서 제외한다.

### P-06 기록 중 안내

진행 중이면 앱 공통 영역에 작업명·분 단위 경과·종료 동작과 ‘화면을 닫아도 종료할 때까지 시간이 계산됩니다’ 안내를 표시한다. ‘백그라운드 재생’보다 ‘기록 진행 중’으로 표현한다. 닫힌 브라우저에서 프로그램이 계속 실행된다고 보장하는 설명이나 기기 알림 기능으로 오해할 표현은 피한다.
