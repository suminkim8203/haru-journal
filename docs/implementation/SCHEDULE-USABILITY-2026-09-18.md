# 일정 사용성 수정·배포 — 2026-09-18

요약: 승인한 일정 사용성 수정과 월간 간략 목록을 https://haruleaf.com/ 에 배포했다. release approved-1cd31cf9a6ff, 정적 파일 23개 해시 일치·53개 기능 검사·빌드·공개 조회/내보내기 검증을 통과했다.

## 실제 구현

- 개별 배치/실행 ID를 선택한다. 같은 블록을 다시 클릭해도 상세로 이동하며, 소속 계획명과 할 일 제목이 가려지지 않도록 상세 상단을 기준으로 이동한다. 배치 선택은 예정 시간을 펼치고 해당 배치를 강조하며 시간 변경 입력으로 연결한다.
- 상세 상단 소속 계획명은 기존 세리프·얇은 노란 하이라이트를 사용한다. 활성 기록 시작 날짜·시각/상태는 제어 및 작업 시간 바로 아래, 예정 시간 위에 표시한다. 활성 기록을 하단 종료 기록 목록에 중복 표시하지 않는다. 타이머 기록 출처 라벨만 제거하며 DB 출처·작업 시간 계산은 유지한다.
- 선택한 타임라인 블록의 좌측 선만 #75444b로 표시한다. 같은 할 일의 다른 블록은 함께 선택하지 않는다. 색감·제호·기본 서체 규칙은 유지한다.
- 멈춘 구간이 있는 종료 기록만 휴식·중단 구간을 펼칠 수 있다. 작업 구간 중복 나열을 제거했고 수정/기록 삭제는 항상 접힘 밖에 남긴다. 막힌 이유와 필수 집계/근거는 보존한다.
- 선택 날짜의 00–06시 펼침을 시간표 좌측 위로 이동했다. 하단 짧은 기록 색인을 제거하고 실제 시간 높이와 작은 블록의 키보드 접근 및 투명 선택 영역을 유지한다. 기존 timeline-tooltip 스타일로 계획명/제목/시간/우선순위 안내를 복구했다. 키보드 초점·Escape와 자동 스크롤 중 안내 위치 갱신을 지원한다.
- 문맥 귀환 버튼을 제거했다. 주요 메뉴와 화면별 조회 상태는 유지한다.
- 월간 칸은 제목 최대 2개(모바일 1개)+나머지 개수를 표시한다. 날짜 클릭은 월간에 머물며 간략 목록을 갱신한다. 목록의 할 일 또는 일간 상세 버튼만 일간으로 이동한다. 여러 배치와 마감이 겹쳐도 할 일은 한 항목이고 개별 배치 시간은 모두 남긴다. 자정 경계·다음 날에 걸친 배치·날짜별 루틴을 처리한다. 날짜 없는 할 일을 임의 날짜에 넣지 않는다.

## 직접 확인한 내용

- 로컬 기능 검사 53개 통과(기존 50개 + 월간 중복/자정/루틴·제외 조건 3개). 최종 정적 빌드의 TypeScript 검사 통과. 공개 안내·정적 JS·폐기한 서버 API/환경·소스 경로 차단 HTTP 검사 통과.
- 데스크톱 1280px 및 모바일 390px에서 기존 DB 자료를 읽기 전용으로 조회했다. 상세 계획명/버건디/예정 펼침, 반복 선택, 시간 변경 입력 열기/취소, 종료 기록의 중단 구간만 표시, 작업만 있는 기록에도 삭제 버튼 유지, 월간 날짜 선택 후 월간 유지와 목록 중복 제거를 확인했다.
- 모바일 document.scrollWidth=375, innerWidth=390으로 수평 넘침이 없었다. 모바일 제목 1개/외 3개, 데스크톱 제목 2개/외 2개가 각각 표시되고 숨긴 개수 표시는 중복 노출되지 않았다.
- 키보드 Tab으로 전체 제목 안내를 확인하고 Escape로 닫았다. 공개 화면에서도 개별 배치 선택, 상세 계획명 노출/예정 펼침, 버건디 색, 하단 색인 제거 및 월간 목록을 확인했다.
- 공개 파일 23개 SHA-256이 로컬 정적 빌드와 일치한다. 익명 조회/내보내기 정상, snapshot 6·revision 31. 관리자 경로 인증 및 비공개 경로 차단 정상. 배포는 웹 정적 파일만 변경했다. DB migration/자료 쓰기·타이머 시작/종료·체크박스 변경을 하지 않았다.

## 확인하지 않은 부분과 후속

- 검증 시 공개 DB에 활성 실행이 없어 실제 시작 줄의 실행 중 화면은 이번 브라우저에서 직접 재현하지 않았다. 코드 조건/타입 검사는 통과했으며 기존 실시간 계산과 실행 데이터는 보존한다. 사용자의 다음 자연스러운 기록 시작 때 예정 시간과의 비교를 확인한다.
- 매우 짧고 겹친 블록의 모든 포인터 조합, 별도 물리 모바일, 모든 시간 편집 저장/실패 복원·삭제 확인창 수락을 전수 검사한 것은 아니다. 실제 자료를 수정하지 않고 기존 예시 자료의 입력 열기/취소로 검증했다.
- 호버와 키보드는 동일 안내 구현이며 키보드 안내를 직접 렌더링 확인했다. 모든 마우스 이동 조합을 완료로 기록하지 않는다.
- 별도 기기 복원·제출 증거·main 통합, 정기 백업/재부팅 복원은 기존 후속 과제다. 날짜 미정 할 일의 월간 별도 표시는 아직 확정하지 않는다.
