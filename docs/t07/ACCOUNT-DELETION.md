# 계정 탈퇴 — 7일 유예

요약: 사용자가 승인한 ‘신청 후 7일 취소 가능, 기한 후 계정·기록 삭제’를 구현했다. 7일은 신청 시각부터 168시간이며 화면에는 한국 시간으로 표시한다.

## 사용자 흐름

1. 로그인 상태의 ‘계정 탈퇴’에서 내 기록을 JSON 하나로 내려받을 수 있다.
2. 현재 비밀번호 재확인과 삭제 안내 체크 후 신청한다. 실행 타이머가 진행 중이면 종료 후 다시 신청하도록 안내한다.
3. 서버가 신청 시각과 삭제 예정 시각을 저장하고 모든 기존 세션을 삭제한다. 일반 화면은 로그인 화면으로 돌아간다.
4. 7일 이내 다시 비밀번호 로그인하면 탈퇴 대기 화면만 보인다. 로그인 자체는 취소가 아니다. ‘탈퇴 취소’를 눌러야 기록 접근이 복원된다.
5. 7일이 지나면 취소·자료 접근이 금지된다. 예약 작업은 매분 만료 계정을 확인한다. 정상 운영 시 실제 삭제는 기한 뒤 첫 실행에 처리되며 장애 시 지연될 수 있다.

## 서버 경계

- `07_account_deletion.sql`: 자료 조회/내보내기/변경/계정 준비를 pending 상태에서 차단한다. 상태 확인과 취소는 이메일 확인·비밀번호 인증·실제 유효 세션을 요구한다.
- 신청에는 최근 2분 이내 생성한 비밀번호 인증 세션을 요구한다. 사용자 ID는 호출자가 지정하지 않는다. 중복 신청은 기존 기한을 연장하지 않는다.
- `08_account_purge.sql`: 비공개 운영 함수. 만료 시각·소유 관계를 재검사하고 한 트랜잭션 안에서 관련 기록과 Auth 사용자를 제거한다. public/anon/authenticated/service_role에는 호출 권한이 없다.
- 예약 작업: `infra/operations/account-purge.py`, 동일 이름의 service/timer. `/backup` 마운트가 없으면 삭제를 거절한다. 삭제 전 `/backup/haru-deletions/deleted-accounts.jsonl`에 계정/다이어리 식별자와 기한만 기록하고 디스크 쓰기를 확정한다. 비밀번호·이메일·기록 본문은 넣지 않는다.

## 배포·검증

- 실제 release `t07-deletion-dcc3f1a4c362`, 적용 전 백업 `/opt/supabase/backups/t07-deletion-20260922-062650/database.dump`.
- 기존 자료 불변 비교를 SQL 적용 트랜잭션 안에서 수행했다. 불일치 시 전체 적용이 취소된다.
- 예약 작업 active, 최초 실행 success, 적용 당시 신청 0건. 실제 사용자 계정에 탈퇴를 신청하지 않았다.
- 로컬 전체 68/68 검사와 정적 빌드 통과. 전 세션 차단·유예 중 조회/내보내기/계정 준비 차단·명시적 취소·기한 후 취소 거절·본인 자료만 삭제·다른 계정 보존을 검증했다.
- 실제 168시간의 경과 관찰은 아직 아니다. 경계 검사는 격리 테스트에서 시각을 설정해 확인한 것이다.

## 백업과 복구 제한

최신 사용자 결정: 168시간 유예가 끝나면 운영 DB뿐 아니라 관리 중인 백업 사본의 해당 사용자 기록도 제거한다. 백업별 재작성·예약 작업 통합을 설치했고, 2026-09-23 서비스 안내를 배포했다. 관리 중인 사본에는 추가 유예기간을 두지 않는다. 장애 시 정리가 지연될 수 있으며, 실제 168시간 경과 관찰은 아직이다. 다른 사용자의 과거 백업은 보존해야 하며 전체 백업 일괄 폐기로 대체하지 않는다. 진행 근거는 BACKUP-ERASURE-PROGRESS.md에 기록한다.

재해 복구 시 앱을 차단한 상태에서 최신 외부 삭제 이력을 확보하고, 복구된 자료에 삭제를 재적용한 뒤에만 서비스를 열어야 한다. 이 파일을 오래된 DB 백업으로 덮어쓰면 안 된다. 외부 장비 복제·복구 자동 연동은 아직 미구현이다. 따라서 임의의 수동 백업 복구까지 자동으로 삭제 계정 부활을 막는다고 보장하지 않는다. 복구 점검 없이 운영 재개하지 않는 절차가 필요하다.

## 실제 HTTP 후속 확인
별도 검증 계정의 신청 200 → 기존 인증값 조회 401 → 재로그인 후 pending → 조회/내보내기/계정 준비 423 → 명시적 취소 성공 → 원래 자료 그대로 조회 성공을 확인했다. [비밀값을 가린 요청·응답](evidence/deletion-http-2026-09-22.json). 공개 HTML·JS·CSS 12개가 로컬 배포 파일과 해시 일치했다.
