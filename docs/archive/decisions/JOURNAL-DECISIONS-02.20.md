# 02.20 합의 사항과 자료 저장 기준

2026-09-17. 02.18 이후 합의한 변경을 반영한 최신 검토 시안은 02.20입니다. 별도 검토가 불필요한 작업은 중간 승인을 요청하지 않고 완료합니다. 예정했던 02.19 오류 수정과 02.20 일기/보관함을 통합했습니다.

## 화면과 자료의 역할

| 자료 | 저장 기준 | 사용 위치 |
|---|---|---|
| 짧은 메모 journalNotes | 고유 ID, 계획/할 일 구분, 출처 ID와 제목 스냅샷, 관련 계획 ID, 날짜, 내용, 수정 이력, 삭제 상태 | 계획 화면 하단, 일간 할 일 상세, 일반 할 일 편집 아래 |
| 일기 reflections | 날짜별 미삭제 일기 1개, 독립 본문, 관련 계획 ID, 가져온 메모 ID, 수정 이력, 삭제 상태 | 돌아보기 회고 및 보관함 회고 모음 |
| 책갈피 bookmarks | 일기 ID와 저장 시점 본문 스냅샷 | 보관함 책갈피 |
| 기존 계획 메모 planMemos | 이전 자료를 유지하며 신규 붙이기는 중단 | 계획의 이전 시안 보존 메모 |

기존 할 일 설명, 계획 성공 기준, 실행 기록의 막힘 이유는 날짜별 메모와 다른 자료입니다. 임의 변환하지 않습니다.

메모는 오늘 또는 과거 날짜, 최대 2,000자입니다. 선택한 일기 날짜와 같은 메모만 사용자가 선택해서 본문 끝으로 가져옵니다. 출처 제목을 포함하고 가져온 ID를 저장해 중복 추가를 방지합니다. 날짜를 바꿔도 본문은 덮어쓰지 않습니다. 저장한 일기는 원본 메모 수정/삭제에 영향받지 않습니다. 일기는 메모 없이도 쓸 수 있으며 최대 4,000자입니다. 가져오기로 제한을 초과하면 초안을 보존하고 안내합니다. 문장 자동 재작성은 없습니다.

일기·메모 삭제는 휴지통 이동입니다. 책갈피와 이전 계획 메모, 이미 저장된 일기는 보존합니다. 일기를 복원할 때 같은 날짜의 미삭제 일기가 있으면 복원을 막고 안내합니다. 영구 삭제는 제공하지 않습니다. 기존 할 일·루틴 휴지통 규칙을 유지합니다.

## 화면 구조

- 일정: 기록 시작 강조를 유지하며 상세 완료 체크, 날짜별 짧은 메모 입력을 추가합니다. 완료 체크는 실행 타이머 종료와 별개입니다.
- 계획: 계획별 짧은 메모를 작성합니다. 할 일별 메모는 일반 할 일 편집 아래 또는 일간 상세에서 작성합니다. 루틴 메모는 해당 날짜의 할 일에 연결됩니다.
- 돌아보기 → 회고: 오늘의 일기 쓰기, 날짜별 메모 가져오기, 본문 수정 및 저장. 저장된 카드의 ⋯ 메뉴에는 수정/삭제, 하단에는 책갈피 저장이 있습니다.
- 보관함: 회고 모음 / 책갈피 / 휴지통. 날짜·계획·내용 검색은 회고 모음과 책갈피에 적용합니다. 동일한 일기를 별도 복제하지 않습니다.
- 책갈피 저장: 전체 본문을 팝업 없이 저장합니다. 같은 일기 ID/본문은 중복 저장하지 않습니다. 6초 알림의 보기 또는 고정 보관함 메뉴에서 찾습니다. 카드에는 저장됨을 표시합니다.
- 일정 선택: 상세 패널을 화면 위쪽에 보이도록 스크롤하고 초점을 연결합니다. 동작 줄이기 환경 설정을 반영합니다.
- 서체: 기존 제공 명조 계열을 일기 날짜와 큰 제목에 활용하며 조작/본문은 고딕 체계를 유지합니다. 외부 글꼴이 없을 때 시스템 글꼴로 대체합니다. 새 외부 서비스는 추가하지 않습니다.

## 실제 구현과 미구현

현재는 HTML + 브라우저 저장소 시안입니다. 서버, DB, 인증, 배포는 구현하지 않았습니다. 챌린지·누적 루틴 진행률·자동 글쓰기·계획 보관 기능은 추가하지 않았습니다. 보관함 이름을 복구한 것이 계획 보관 기능까지 구현했다는 뜻은 아닙니다.

02.20은 독립 저장 키 flow0220을 사용하며 접근 가능한 flow0216 자료를 최초 한 번 복사합니다. 이전 시안의 자료는 덮어쓰지 않습니다. 실제 file URL 사이의 브라우저 저장소 공유와 사용자의 현재 타이머 자료는 확인되지 않았습니다.

## 다음 사용자 확인

1. 일간에서 현재 시간선이 움직이는지, 상세 완료 체크가 찾기 쉬운지 확인합니다.
2. 할 일의 짧은 메모를 저장하고, 돌아보기 → 회고에서 가져와 문장을 다듬어 저장합니다.
3. 책갈피 저장 후 보관함에서 찾고, 회고를 읽거나 수정하는 흐름을 확인합니다.
4. 제목/본문/보조 정보와 섹션 사이 간격이 편한지 확인합니다.

사용자 승인 이후 확정 요구사항·미구현 기능 목록을 기준으로 실제 데이터 계약과 기술 구성을 정리합니다. 서버 구축이나 새 기능 범위는 화면 승인만으로 완료되었다고 간주하지 않습니다.
