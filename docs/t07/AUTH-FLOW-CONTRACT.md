# 인증 흐름·예외 처리 계약 01

요약: 사용자 2026-09-21 동의로 아래 정책을 승인 기준으로 기록한다. 실제 Auth 설정과 앱 구현은 아직 적용하지 않았다. 기존 공개 서비스/DB는 변경하지 않는다.

## 승인된 정책

이메일 인증번호 6자리, 유효 10분, 재발송 대기 60초, 발급 건당 오입력 5회 후 해당 시도 종료. 성공한 번호 재사용 금지, 재발송 시 이전 번호 무효화. 이메일/IP별 추가 발송·검증 제한은 필요하며 세부 수치와 설치 버전의 구현 가능성은 후속 기술 검증 대상이다. 번호 재발송으로 전체 제한을 우회할 수 없어야 한다.

이메일·비밀번호 가입 → 가입용 이메일 소유 확인 → 정상 인증 → 첫 사용 안내. 비밀번호 변경은 현재 비밀번호 재확인과 새 비밀번호 설정, 분실 재설정은 복구용 이메일 확인과 새 비밀번호 설정으로 분리한다. 둘 다 완료 후 모든 기존 세션 무효화와 재로그인. 일반 로그아웃은 현재 세션 종료. 접근 토큰 1시간/전체 세션 최대 7일은 앞선 승인 정책이며 실제 서버에서 집행·검증해야 한다.

## 실행 주체·입력·검증·결과

| 절차 | 사용자 입력 | 서버 확인 | 결과 |
|---|---|---|---|
| 가입/최초 비밀번호 설정 | 이메일·새 비밀번호 | 형식·조건·중복 | 이메일 미확인 계정, 자료 접근 불가 |
| 가입 이메일 확인 | 가입용 번호 | 대상 이메일·목적·만료·횟수·일치 | 이메일 확인과 정상 인증, 신규 온보딩 |
| 로그인 | 이메일·비밀번호 | 계정 자격·비밀번호·이메일 확인 | 새 세션, 기존 사용자는 일간 |
| 변경 전 본인 확인 | 현재 비밀번호 | 현재 사용자와 재인증 | 해당 사용자의 변경 허용 |
| 비밀번호 변경 | 새 비밀번호 | 본인 재확인·조건 | 변경 완료·이전 세션 모두 거절 |
| 분실 재설정 요청 | 가입 이메일 | 발송 제한·계정 상태 | 존재 여부와 무관한 동일 안내 |
| 재설정용 이메일 확인 | 복구 번호 | 목적·대상·만료·시도 횟수 | 재설정 단계 진입 |
| 재설정 완료 | 새 비밀번호 | 복구 권한·조건 | 비밀번호 저장·기존 세션 거절·로그인 |
| 로그아웃 | 현재 세션 | 서버 세션 무효화 | 같은 이전 인증값 자료 요청 거절 |

복구 과정의 중간 인증 상태가 자료 조회/일반 설정 변경을 허용하는지는 기본 API 이름으로 추정하지 않는다. 서버에서 제한할 방법을 기술 검증 후 명시한다. 초대/소셜 로그인은 현재 범위 밖이며 일반 가입과 혼합하지 않는다.

## 정상·예외 상태

| 상황 | 사용자에게 보여줄 것 / 처리 |
|---|---|
| 잘못된 이메일 형식 | 입력란에서 수정 안내, 발송 안 함 |
| 없는 계정/틀린 로그인 비밀번호 | 동일한 이메일 또는 비밀번호 확인 문구 |
| 미확인 이메일 계정 | 자격 검증 뒤 확인 재개 경로, 미인증 자료 접근 불가 |
| 중복 가입 | 계정 존재를 직접 노출하지 않는 안내, 로그인/재설정 경로 |
| 가입 중 이탈 | 다시 가입/로그인 시 확인 재개, 중복 계정 생성 안 함 |
| 번호 오입력 | 입력란 근처 안내, 최대 시도 제한은 서버 기준 |
| 번호 만료 | 새 번호 받기, 기존 번호로 진입 불가 |
| 번호 재사용/다른 목적 | 가입/복구 목적을 검사해 거절 |
| 5회 실패 | 해당 시도 종료, 재발송만으로 무한 시도 허용 안 함 |
| 재발송 대기 | 남은 시간과 비활성 버튼, 서버도 같은 제한 |
| 메일 미도착 | 스팸함·이메일 확인·재발송·이메일 다시 입력 |
| 발송 실패 | 성공했다고 표시하지 않고 재시도 안내 |
| 연결/응답 불명확 | 무작정 다음 화면으로 이동하지 않음, 중복 요청 방지 |
| 비밀번호 확인 불일치 | 저장 전 입력란 근처 오류 |
| 세션 만료 | 개인 화면 제거·재로그인, 저장된 기록 유지 |
| 로그아웃 실패 | 서버 종료 확인 전 성공이라고 표시하지 않음 |
| 다른 기기 | 현재 세션 로그아웃과 비밀번호 변경 시 전체 종료 구분 |
| 복구 이메일 접근 불가 | 이메일 주소 주장만으로 관리자 우회 복구하지 않음 |
| 계정 삭제 | 본인 재확인·자료/백업 안내·명시적 확인 후 처리 |

## 선행 조건/미확정

비밀번호 길이·조건은 아직 수치 승인/구현하지 않았다. 메일 발송 제공자·실제 수신 검증, 설치 버전의 번호 무효화/서버 제한, 복구 중간 권한, 백업 보존기간과 삭제 정책은 남아 있다. 현재 자동 백업 보존 때문에 즉시 모든 백업에서도 삭제된다고 약속하지 않는다. 계정 삭제·보안 검사에는 폐기 가능한 테스트 계정을 사용한다. 검증 증거에는 실제 비밀번호/OTP/토큰을 넣지 않는다.

## 시안 범위와 검증

[인증 시안 01](studies/Haru-auth-study-01.html)은 독립 HTML이다. 로그인/가입/가입 확인/분실 재설정/복구 확인/새 비밀번호/로그인 중 변경/온보딩/기존 자료 경로/만료 화면을 포함한다. 정상/오류/만료/시도 초과/메일 실패/중복 가입/연결 실패 상황을 선택할 수 있다.

시안은 실제 인증이나 보안 검증이 아니다. 예시 번호 123456은 시안 전용이며 서버·메일 연결·입력 저장 없음. 번호 재발송 후 실제 난수 변경과 서버 5회 제한은 시나리오 표시만 제공한다. 기존 자료 진입 화면은 검토용 설명이지 제품에서 추가로 거치는 페이지가 아니다. 계정 삭제/전체 설정 화면은 이번 인증 시안에 포함하지 않았다.

JavaScript 구문, 화면/시나리오 포함, 네트워크 전송 및 브라우저 저장 코드 부재 검사 통과. 브라우저 보안 정책이 file URL을 차단해 직접 렌더링·모바일 시각·폰트 로딩 검증은 미완료다. 다른 경로로 우회하지 않았다. 사용자 직접 시각 확인 후 수정한다.
