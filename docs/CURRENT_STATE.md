# 현재 프로젝트 상태

요약: 핵심 React 기능과 루틴·편집/복원 UI를 NAS Supabase에 연결했다. 실제 DB·48개 검사·최종 정적 빌드를 검증했고 공개 배포용 파일을 준비했다. 공개 웹 앱 배포는 사용자 확인 전이다.

## 실제 구현

- 기본 폴더 D:/workspace/haru-journal, GitHub suminkim8203/haru-journal, 작업 브랜치 codex/plan-task-fields. main 통합은 아직이다.
- 일반/루틴 계획·할 일/태그·일간/주간/월간 일정·실행 타이머/수기 입력·배치/실행 편집·삭제/복원·단상/회고/책갈피·하루 마무리·집계/근거/개선점·내보내기 실제 코드.
- 브라우저 공개 anon SDK→고정 단일 다이어리 DB 함수. 서버 저장 API/관리 키 중계 없음. 기존 NAS SQL 0001~0009 적용, 테이블 16개, snapshot schemaVersion 6, 앱 공개 함수 3개. 관리자 인증과 내부 접근 차단 유지.
- 승인 공개 예시 계획 1·할 일 5·종료 실행 3·단상 1·회고 1의 영속 저장·앱 새로고침·집계·내보내기를 검증했다. 새 루틴 운영 자료는 추가하지 않았다.
- 실제 NAS anon 트랜잭션 검사 후 rollback, 로컬 48개 검사·타입·최종 정적 빌드/HTTP 검사, 격리 앱의 데스크톱/390px 화면 검사. [이번 구현 및 검증](implementation/ROUTINES-AND-HISTORY-2026-09-18.md).
- 실제 NAS 구조로 [스키마 JSON](../contracts/pds-schema-v2.json) 작성. 적용 전 백업의 프로젝트 스키마/함수를 네트워크 없는 별도 DB로 복구하고 승인 자료 조회·권한 확인 후 검사 컨테이너를 중지했다.

## 미완료·검증 대기

- 공개 웹 앱 배포·HTTPS 제품 URL 검사·별도 기기 복원·최종 제출 증거 및 main 통합.
- Supabase 전체 플랫폼/최신 루틴 백업 복구, 정기 백업·VM 재부팅 복원·장비 부하·대량 반복 성능.
- 배치/실행 삭제의 기본 브라우저 확인 창 승인 경로, 모든 시간 입력/실패 복원의 브라우저 전수 검사. SQL 검증 결과로 화면 전수 검증을 대신하지 않는다.

## 플랫폼 지원과 미사용

Supabase Auth·Realtime·Storage·Edge Functions는 앱에 사용하지 않는다. T06은 로그인 없는 공개 단일 다이어리다. 회원가입·초대·이메일 확인·계정 활성화·최초 비밀번호 설정·비밀번호 변경·재설정은 구현하지 않았다. Studio 관리자 인증과 구분한다.

## 불확실한 부분

로컬 앱·정적 빌드·Supabase 설치/연결은 공개 웹 배포 완료가 아니다. 같은 PC의 재접속은 별도 기기 증거가 아니다. 적용 전 프로젝트 복구 시험은 전체 플랫폼과 최신 루틴 백업의 복구 보장이 아니다. main/과거 HTML 시안/이전 인계는 현행 구현으로 판정하지 않는다.
