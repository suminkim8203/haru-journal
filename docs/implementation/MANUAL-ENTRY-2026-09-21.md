# 수기 실행 입력 보정 — 2026-09-21

요약: 미래 시각과 실제 기록 겹침을 입력창에서 설명하고, 배치·실행 입력창을 해당 조작 구역으로 옮겼다. 새 수기 기록은 작업 구간 한 개로 단순화했다.

## 확인한 원인과 범위
- 기존 TaskRecordZones는 세 details 뒤에 공통 RunEditor를 렌더링했다. 각각의 details 내부 버튼 아래로 이동했다. 일간의 직접 입력창도 상세 조작부 아래·이력 위로 이동했다.
- 기존 클라이언트/SQL 코드에서 미래 실행 종료 차단은 확인되지 않았다. 사용자 실패 원인이 미래 시각이었다고 단정하지 않는다. 확인 당시 오전 수업 타이머가 진행 중이었다. DB는 다른 실제 기록과 겹침을 거부하며, 기존 UI는 일반 오류를 페이지 상단에만 표시했다.
- 이제 입력창에서 현재 시각 초과, 기존 종료 기록/진행 타이머 겹침을 안내한다. 전송 실패의 저장 오류도 제출한 입력창에서 표시한다. 이번 미래 검사 추가는 UI 범위이며 서버가 동일 미래 규칙을 집행한다고 설명하지 않는다.
- 수기 신규 기록은 시작/종료, 선택 막힌 이유만 입력한다. 휴식·중단 추가/편집 조작은 제거했다. 쉬는 시간이 있다면 실제 작업 구간별로 저장한다. C23–27 및 집계·막힌 이유는 유지하므로 과제 기준과 충돌하지 않는다.
- 기존 휴식·중단이 있는 실행을 수정하면 해당 구간·유형을 보존하고 안내한다. 구간 밖으로 전체 시각을 줄이면 오류로 막는다. 기존 초·밀리초는 시간 필드를 변경하지 않으면 보존한다.
