# 인증·첫 화면·온보딩 제안 01

상태: 2026-09-21 작성. 사용자는 이메일 인증 우선·간편 로그인 후순위·온보딩 도입과 흐름 먼저 설계하는 방향에 동의했다. 아래 세부 정책은 제안이며 아직 확정/구현하지 않았다.

## 현재 실제 구현 / 서버 설정 / 미확인

앱은 고정 공개 다이어리 RPC, persistSession=false. 가입·로그인·계정별 권한·온보딩 미구현. NAS Auth v2.196.0, 설치 SDK2.116.0. Auth health/settings 읽기 조회에서 email=true, disable_signup=false, mailer_autoconfirm=false, Google/Kakao=false. 이는 Haru 가입 기능이나 이메일 발송 성공을 의미하지 않는다. SMTP 실제 배달·세션 만료 설정·비밀번호 변경 무효화 동작은 미확인.

## 제안 1 — 계정 정책

- Supabase Auth 이메일·비밀번호 가입. 가입에 필요한 입력은 이메일·비밀번호만, 비밀번호 표시 전환/명확한 조건 안내. 사용자명·전화번호·생년월일 수집 없음.
- 이메일 소유 확인 후 이용. 확인 메일 발송/재발송/이메일 수정·가입 재시도 흐름 포함. 토큰이 URL에 노출되지 않도록 이메일 코드 입력 방식을 우선 검토하며 실제 설치 버전 지원/재사용/만료 검증 후 확정한다.
- 가입 시 최초 비밀번호 설정. 이메일 확인은 별도의 계정 소유 확인 단계이며 일반 로그인과 구분. 이메일 확인 후 인증 세션이 발급되면 바로 진입, 아니면 로그인 화면으로 이동하도록 실제 응답에 맞춰 구현한다.
- 로그인 실패: ‘이메일 또는 비밀번호를 확인해 주세요.’ 동일 안내. 가입 안내도 계정 존재 여부를 불필요하게 드러내지 않는다.
- 로그인 유지 제안: 접근 토큰 1시간, 전체 세션 최대 7일. 둘은 다르며 토큰 자동 갱신으로 전체 최대 기간을 늘리지 않는다. 서버 유효성 검사 구현이 필요하며 자체 호스팅 기본 지원으로 단정하지 않는다. 일반 로그아웃은 현재 세션, 비밀번호 변경은 모든 기존 세션 종료 후 재로그인. 다른 기기/현재 기기의 적용 범위를 화면에 명시한다.
- 비밀번호 변경: 로그인된 본인의 재확인 후 변경. 비밀번호 재설정: 로그인 불가 상황의 이메일 소유 확인 후 새 비밀번호 설정. 두 절차 별도. 메일 설정 미검증이므로 재설정 버튼만 만드는 것은 피한다.
- 계정 삭제: 재확인/내보내기 안내 후 본인 계정과 자료 삭제. 백업 내 잔존/만료 정책은 기존 자동 보존과 함께 먼저 결정하고 안내한다. 실제 영구 삭제 검증은 폐기 가능한 계정에서 별도 승인 절차를 지킨다.
- 소셜 로그인/초대는 이번 1차 범위 밖. 비활성/가짜 버튼 없음.

## 제안 2 — 화면 흐름

비로그인 자료 URL → 로그인 화면 → 가입 또는 로그인.
가입 → 이메일 확인 안내/코드 입력 → 인증 확인 → 신규 온보딩.
기존 계정 로그인 → 오늘의 일간 화면. T06 자료 이전 계정도 기존 자료와 함께 일간으로 바로 진입.
비밀번호 분실 → 이메일 확인 → 새 비밀번호 설정 → 로그인.
계정 설정 → 비밀번호 변경/내보내기/로그아웃/계정 삭제.

첫 URL은 로그인 화면. 별도 랜딩 페이지로 입구를 늘리지 않는다. 영문 제호 Cormorant Garamond 정자, 한글 주요 제목 조선일보명조, 입력/설명/버튼 Pretendard 등 승인 디자인을 유지. 기능 없는 예시 타이머·가짜 개인 기록을 로그인 배경에 넣지 않는다.

로그인 화면: HaruLeaf 제호, ‘계획과 실제를 나란히, 하루를 기록하세요.’ 소개, 이메일/비밀번호/로그인, 계정 만들기/비밀번호 찾기. 메일 발송 기능은 검증 완료 후 실제 연결.

## 제안 3 — 온보딩

신규 사용자 첫 인증 진입에만 한 화면의 3단계 안내. 순차 슬라이드/강제 팝업 여러 장을 사용하지 않는다.
1. 계획: 목표를 계획으로, 할 행동을 할 일로 나눈다.
2. 실행: 예정 시간은 배치하고 실제 시간은 기록한다.
3. 돌아보기: 예상과 실제를 비교하고 하루의 생각을 회고로 남긴다.

주요 행동 ‘첫 계획 만들기’, 보조 ‘건너뛰기’. 건너뛰어도 빈 일간에서 첫 계획 진입을 제공한다. 도움말 ‘사용 안내’에서 다시 볼 수 있다. T06 자료 이전 계정은 강제 안내/빈 계획 생성 없이 기존 기록으로 들어간다. 첫 사용 안내 완료/건너뛰기는 계정별로 기억하며 다른 기기 첫 로그인마다 반복하지 않는다.

화면 내 설명: 배치=앞으로 할 시간, 실행=실제로 한 시간. 첫 실제 기록은 사용자가 직접 시작한다. 온보딩이 임의로 계획/할 일/실행을 생성하지 않는다. 기존 일정·계획·돌아보기·보관함 구조와 필수 근거 이동 유지.

## 다음 구현 선행 조건

SMTP 발송 수단, 실제 메일 검증, 세션 최대 기간 집행, 소유권 이전 대상 계정 확인, 계정 삭제/백업 잔존 정책, 5일 실험 기준은 후속 확인 대상. 먼저 정책 승인 후 로그인·가입·안내의 독립 와이어프레임을 만든다. 지금 운영 인증 설정이나 공개 권한을 변경하지 않았다.
