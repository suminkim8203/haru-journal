# 선택 메뉴의 바깥 클릭 닫힘 점검 — 2026-09-30

요약: 돌아보기의 `대상 일반 계획`과 계획 화면의 `현재 계획`은 검색 가능한 별도 선택기다. 둘 다 항목 선택·Escape·트리거 재클릭으로만 닫고, 바깥 클릭이나 Tab으로 초점을 옮겼을 때 닫는 처리가 없어 사용자가 보고한 현상이 발생한다. 이 문서는 수정 전 범위와 방법이며 아직 구현·배포 결과가 아니다.

| 위치 | 실제 구현 | 조치 |
| --- | --- | --- |
| 돌아보기 → 계획 결과 → 대상 일반 계획 | `web/src/components/review.tsx`의 `ReviewPlanPicker`; 바깥 클릭·초점 이탈 처리 없음 | 선택기 바깥을 누르면 닫고 검색어/더 보기 임시 상태만 초기화. 기존 선택 값과 화면 집계는 바꾸지 않음 |
| 계획 → 현재 계획 → 계획 바꾸기 | `web/src/components/plans.tsx`의 `PlanQuickPicker`; 바깥 클릭·초점 이탈 처리 없음 | 같은 닫힘 규칙 적용. 기존 선택 계획과 편집 내용은 유지 |
| 할 일 추가 우선순위·상태·정렬·색 등 짧은 선택 목록 | `web/src/components/choice-select.tsx`의 `ChoiceSelect`; `pointerdown` 바깥 감지와 `onBlur`가 이미 있음 | 원칙적으로 변경 없음. 회귀 확인만 수행 |
| 날짜·시각 선택창 | `web/src/components/picker-dialog.tsx`의 모달 달력/시계; 바깥 클릭과 Escape 처리 있음 | 변경 없음. 회귀 확인만 수행 |
| 계획·근거·실행 이력 등의 접기/펼치기 | HTML `details`로 만든 내용 구역 | 값을 고르는 선택 메뉴와 목적이 다르다. 이번 바깥 클릭 자동 닫힘 대상에서 제외 |

## 수정 순서

1. 두 검색형 선택기에서 트리거와 팝오버를 감싼 요소를 기준으로 바깥 `pointerdown`을 감지한다. 선택기 안에서 검색하거나 목록을 누를 때는 닫히지 않게 한다.
2. 다른 곳을 클릭하거나 Tab으로 초점이 벗어나면 선택만 취소하고, 클릭한 대상의 동작·초점은 그대로 둔다. Escape로 닫을 때만 트리거에 초점을 돌린다.
3. 두 곳에서 열기→배경 클릭→닫힘, 열기→검색→선택, Escape, Tab 이동, 다른 버튼 클릭을 확인한다. 짧은 선택 목록과 달력·시계의 기존 닫힘 동작도 회귀 확인한다.
4. 타입 검사·기존 테스트·빌드 후 승인된 UI 외에 시각 변경이 없는지 확인한다. 실제 사이트 배포는 이 계획 검토 이후에 진행한다.
