# Ubuntu VM 재부팅 검증

요약: 사용자 승인 후 Haru가 실행 중인 Ubuntu VM만 실제 재부팅했고, 서비스·자료·공개 사이트·자동 백업 예약의 자동 복구를 확인했다. Proxmox 호스트나 다른 VM은 재부팅하지 않았다.

## 실행과 결과

- 2026-09-21 09:47:11 KST에 재부팅 전 상태를 기록했다. 09:48:12 KST에 모든 컨테이너 정상과 자료 보존 검사를 통과했다. 부팅 식별자가 실제 변경됐다.
- Haru 웹과 Supabase 컨테이너 12개 모두 재시작 후 healthy. 별도 수동 컨테이너 시작이나 DB 복구 명령을 실행하지 않았다.
- 자료 revision 32 → 32, 전체 snapshot(순서 의미 없는 태그 정규화) 동일, journal 16개 테이블 모든 행 해시 동일.
- Docker·Tailscale·haru-backup.timer 모두 enabled·active. 재부팅 후 다음 백업은 2026-09-22 04:13:42 KST로 확인됐다. 기존 04:10 + 최대 5분 분산 범위다.
- 외부에서 공개 앱 HTTP 200, 승인 배포 파일 23개 해시 일치, 익명 snapshot·내보내기 정상, 관리자 경로 401 및 비밀 설정 경로 차단 확인.
- 기존 디자인·배포 release approved-1cd31cf9a6ff 유지. 자료 쓰기·마이그레이션·배포 변경 없음.
- 재부팅 후 검사는 일회성 서비스로 실행하고 자동 비활성화하도록 구성했다. 검사 요약과 전후 비공개 자료 해시는 NAS의 제한된 백업 경로에 보관했다.

## 확인 범위

재부팅 전 상태 기록부터 모든 컨테이너 정상 확인까지 약 61초다. 외부 HTTP 관찰은 사이트가 응답하기 시작한 뒤 시작됐으므로 정확한 사용자 접속 중단 시간을 측정했다고 표현하지 않는다. 이번 시험은 정상 VM 재부팅이며 물리 전원 차단·Proxmox 호스트 재부팅·디스크 손상·새 장비 재구성 시험이 아니다.

다음 운영 보완은 같은 NAS 디스크 밖의 백업 장소 결정이다. 현재 같은 NAS 내부 백업과 매일 자동 실행은 구성됐지만 외부 장비 복제·외부 실패 알림은 미구성이다. 미래 예약 실행 자체는 아직 관찰하지 않았다.
