# 02.13 화면·집계·이동 구조 점검 및 정리안

한 줄 요약: 일반 계획과 루틴의 집계 단위를 분리하고, 돌아보기 안에서 근거를 확인하게 하며, 각 화면의 주된 행동을 명확하게 만드는 정리가 먼저 필요합니다.

작성 당시 상태: 코드 확인과 분리된 예시 자료로 검증한 화면 구조 제안. 챌린지 구현은 이 정리안에 포함하지 않습니다.

후속 반영: 사용자가 근거 항목의 제목 강조와 보조 정보 축소를 추가로 요청하고 다음 작업 진행을 지시하여, 돌아보기의 계획 결과 집계·근거 표시를 02.14 시안에 반영했습니다. 아래 제안 전체의 구현 완료를 뜻하지 않습니다. 적용 범위와 남은 작업은 `../outputs/CHANGELOG-T06-02.14.md`를 따릅니다. 02.13과 실제 브라우저 자료는 보존했습니다.

## 1. 현재 단계와 이번 사용자 의견

프로젝트 자료 이전과 기존 테스트 재실행은 완료했습니다. 현재는 실제 서버 구현에 앞서 요구사항과 화면 구조를 정리하는 단계입니다. 이번 피드백은 기존 시안의 검토 결과이므로, 전체 초기 기획을 다시 시작하지 않고 문제 구간의 집계 정의와 행동 흐름을 수정합니다.

사용자가 밝힌 내용:

- 일상 루틴의 누적 진행률에 반대합니다. 지난 미실행 때문에 100%가 불가능해지는 평가를 원하지 않습니다.
- 챌린지는 목적이 다를 때 가능한 아이디어였지만, 지금은 기능이 곁가지로 커질 것을 우려합니다. 챌린지 추가 승인은 없습니다.
- 돌아보기에서 루틴의 날짜별 항목이 같은 제목으로 반복되고, 계획한 할 일이 64개로 표시됩니다.
- 루틴을 결과 집계에서 제외하거나 반복 규칙 하나로 묶는 방향을 제시했습니다. 두 대안 중 최종 선택은 아직 하지 않았습니다.
- 반복되는 ‘할 일 보기’와 목적이 불명확한 화면 이동을 줄이고 전체 화면을 정리하기 원합니다.

진행 순서: 집계 대상·화면 역할 정리 → 변경할 화면과 버튼 검토 → 승인된 흐름을 반영한 시안 수정 → 해당 기능 및 기존 핵심 흐름 검증 → 데이터 계약과 실제 서버 구현.

## 2. 현재 프로젝트에 실제 구현된 동작

근거는 `outputs/T06-flow-v2.13.html`의 현재 실행 스크립트입니다. 내장된 과거 화면 JSON과 이전 버전의 함수가 최종 구현인 것처럼 판정하지 않았습니다. 기존 02.12 테스트의 대체 DOM 하네스를 02.13 HTML에 연결하여 최종 함수 체인의 결과도 확인했습니다.

### 2.1 루틴이 많은 할 일로 집계되는 원인

- `createRoutine`은 반복 규칙 1개를 만들고, `makeOccurrence`는 날짜마다 서로 다른 ID의 할 일을 생성합니다.
- 날짜별 자료는 완료 여부·실행 기록·그날의 예외를 보존하는 역할입니다. 같은 자료가 실수로 두 번 저장된 현상과는 구분해야 합니다.
- `reviewTasks`는 일반 할 일과 루틴의 날짜별 항목을 같은 대상으로 취급합니다. 전체 기간이면 미래에 자동 생성된 항목도 포함합니다. 최종 래퍼에서는 건너뛰기·중단 항목을 제외합니다.
- `renderReviewResults`는 이 항목 수를 ‘계획한 할 일’로 표시하고, 근거 목록도 날짜별 항목 하나당 한 줄씩 만듭니다.
- 근거 행에는 제목·소속 계획·완료 상태·시간이 표시되지만 루틴 발생 날짜는 표시하지 않습니다. 따라서 같은 제목의 행들을 구분하기 어렵습니다.

분리된 예시 자료에서 확인한 결과:

| 확인 항목 | 결과 |
|---|---|
| 기존 예시 일반 할 일 | 5개 |
| ‘스트레칭’ 규칙을 오늘부터 7일로 생성 | 규칙 1개, 날짜별 항목 7개 |
| 생성 후 돌아보기 전체 대상 | 12개 |
| ‘스트레칭’ 근거 행 | 같은 제목 7줄 |
| 그중 미래 날짜의 항목 | 6개 |
| 스트레칭 근거 행의 날짜 표시 | 없음 |
| 전체 근거 목록의 ‘할 일 보기’ | 12개 |

이 검증은 메모리의 합성 자료에만 수행했습니다. 사용자의 브라우저 자료는 읽거나 수정하지 않았습니다. 따라서 사용자가 본 64개의 정확한 구성은 현재 확인되지 않음입니다.

### 2.2 ‘할 일 보기’의 실제 목적지

- 일반 할 일: 돌아보기 → 해당 계획 화면의 할 일 선택 상태.
- 루틴: 돌아보기 → 계획 화면에서 해당 규칙의 하루 이력 표시 → ‘일간 보기’ → 해당 날짜의 일정.
- 원래 돌아보기로 복귀하는 버튼은 존재하지만, 근거를 이해하기 위해 다른 관리 화면을 경유하도록 되어 있습니다.
- 과제 C83은 숫자의 근거 기록을 확인할 수 있어야 한다는 요구입니다. 모든 근거 행에서 계획 화면으로 이동해야 한다는 요구는 아닙니다.

### 2.3 다른 화면에서 확인된 정리 대상

- 일간: 목록의 제목 선택과 별도 ‘할 일 선택/바꾸기’가 함께 있습니다. 모바일과 데스크톱의 별도 목록 마크업도 있으므로 소스상 버튼 수를 동시에 보이는 버튼 수로 단정하면 안 됩니다.
- 선택한 할 일: ‘시간 관리’를 연 뒤 배치 확인·추가, 실행 기록 입력·정정을 고르는 구조입니다. 과거 날짜의 수동 기록 입력도 그 안에 있습니다.
- 계획: 관리용 화면 안에 ‘이전 계획 시안 보기’, ‘이전 휴지통 시안 보기’가 노출됩니다. 사용자 작업과 시안 검토 도구가 섞여 있습니다.
- 돌아보기: 계획 결과·날짜별 시간 사용·회고가 있고 공통 대상 계획 선택기가 일반 계획과 루틴을 모두 포함합니다. 구역마다 마감일 범위와 실제 활동일 기준이 다릅니다.
- 회고: 수정·책갈피·계획에 붙이기와 별도 책갈피 목록이 있습니다. 다음 계획으로 가져갈 행동과 보조 보관 행동의 우선순위를 정리할 수 있습니다.
- 보관함: 현재 별도 실제 보관 기능이 완성된 화면이 아니라 이전 시안으로 연결되는 안내 화면입니다. 설정의 휴지통은 실제 동작합니다.

## 3. 집계와 루틴 표시 수정안 — 제안, 미적용

### 추천: 계획 결과는 일반 계획에 한정하고, 루틴 활동은 실제 시간과 이력에서 확인

1. ‘계획 결과’의 대상 선택에는 일반 계획만 포함합니다. ‘전체’도 ‘모든 일반 계획’이라고 명시합니다. 범위를 바꾸면서 같은 전체 수치인 것처럼 표시하지 않습니다.
2. 계획한 할 일·완료·지연·막힘·예상·실제·차이는 동일한 일반 할 일 대상 집합에서 계산합니다. 루틴 날짜별 항목을 여기서 7개 또는 1개로 섞어 세지 않습니다.
3. 루틴의 날짜별 항목과 실제 실행 기록은 보존합니다. 일간에서는 선택 날짜의 수행 여부를, 날짜별 시간 사용에서는 실제 수행한 시간을 확인합니다.
4. 날짜별 시간 사용의 전체 합계에는 루틴 실제 작업 시간도 포함합니다. 계획 결과에서 분리했다는 이유로 실제 수행 시간을 없애지 않습니다. 진행 중 기록·삭제 자료에 관한 기존 집계 규칙은 별도 유지합니다.
5. 루틴을 요약해서 보여줘야 하는 위치에서는 반복 규칙당 한 줄로 묶습니다. 예: ‘스트레칭 · 선택 기간 실제 40분’. 날짜별 내역은 그 줄 안에서 필요할 때 펼칩니다. 이 요약을 위해 새 메뉴나 필수 화면을 추가하지 않습니다.
6. 묶음 기준은 제목 문자열이 아니라 반복 규칙 ID입니다. 같은 이름의 독립된 할 일이나 서로 다른 루틴을 합치면 안 됩니다.
7. 일상 루틴의 누적 완료율·연속 달성률을 기본 화면에 추가하지 않습니다. 현재 돌아보기 하단의 일반/루틴 혼합 완료율도 정리 대상입니다.

대안인 ‘계획한 할 일에서 스트레칭을 1개로 세기’는 이번에는 추천하지 않습니다. 일반 할 일의 완료와 반복 규칙 전체의 완료를 같은 숫자로 섞으면 ‘며칠 해야 이 1개가 완료인가’라는 새로운 정의가 필요합니다. 규칙 개수와 일별 수행 횟수는 서로 다른 단위입니다.

### 과제 및 기존 결정과의 관계

- 과제 원문 C28~C32는 선택한 계획에 딸린 미삭제 할 일 수와 해당 완료·지연·막힘·시간을 요구합니다. C83은 숫자에서 근거 기록으로 연결되어야 한다고 요구합니다.
- 일반 계획에 대해서는 위 공식을 그대로 유지하는 안입니다. 일반 할 일 5개라면 5개로 계산하며 완료·지연 및 시간도 같은 대상이어야 합니다.
- 기간 없는 루틴 묶음은 기존 감사에서도 과제의 일반 계획과 구분한 추가 기능입니다. 그러나 최신 승인 기록은 기본 집계에서 루틴 발생 항목을 단지 건너뛰기·중단했다는 이유로 제외하지 않도록 했습니다.
- 따라서 이번 안은 기존 집계에서 예외 항목만 임의로 숨기는 패치가 아니라, ‘계획 결과의 대상 범위’를 일반 계획으로 명시적으로 변경하는 요구사항 제안입니다. 기준표·화면 라벨·필터·근거·검증을 함께 바꿔야 합니다. 아직 승인된 최종 정책이나 과제 통과로 단정하지 않습니다.
- 숫자만 규칙 수로 줄이고 시간이나 근거 목록은 발생 항목 기준으로 남기는 방식은 적용하지 않습니다.

## 4. 화면별 역할과 행동 정리안 — 제안, 미적용

| 화면 | 사용자가 해결할 질문 | 주된 행동 | 정리할 부분 |
|---|---|---|---|
| 일정·일간 | 오늘 무엇을 하고, 언제 했는가? | 할 일 선택, 기록 시작·종료, 완료 체크 | 목록과 별도 선택창의 중복 진입점 정리. 실제 기기에서 둘 다 필요한지 확인한 후 줄임 |
| 선택한 할 일 | 이 일의 예정 시간과 실제 기록은? | 예정 시간 배치, 실행 기록 입력 | 포괄적인 ‘시간 관리’ 진입 단계를 줄이고 목적이 드러나는 행동을 제공. 기존 내역은 필요할 때 펼침 |
| 계획 | 무엇을 언제까지 할 것인가? | 계획·할 일 추가 및 수정 | 이전 시안 링크를 검토 도구로 이동. 루틴 규칙 편집과 하루 수행을 섞지 않음 |
| 돌아보기·계획 결과 | 예상과 실제가 어떻게 달랐는가? | 숫자 선택 → 근거 확인 | 일반 계획으로 대상 명시. 근거를 같은 화면에서 열고 반복 ‘할 일 보기’ 제거 |
| 돌아보기·날짜별 시간 사용 | 실제 시간을 어디에 썼는가? | 날짜·기록 펼치기 | 기록 열람을 위해 일간으로 자동 이동시키지 않음. 일반/루틴 실제 시간 보존 |
| 돌아보기·회고 | 다음 계획에서 무엇을 바꿀 것인가? | 회고 작성, 다음 계획에 반영 | 책갈피 등 보조 동작은 더보기로 정리. 계획 선택·저장 결과를 현재 흐름에서 명확히 표시 |
| 보관함·설정 | 보관·복원·자료 관리는 어디서 하는가? | 필요한 관리 동작 | 미완성 보관함은 주 동선에서 제외하는 안 검토. 휴지통 복원은 계속 접근 가능하게 유지 |

한 화면에 버튼을 무조건 한 개만 남기자는 뜻은 아닙니다. 읽기 위해 이동하는 버튼과 실제 상태를 바꾸는 행동을 구분하고, 드물게 쓰는 동작은 필요할 때 노출합니다.

### 버튼 처리 기준

| 현재 요소 | 제안 | 보존할 기능 |
|---|---|---|
| 근거 행마다 ‘할 일 보기’ | 제거하고 근거 행을 같은 화면에서 펼침 | 할 일 제목·기간/마감·상태·예상·실제·막힘 이유·실행 기록 열람 |
| 기록의 ‘일간 상세’ | 기본 열람은 현재 화면에서 펼침 | 실제 수정이 필요하면 펼친 기록에서 ‘기록 수정’ 제공; 닫으면 기존 근거와 필터 유지 |
| 루틴 근거 → 계획 이력 → 일간 | 기본 근거 흐름에서 제거 | 일간에서 날짜별 수행, 계획에서 반복 규칙 관리 |

| ‘이전 … 시안 보기’ | 시안 검토 도구로 이동 | 버전 비교 기능 자체는 보존 |

## 5. 구현 순서와 완료 기준

첫 묶음은 돌아보기입니다. 사용자가 실제로 지적한 혼란을 먼저 해결하고 결과를 검토한 뒤 일간·계획으로 확장합니다.

1. 집계 범위를 요구사항에 명시하고 일반 계획·루틴의 역할을 분리합니다.
2. 돌아보기 근거를 같은 화면에서 읽는 구조와 필요한 정보 순서를 확정합니다.
3. 후속 시안으로 집계·근거·버튼을 함께 변경합니다. 기존 02.13과 사용자 자료는 보존합니다.
4. 다음 기준으로 검증합니다.
   - 일반 할 일 5개와 7일 루틴 1개를 넣었을 때, 일반 계획 결과는 일반 할 일 5개를 집계합니다. 이 범위가 화면에 명시되어야 합니다.
   - 숫자를 누르면 같은 범위의 근거가 열리고, 일반 할 일 5개의 수·완료·지연·막힘·시간이 정확히 일치합니다.
   - 루틴의 7일 수행 자료는 유지되고 날짜별 완료·실행 기록이 서로 덮어쓰이지 않습니다.
   - 루틴 실제 시간은 날짜별 시간 사용에서 사라지지 않습니다. 규칙 요약이 있는 경우 같은 규칙은 한 줄이고 날짜는 안쪽에서 구분됩니다.
   - 제목이 같은 독립된 두 할 일과 서로 다른 두 루틴은 합쳐지지 않습니다.
   - 근거를 읽기 위해 계획 화면이나 일간을 경유하지 않습니다. 기록 수정 후 필터와 펼친 위치를 잃지 않습니다.
   - 자료 없음, 완료 0건, 기록 없음, 삭제 자료 보존 정책에서도 표시와 합계가 일치합니다.
   - 모바일·키보드의 명시적 시간 배치와 수동 기록 입력이 계속 가능합니다.
5. 돌아보기 검토 후 일간의 중복 선택 경로, 시간 관리 단계, 계획과 관리 화면의 보조 버튼을 정리합니다.

## 6. 서비스가 지원하지만 현재 사용하지 않는 기능

이번 문제는 현재 HTML의 정보구조와 집계 정책에 관한 것입니다. 외부 서비스의 기능으로 해결할 사안은 확인되지 않았고, DB·호스팅·인증 서비스 연결은 현재 없습니다.

## 7. 확인이 필요한 불확실한 부분

- 사용자의 64개 구성 및 실제 저장 상태: 현재 확인되지 않음. 합성 자료로 같은 증가·반복 표시와 이동 경로는 재현했습니다.
- 실제 브라우저에서 동시에 보이는 버튼, 스크롤·초점·모바일 동작: 이번 점검에서 확인되지 않음. 코드 마크업만으로 화면 배치를 검증했다고 주장하지 않습니다.
- 집계에서 루틴을 분리하는 최종 정책: 위 추천안으로 제시했으며 아직 적용하지 않았습니다.
- 돌아보기 상세를 인라인으로 펼치는 최종 배치와 후속 시안: 아직 구현하지 않았습니다.
- 챌린지: 이번 정리에서 추가하지 않으며, 후속 구현을 자동으로 약속하거나 필수 목록에 넣지 않습니다.
