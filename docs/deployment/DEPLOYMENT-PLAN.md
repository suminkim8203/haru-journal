# 개발 환경 및 배포 방향

상태: 목표와 검토 기록이며 완료된 운영 구성은 아닙니다. 2026-09-17 대화 기준.

## 실제 현재 상태

React/Next.js/TypeScript 앱과 Next.js 서버 API가 구현돼 있습니다. Supabase SDK로 DB 함수를 호출하는 첫 저장 구조를 작성했고 SQL은 로컬 PGlite에서 검증했습니다. 실제 Supabase 연결·Docker 개발 환경·NAS 설치·외부 서비스 배포는 미완료입니다. Spring 백엔드도 없습니다.

후속 기록 정정: infra/supabase/README.md에는 별도 NAS 작업으로 자체 호스팅 설치 및 내부/외부 서비스 검증이 완료됐다고 기록되어 있습니다. 위 NAS 미설치 문장은 해당 작업 전 상태입니다. 같은 인프라 기록에 앱 연결/프로젝트 DB 스키마 적용은 미완료라고 명시돼 있어, Supabase 가동과 다이어리 앱 저장 완료를 구분합니다. 이번 UI/과제 감사에서 원격 상태를 재검증하지 않았습니다. 다음 연결 대상은 기존 NAS 구성을 먼저 확인하며 새 클라우드 프로젝트를 중복 생성하지 않습니다.

T06 제출에는 내부망/Tailscale 접속과 별도로 무인증 공개 제품 URL이 필요합니다. 인증이 있는 Supabase Studio 관리 주소를 제품 결과물 주소로 제출하지 않습니다. 서비스의 관리자 인증을 제거하는 조치는 필요하지 않습니다.

## 사용자 목표

지금은 개발할 때만 PC에서 실행합니다. 추후 개인 PC 또는 개인 NAS에 서버를 열어 배포 이후 운영까지 경험하려 합니다. Java/Spring은 사용 경험이 없습니다.

기존에는 Supabase 클라우드 + Vercel 구성에 동의하고 Supabase 프로젝트 생성을 요청했습니다. 이후 로컬 개발·자체 장비 운영 방향을 논의했습니다. Spring 전환이나 Supabase 자체 호스팅 최종 선택은 아직 명시적으로 확정하지 않았으므로 새 클라우드 생성/비용 발생/전환을 확정 결정으로 기록하지 않습니다.

## 검토 중인 선택

| 선택 | 활용 및 변경 |
|---|---|
| Next.js + Supabase 로컬 개발 → 자체 호스팅 | 기존 저장 코드 활용 가능. 배포 환경에 맞는 URL·키·설정 검증 필요 |
| React + Spring Boot + PostgreSQL | 백엔드 학습 범위 확대. 기존 서버 API와 업무 규칙 이전 및 재검증 필요 |
| 관리형 DB를 일부 유지 | 자체 서버를 운영하면서 DB 운영 책임을 줄이는 대안 |

최근 추천은 프로젝트 범위에 충분한 Supabase를 유지하는 방향입니다. 추천은 최종 사용자 승인과 구분합니다. Supabase는 실제 PostgreSQL 기반이지만 루틴/복원/집계 등 서비스 규칙은 직접 구현해야 합니다.

## 개발과 운영의 구분

Supabase CLI의 로컬 환경은 개발·테스트용이며 그대로 외부에 공개하면 안 됩니다. 운영용 자체 호스팅은 별도 Docker 구성과 보안 설정으로 준비합니다. NAS의 Supabase Studio/API는 주요 개발 경험이 클라우드와 유사하지만 단일 프로젝트이며 설정·업데이트·백업·복구·모니터링은 직접 담당합니다.

현재 Next.js 서버 API도 실행 서버가 필요합니다. Supabase만 NAS에서 실행한다고 웹 화면과 Next.js API까지 배포되는 것은 아닙니다. 운영 구성에는 앱 서버와 DB 서비스 모두를 포함해야 합니다.

## 배포 전에 결정/검증할 항목

- PC/NAS 모델, CPU 아키텍처, RAM, 저장 장치, 컨테이너 실행 지원.
- 내부망만 사용할지 외부에 공개할지, 공개 시 허용할 사용자와 쓰기 권한.
- 앱/DB의 영구 저장, 별도 백업 위치, 실제 복구 검사.
- HTTPS, 접속 주소, 라우터·회선 조건, 관리자 화면 접근 범위.
- 환경 변수와 비밀 키의 서버 측 보관, 개발/운영 데이터 분리.
- 상태 점검과 오류 로그, 업데이트 및 배포 되돌리기.

사양·접근 범위·복구 방식·구체적인 배포 설정은 현재 확인되지 않음. 일괄 자료 조회 및 다이어리 전체 revision 방식은 초기 구현이므로 사용량 증가 시 조회 범위와 충돌 단위를 조정합니다. NAS 처리량은 실제 장비와 부하 검사로 판단합니다.

## 단계 제안

1. 로컬 개발 방식 선택 및 실행 환경 확인.
2. 첫 일반 계획/할 일 기능을 실제 DB에 연결하고 지속 저장 검증.
3. 승인된 나머지 기능 구현·검증.
4. 목표 장비에서 운영용 설치, 데이터 이전 및 복구 검사.
5. 접근 범위에 맞는 접속 설정 후 배포·운영 확인.
