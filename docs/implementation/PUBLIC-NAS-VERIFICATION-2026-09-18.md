# 승인 공개 예시 — 실제 NAS 영속 저장 검증

요약: 사용자가 승인한 계획 1·할 일 5·종료 실행 3·단상 1·회고 1을 NAS에 저장했다. 새 SDK 연결과 앱 새로고침에서 복원됐으며 집계·근거·내보내기가 일치했다. 공개 웹 앱 배포 완료를 뜻하지 않는다.

## 실행과 보정

- 사용자 답변 “예시 자료로 검증 진행”으로 [검토한 자료](../reviews/PUBLIC-TEST-DATA-PREVIEW.md)만 저장했다. 개인정보/실제 활동은 없다.
- 최초 계획/할 일 저장 뒤 수기 실행 저장이 42501(permission denied for schema journal)로 실패했다. 실패 명령은 rollback돼 자료 revision·receipt가 늘지 않았고 기존 자료는 보존됐다.
- 원인은 지연 constraint trigger가 공개 RPC 반환 후 호출자 권한으로 실행되는 설정이었다. 선행 롤백 검사에서는 관리자 권한으로 돌아온 시점에 검사돼 이 문제를 잡지 못했다. 로컬 엔진 결과를 실제 HTTP 커밋 동작으로 일반화하지 않는다.
- 적용된 0001~0006은 바꾸지 않고 0007_deferred_segment_validation.sql을 추가했다. 검사 함수는 security definer와 빈 search_path를 사용하며 공개/anon/authenticated/service_role 직접 실행 권한을 회수했다. 내부 schema/table 사용 권한은 계속 없다.
- 실패한 원래 요청 UUID·revision·payload로 재시도해 중복 없이 이어 저장했다. SQL에는 자료 삭제·테이블 구조 변경이 없다.

## 직접 확인한 결과

|검사|결과|
|---|---|
|서버에 저장한 자료|계획 1·소속 할 일 5·종료 실행 3·단상 1·회고 1|
|새 SDK 클라이언트 재접속|전체 snapshot ID·값 동일|
|실제 앱 새로고침|같은 계획/할 일/회고 복원|
|계획 결과|계획한 할 일 5·완료 2·지연 1·막힘 1|
|시간|할 일 예상 합 105분·종료 작업 합 75분·차이 −30분|
|계획 독립 예상|150분 유지|
|JSON 내보내기|종료 실행/회고 포함, command_receipts 제외|
|근거 이동|막힘 1 → 해당 할 일 → 이유/실행 시간 → 09.18 일간|
|일간 상세|첫 선택의 예정 시간·단상·실행 기록 모두 접힘; 단상 한 번 표시|
|완료 제한|기록 시작/계획 배치 disabled, 수기 실행 입력 가능|
|회고|글 안에서 편집 가능, 날짜 누르면 09.18 일간 이동|
|책갈피 실제 저장|저장 → 필터 → 새로고침 → 저장 상태 유지 → 해제로 원복|
|390×844 모바일|자료 있는 보관함/일간/주간 document overflow 없음|
|NAS 추가 rollback 검사|anon로 시작 → 휴식 → 완료 → 지연 검사 강제 실행 성공, rollback 후 기존 할 일 5/실행 3 유지|

책갈피 검증은 예시 회고의 상태만 잠시 바꾼 후 원복했다. 성공 이력과 revision은 남는다. 추가 테스트용 할 일/열린 실행은 영속 저장하지 않았다. 종료 실행의 휴식·중단 구간은 작업 시간에 포함하지 않는다.

## 검증의 한계와 남은 작업

- 37개 로컬 회귀 검사 통과. 폰트 실제 글리프/합성 굵기·모든 조작·대량 자료·장시간 타이머·네트워크 오류 복원·별도 기기는 이번 검사 범위가 아니다.
- 화면 접근성 내용과 일부 screenshot/DOM 폭으로 확인했다. 전체 스크린샷 수집 일부가 실패해 최종 제출 캡처 완료로 표시하지 않는다.
- 루틴, 예정 편집/기록 삭제 UI 등 남은 구현은 [다음 순서](NEXT-STEPS.md). 과제 C26/C31/C33를 삭제하지 않았다.
- 원래 과제의 본인 실제 자료 조건은 사용자 개발 예외만 적용했다. 외부 평가 기준 변경/제출 통과를 주장하지 않는다.
- 관리자 Studio는 기존 인증 유지. 로컬 웹 앱+NAS DB 연결이며 haruleaf.com의 공개 웹 앱 배포는 아직이다.
