# T06 기획 확정 및 개발 전 점검

> 후속 결정으로 일부 대체: 02.13에서 루틴 계획은 기간 없는 묶음으로 변경합니다. 따라서 아래 상위 계획 기간 변경·단축 및 경계 정책은 더 이상 적용하지 않습니다. 각 반복 할 일이 자체 기간을 가지며 새 입력 기본값은 오늘부터 한 달 뒤까지입니다. 반복 재개·건너뛰기 취소의 합의는 유지하되 미구현입니다. 최신 범위는 CHANGELOG-T06-02.13.md를 확인합니다.

한 줄 요약: 02.12의 삭제·복원 흐름과 아래 네 가지 정책을 사용자가 승인했습니다. 정책 승인과 시안 구현 완료는 구분합니다.

## 현재 프로젝트에 실제 구현된 기능

- 기준 시안: T06-flow-v2.12.html. 기존 HTML은 이번 정리에서 수정하지 않습니다.
- 계획·할 일, 시간 배치·실행 기록, 루틴, 돌아보기, 휴지통 삭제·복원 흐름이 있습니다.
- 사용자는 02.12를 확인하고 흐름을 승인했습니다. 모든 예외와 모바일 조작 검증 완료를 의미하지는 않습니다.
- 반복 생성 시 계획 기간 사용 또는 별도 기간 지정이 가능합니다. 현재 계획 기간 수정은 기존 반복 날짜가 새 기간 밖으로 나가면 차단합니다.

## 확정됐으나 아직 구현되지 않은 정책

승인 근거: 직전 네 가지 추천안에 대한 사용자 응답 “전부 동의”.

1. 계획 기간 변경: ‘계획 기간과 동일’인 루틴만 변경 대상에 포함합니다. 별도 기간 루틴은 자동 변경하지 않습니다. 저장 전에 영향받는 항목을 확인합니다.
2. 계획 기간 단축: 제외 날짜의 미실행 할 일·예정 배치만 정리합니다. 과거·실행·완료·개별 수정 항목은 보존하고 새 기간 밖에 남는 이유를 안내합니다.
3. 반복 재개: 재개 날짜를 선택합니다. 중단됐던 빈 날짜를 소급해서 채우지 않으며 기존 항목을 중복 생성하지 않습니다.
4. 하루 건너뛰기 취소: 해당 날짜만 되돌립니다. 기존 예정 배치도 복원하되 일정이 겹치면 확인합니다. 실행 기록은 변경하지 않습니다.

### 구현 전 수용 기준

- 계획 기간 변경 확인 화면은 변경 대상, 유지 대상, 보존 사유를 구분합니다. 취소나 저장 실패 시 기존 자료가 유지되어야 합니다.
- 기간을 연장했다가 단축해도 완료·실행 기록과 개별 수정이 훼손되지 않아야 합니다.
- 반복 재개를 여러 번 눌러도 동일 루틴·동일 날짜가 중복되지 않아야 합니다.
- 건너뛰기 취소 시 겹침 확인을 취소하면 건너뛰기 상태와 현재 일정 모두 유지되어야 합니다.
- 삭제 복원, 중단 재개, 건너뛰기 취소는 서로 다른 작업으로 표시합니다.

## 서비스가 지원하지만 현재 사용하지 않는 기능

외부 서비스는 연결하지 않았습니다. 특정 서비스의 지원 여부는 이번 점검 대상이 아닙니다. 서버·DB·인증·기기 간 동기화는 구현 완료로 간주하지 않습니다.

## 확인이 필요한 불확실한 부분

다음은 승인된 큰 원칙 사이의 경계 사례이며 임의로 확정하지 않습니다.

- 별도 기간 루틴이 단축한 계획 기간 밖에 남는 경우의 허용·안내 방식.
- 기간 변경 또는 재개와 중단·건너뛰기·휴지통 상태가 겹치는 경우의 처리 우선순위.
- 새 계획 기간 밖의 보존 항목을 계획 결과에서 어떤 기간 기준으로 집계할지.
- 실제 브라우저·모바일·키보드 전체 흐름 검증. 기존 56개 자동 검사는 이번 네 정책을 검증한 것이 아닙니다.

## 후속 순서

1. 위 경계 사례를 포함한 전체 흐름 점검과 추천안 정리.
2. 개발용 요구사항에 확정/미구현/미결정/검증 대기를 분리하고 경미한 개선은 별도 목록으로 관리.
3. 사용자 유형·권한, 데이터 관계, 저장·복구 정책 및 기술 선행 조건 확정.
4. 필요한 화면만 추가 검토한 뒤 실제 개발과 테스트 진행.

현재 문서는 정책 승인 기록입니다. 전체 기획 완료, 새 HTML 구현 또는 테스트 완료 보고서가 아닙니다.
