# T06 제출 자료

요약: 공개 결과물과 소스, 확인 방법을 정리했다. 사용자 판단 문장은 대화에 근거한 초안이며 본인 확인 후 제출한다.

## 주소

- 결과물: https://haruleaf.com/
- 소스: https://github.com/suminkim8203/haru-journal

## 짧은 확인 방법 — 4줄

1. 어디로 가나요: 결과물 주소에서 돌아보기 → 계획 결과로 이동합니다.
2. 무엇을 하나요: 예시 · Haru 사용 흐름 확인 계획을 선택 → 완료 또는 막힘 숫자 선택 → 근거 할 일의 일간 상세를 엽니다.
3. 통과 기준: 숫자와 근거 할 일이 일치하고, 상세에 연결된 실행 시간·막힌 이유가 보이며 새로고침 후에도 저장 자료가 유지됩니다.
4. 안 될 때: 연결·입력 오류 안내와 최신 자료 확인이 표시됩니다. 입력을 확인하고 저장 결과가 불명확하면 이전 저장 결과 확인으로 재확인합니다.

## AI와 내 판단 — 사용자 확인용 3줄

1. AI에게 맡긴 일: 화면·DB 구현, 과제 기준 대조, 자동 검사와 배포·문서 정리를 맡겼습니다.
2. 내가 직접 판단한 일: 신문과 개인 기록장 분위기, 서체의 역할, 제호 위치, 단상·회고 구분과 일정 화면의 사용 흐름을 직접 결정했습니다.
3. AI 제안을 따르지 않은 일: 루틴 누적 진행률과 불필요한 이동·중복 기록 표시를 줄였으며, 승인 시안과 다른 구현은 그대로 수용하지 않고 원래 디자인으로 복원하도록 했습니다.

## 자료/조건 구분

예시 자료는 사용자가 허용한 검증용 자료다. 과제 원문의 본인 실제 자료 조건이 외부 평가에서도 면제됐다고 주장하지 않는다. 계획 1개·소속 할 일 5개·종료 실행 3개 이상과 집계 기준은 유지한다.

## 아직 증거가 필요한 항목

- 별도 물리 기기에서 동일 자료 조회. 같은 PC의 다른 창은 대체 증거가 아니다.
- 최초 공개 저장 증거와 최근 읽기 검증을 구분하며, 모든 조작을 이번에 다시 저장한 것으로 표시하지 않는다.
- 사용자 판단 3줄의 본인 확인.
- 운영 정기 백업/전체 복구·재부팅 검증은 별도 완료 증거가 필요하다.
