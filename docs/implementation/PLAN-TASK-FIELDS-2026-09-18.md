# 첫 저장 기반·계획/할 일 필수 항목 구현

요약: 기본 폴더의 codex/plan-task-fields에서 첫 저장 소스를 기반으로 필수 필드·수정·이력·검색/필터/정렬을 구현했습니다. 로컬 검증이며 NAS 적용·공개 서비스 완성은 아닙니다.

## 실제 구현

| 항목 | 화면/API/저장 동작 |
|---|---|
| 개발 기반 | origin/feat/persistent-plans 20842d2의 web 소스(기존 README 제외)를 기본 폴더에 반영. main 통합 전 별도 작업 브랜치 |
| 계획 우선순위 C05 | 높음/보통/낮음 입력·수정·조회, 서버 검증과 DB 제약 |
| 계획 예상 C07 | 정수 분 입력·수정, 할 일 예상 합계와 별도 표시/저장. 자동 덮어쓰기 없음 |
| 계획 수정 이력 C08 | 수정 전 제목/기간/성공 기준/예상/우선순위 보존, 계획 상세의 접힌 수정 이력에서 조회 |
| 할 일 수정 C10 | 제목·설명·마감·예상·우선순위·태그 수정. 완료 상태는 별도 명령이며 수정으로 초기화하지 않음 |
| 여러 태그 C16 | tags와 task_tags의 ID/이름/다중 연결, diary 내 같은 이름 재사용·연결 중복 차단. 수정 전 태그 ID/이름 스냅샷 보존 |
| 검색/필터/정렬 C18~20 | 제목/설명/태그 검색, 상태/태그 필터 결합. 마감일/우선순위/제목 정렬, 동률 ID 순·마감 없음 마지막을 화면에 안내 |
| 중복 완료 C21 | 같은 요청 재시도는 기존 응답. 이미 같은 완료 상태면 새 완료 이력/시각/자료 revision을 만들지 않는 no-op |
| 화면 갱신 | 완료는 해당 행·자료 revision만 갱신, 실패는 원래 체크 상태 복원. 불명확한 응답은 기존 요청 확인·충돌은 최신 확인. 새로고침 초안 복원 보장은 아직 없음 |
| 주소 검사 | Next.js 내부 request.url과 브라우저 Host 불일치를 보정. HTTPS 프록시에는 APP_ORIGIN 명시, forwarded 헤더는 기본 신뢰하지 않음. 사용자 인증 기능이 아님 |
| 저장 버전 | snapshot schemaVersion=2. 구형 저장소는 쓰기 전 SCHEMA_UPDATE_REQUIRED 503으로 차단해 새 필드를 조용히 누락 저장하지 않음 |

태그 입력은 항목별 Enter/추가·개별 제거이며 입력 중인 이름도 저장에 포함합니다. 30자/20개 제한은 초기 입력·저장 검증의 기술 제한입니다. 쉼표 포함 이름도 한 항목으로 편집할 수 있습니다. 이름은 앞뒤 공백을 제거하고 정확히 같은 이름을 중복 연결하지 않습니다. 수정 요청에서 빠진 선택 필드는 기존 값 유지, tags 누락은 유지·빈 배열은 해제입니다.

## SQL와 데이터 보존

0001_core.sql은 기능 브랜치 원본을 변경하지 않았습니다. 후속 0002_plan_priority_task_tags.sql은 계획 priority를 기본 normal로 추가하고 tags/task_tags 및 RPC 조회·수정·이력을 보정합니다. 기존 ID/기간/예상/완료/이력을 유지하는 업그레이드 테스트를 수행했습니다. 이전 기록에 없던 우선순위를 원래부터 입력한 값처럼 설명하지 않습니다.

실제 NAS의 적용 이력을 먼저 확인하고 이미 적용한 SQL을 재실행하지 않습니다. 현재 로컬 설치에 migrations 존재만으로 실제 서버 적용 완료를 판정하지 않습니다. 루틴 날짜 NULL 제약/전체 실행 모델은 이 마이그레이션에서 해결했다고 주장하지 않습니다.

## 승인 디자인의 초기 적용

HaruLeaf 제호/Haru 메타데이터, 기존 승인 웹폰트 3가족(Cormorant Garamond 500 정자/조선일보명조 400/Pretendard)을 초기 계획 화면에 지정했습니다. 계획/할 일 제목·서술형 할 일 설명/편집은 세리프, 버튼/입력 라벨/보조 정보/숫자는 산세리프, 계획 콘텐츠 최대 940px입니다. 세리프 합성 굵기를 차단했습니다. 미구현 메뉴나 타이머를 디자인용 가짜 버튼으로 추가하지 않았습니다.

전체 승인 지면/일정·보관함 적용은 후속입니다. CSS 선언과 HTTP HTML 확인을 실제 브라우저 폰트 로딩/글리프·모바일 외관 검증으로 설명하지 않습니다. 완료 체크 잔여 깜박임도 해결 완료가 아니라 실제 화면 검증 대상입니다.

## 검증

- 기본 폴더에서 로컬 테스트 19개 통과: 원본 보존 업그레이드, 필수 필드/태그 수정, rollback, 재시도, 동시 revision, 중복 완료, 권한/관계, 검색/정렬, 주소 검사와 시간 계산.
- 기본 폴더의 최종 npm run typecheck 및 npm run build(Turbopack) 통과. 마지막 태그 입력/필터 보정까지 빌드에 포함했습니다.
- HTTP smoke: 연결 미설정/잘못된 JSON/다른 Origin 거부/거짓 저장 성공 방지.
- HTTP integration: Next.js API → Supabase SDK → 임시 로컬 RPC 어댑터 → PGlite. 실제 앱 경로의 생성/수정/재조회·태그/이력·중복 요청/충돌/구형 스키마 쓰기 차단을 검증. 공개 안내와 script 문자열의 HTML 이스케이프·임시 테스트 키의 HTML 미포함 확인.
- 통합 테스트의 자료/키는 해당 테스트의 임시 로컬 자료입니다. 외부 NAS/실제 Supabase PostgREST·JWT/RLS 전체 구성·브라우저 조작·키 누출 전체 감사·새 기기 공유 검증이 아닙니다.

GitHub 업로드·main 통합·NAS DB 변경·실제 앱 연결·공개 배포는 이번 구현 범위에 포함하지 않았습니다. 기존 미커밋 지침/목차/개발 인계는 보존합니다.
