# 디자인 방향 검토 01 — 인쇄와 주석이 공존하는 기록장

> 최신 결정: 사용자가 손글씨 제거/두 서체 통일을 요청했습니다. 이 문서는 이전 제안 기록이며, 현재 서체 기준은 [디자인 검토 02](DESIGN-DIRECTION-NOTEBOOK-02.md)입니다.

요약: 기존 ‘돌아보기 → 계획 결과’ 한 화면으로 정교한 세리프, 명료한 조작 활자, 실제 한글 기록의 짧은 손글씨를 검토합니다. 제안 단계이며 본 시안/실제 앱의 디자인 확정 또는 전체 적용이 아닙니다.

## 현재 단계와 검토 화면

사용자가 02.39의 휴식/중단 입력 방식에 동의했습니다. 기능/관계/화면 흐름/데이터 계약을 유지하며 시각 방향을 검토하는 단계입니다. 검토 파일은 Haru 디자인 검토 01（로컬 자료: `../outputs/Haru-design-study-01.html`）, 본 기능 시안은 02.39（로컬 자료: `../outputs/T06-flow-v2.39.html`） 그대로입니다. 실제 React 앱은 첫 저장 범위이며 전체 기능 시안을 이식하지 않았습니다.

검토본은 기존 02.39 런타임을 사용하고 계획 결과부터 열립니다. 예시 자료는 독립 `haru.design-notebook-study.v1.*` 저장 키를 사용합니다. 본 자료를 읽어 복사하거나 덮어쓰지 않습니다. 신규 기록 유형/필드/권한/강조 선택 기능을 확정하지 않습니다. 근거를 기본 펼쳐 보여주는 것은 디자인 검토 시작 상태입니다. 실제 서비스의 상세 기본 접힘 규칙 변경이 아닙니다.

## 제안하는 인상

차분하게 인쇄된 사실 위에 사용자의 생각이 펜으로 덧붙은 개인 기록장. 영국 고전 출판물의 대비/비례와 오래된 문학 잡지의 여백을 참고하지만 특정 작품의 제호·문장·소품·문양을 복제하지 않습니다. 셜록 홈즈/해리 포터 이름이나 시각 자산을 서비스에 사용하지 않습니다. 역사적 서체의 정확한 재현이라고 주장하지 않습니다.

반항적인 요소는 짧은 생각의 느슨한 획과 한 번 그은 밑줄로 제한합니다. 정보를 비틀거나 조작 요소를 불규칙하게 배치하지 않습니다. 장식 영문 대신 실제 한글 기록을 이 분위기의 중심으로 둡니다.

## 활자 역할과 후보

| 역할 | 검토 서체·크기 | 실제 검토본 적용 |
|---|---|---|
| 가장 큰 제호 HaruLeaf | Cormorant Garamond 500, 84px | Haru는 정자, Leaf는 같은 가족의 이탤릭. 영국 고전 출판물을 연상시키는 획 대비와 비례 후보 |
| 한글 페이지/섹션/할 일 제목 | Noto Serif KR 500, 38/25/19px | 같은 크기의 명조 제목을 반복하지 않고 단계별 크기와 여백으로 구분. 한글을 인위적으로 늘리거나 기울이지 않음 |
| 설명·버튼·입력·시간·숫자 | Pretendard, 12–15px / 집계 숫자 43px | 실제 작업/시간 차이도 조작 활자로 명료하게 표시. 숫자는 tabular-nums. 제호의 세리프를 숫자에 강제하지 않음 |
| 짧은 사용자 기록 | Nanum Pen Script, 27px | 예시의 현재 막힌 이유 100자 이하에만 적용. 이유는 한 번만 출력. 긴 이유는 Noto Serif KR 17px/1.9로 유지 |
| 긴 회고 본문 | Noto Serif KR 400, 17px/1.9 후보 | 이번 계획 결과 화면에는 회고 본문이 없으므로 실제 회고 화면 적용/검증은 미완료 |

Nanum Pen Script(나눔손글씨 펜)는 한글 획 리듬을 볼 첫 후보입니다. 원하는 빠른 잉크펜 느낌에 충분한지, 귀엽게 느껴지는지 아직 사용자 판단이 필요합니다. 가상의 굵기/기울기를 폰트 파일에 가공하지 않습니다. 본문·버튼·시간·집계·입력 편집 중에는 손글씨를 쓰지 않습니다.

회고에는 짧은 강조 문장 한두 개 정도로 확장하는 방향을 제안합니다. 어떤 문장을 사용자가 선택하는 기능/데이터 구조는 아직 확정하지 않으며 이번 검토본에서 새로 만들지 않았습니다. 단상의 전체 본문을 무조건 손글씨로 바꾸는 안도 확정하지 않습니다.

## 기존 화면에서 바꾸는 요소

| 기존 요소 | 검토안 |
|---|---|
| 중앙 정렬 제호·양쪽 신문식 문구 | 제호와 좌측 짧은 설명의 비대칭 비례. 작품 로고를 모방하지 않고 HaruLeaf 표기 유지 |
| 같은 서체가 이어지는 제목·조작 정보 | 한글 제목 세리프 / 정보 산세리프 / 실제 짧은 기록 손글씨의 역할 분리 |
| 지표마다 테두리와 배경 | 같은 지표/클릭 기능을 유지하고 개별 상자 제거. 개수 4열과 시간 3열의 구조 유지 |
| 선택 지표의 카드식 강조 | 지표명과 짧은 펜 밑줄. 무채색에서도 밑줄·aria 상태로 구분 |
| 실행 근거를 둘러싼 카드 | 할 일 아래 여백·짧은 가는 세로선으로 실행을 구분. 실행 날짜/시각/작업/중단/이유/구간 상세 유지 |
| 화면 전체의 촘촘한 선 | 큰 구획에서만 가는 선, 세부 항목 간 여백으로 구분 |
| 근거 속 한글 이유 문장 | 짧은 기록은 손글씨로 보여주되 원문/집계/수정 경로 그대로. 별도 감성 문구로 복제하지 않음 |

섹션 간 40–48px, 항목 안 8–16px, 제목과 부연 설명의 크기/무게 차이를 사용합니다. 900px 내외의 내용 폭 유지. 화면에 모든 것을 네모 테두리로 감싸지 않지만 입력 경계/클릭 가능 여부/포커스 표시는 읽을 수 있게 남깁니다. 모바일에서는 별도 한 줄 흐름과 글씨 크기 조정이 필요하며 실제 기기 검증은 미완료입니다.

## 기능/과제 대조와 검증 한계

- 계획 결과의 계획한 할 일/완료/지연/막힘 및 예상/실제/차이 7개 지표와 각 클릭 경로 유지.
- 이유를 저장한 할 일을 한 번 세는 집계, 할 일→실행 근거 펼침, 다음 계획 개선점 전달, 타 화면으로의 기존 이동 유지.
- 무인증 공개 안내는 제품 적용 문구로 화면에 표시하며 실제 서버 미연결/브라우저 검토용 안내도 별도로 유지. 검토 HTML을 공개 DB 서비스라고 설명하지 않음.
- 과제 C26/C28–C33/C83 등의 필수 기능을 분위기를 위해 삭제/축소하지 않음. 실제 DB/복원/개수 증거/공개 배포 완료는 이 검토안만으로 판정하지 않음.
- 스크립트 구문, 기존 화면 시작/지표 7개/근거 클릭/개선점 진입/한글 기록 한 번 출력/독립 저장/폰트 역할 선언 점검 통과. 모의 DOM 점검이며 실제 서체 로딩·화면 크기·모바일 가독성·키보드/색 대비의 최종 시각 검증은 미완료.
- 브라우저에서 외부 웹폰트를 불러오지 못하면 대체 서체가 보일 수 있음. 현재 사용자 기기의 실제 로딩 결과는 확인되지 않음.
