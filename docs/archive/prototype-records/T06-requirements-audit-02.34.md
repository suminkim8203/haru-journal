# 02.34 합의 사항과 과제 필수 조건 재점검

요약: 기능 제거 합의 세 가지(C26/C31/C33)는 직접 충돌하며, 루틴을 기간 없는 계획으로 저장하는 시안·데이터 계약도 C04에 맞춰 보정해야 합니다. 화면 스타일 변경은 유지할 수 있습니다. 충돌 결정과 아직 구현하지 않은 기능은 구분합니다.

## 기준과 확인 범위

- 작업 기준: docs/T06-ASSIGNMENT-RULE.md 전문. 사용자 예외는 본인 실제 활동 자료만 사용해야 하는 조건을 제외하고 예시/더미를 허용하는 것입니다. 최소 자료 개수/서버 저장/공개/보안 등으로 확대하지 않습니다.
- 현재 HTML: outputs/T06-flow-v2.34.html의 실행 스크립트. 내장 과거 비교 JSON이나 호출되지 않는 옛 함수는 현재 기능으로 세지 않습니다.
- 제품 결정: docs/PRODUCT-DESIGN-CONSTRAINTS.md, IMPLEMENTATION-DECISIONS.md, DATA-CONTRACT-v1.md.
- 실제 앱: web/src/components/plans.tsx, web/src/lib/contracts.ts, web/src/lib/storage.server.ts, web/src/app/page.tsx, web/supabase/migrations/0001_core.sql 및 web/src/app/api.
- 인프라: infra/supabase/README.md 후속 기록. 이번에 원격 상태/실제 환경 변수/배포 상태를 재검증하지 않았습니다.

## 충돌하거나 계약 보정이 필요한 합의

| 합의/현재 구조 | 필수 기준 | 판정 및 기준을 유지하는 최소 대안 |
|---|---|---|
| 막혔던 이유를 없애고 단상 및 중단 시간만 남김 | C26: 실행 기록에 막혔던 이유 저장 | 직접 충돌. 실행 기록의 접힌 세부 영역에 선택 입력 ‘막힌 이유’를 둡니다. 중단 구간이 없어도 입력할 수 있어야 하며 일반 단상을 이유로 자동 분류하지 않습니다. |
| 돌아보기의 막힘 집계 삭제 | C31: 이유가 하나라도 적힌 할 일 수와 일치 | 직접 충돌. 계획 결과에 막힘 수와 같은 대상의 근거를 복원합니다. 한 할 일에 여러 이유가 있어도 1개로 세며 시간 길이나 단상 개수로 대신하지 않습니다. |
| 회고→계획 메모 전달 삭제 후 개선점 전달 경로도 없음 | C33: 돌아보기에서 정한 고칠 점 한 건이 다음 계획으로 넘어감 | 직접 충돌. 회고는 독립으로 두고, 계획 결과의 ‘다음 계획에서 바꿀 점’ 한 줄을 대상 계획에 명시적으로 저장하는 경로를 둡니다. 범용 메모 붙이기/전날 일기 전달 기능을 되살릴 필요는 없습니다. |
| 루틴도 plans의 한 종류지만 루틴 묶음의 기간을 비움 | C04: 계획에 기간 저장 | 시안·계약 보정 필요. 현재 commit은 루틴 계획의 start/end를 비우고 반복 규칙에만 기간을 둡니다. 첫 SQL도 routine의 계획 기간은 NULL로 정합니다. 원문에 루틴 계획 예외는 없습니다. plans로 유지한다면 계획의 기간도 저장해야 합니다. 반복 할 일의 고유 기간 및 누적 100% 표시를 제공하지 않는 결정은 별개로 유지할 수 있습니다. 실제 앱의 루틴 생성 기능은 아직 없습니다. |

위 최소 대안은 제안이며 아직 승인/구현되지 않았습니다. 특히 네 번째 구조는 이전 02.32 감사에서 충분히 지적하지 못한 부분입니다. 사용자 화면 간소화 의도 자체가 문제인 것은 아니며 필수 데이터/집계/전달을 남기는 방식으로 보정해야 합니다.

## 유지 가능한 합의와 조건

| 합의 | 대조 결과 |
|---|---|
| Haru/HaruLeaf, 조선일보명조 본문·로고 별도 서체, 무채색 바탕/포인트색, 폭/여백/메뉴/아이콘 | 과제는 특정 스타일을 요구하지 않습니다. 필수 정보 및 행동을 확인할 수 있게 유지하면 충돌하지 않습니다. 이번에 색/서체는 다시 변경하지 않았습니다. |
| 예정 시간/실행 기록/단상 기본 접힘 | 허용. 펼치기 진입점을 남기며 기록 작성/근거 접근을 막지 않습니다. |
| 주간 대표 항목 3개 및 해당 날짜 펼침, 7일 시간 사용 그래프 | 허용. 나머지 항목에 접근 가능하고 전체 합계 및 숫자의 근거 추적(C83)을 유지해야 합니다. |
| 계획 결과의 불필요한 전체 할 일 이동 버튼 삭제 | 허용. 숫자에서 대상 기록을 확인하는 경로(C83)는 계속 남겨야 합니다. |
| 회고는 하루 단위 독립, 보관함 회고 모음/휴지통, 회고 책갈피, 단상은 실제 할 일/날짜 하나 | 관계/용어는 원문이 지정하지 않습니다. C26의 이유 저장 및 C33의 개선점 전달을 별도로 충족하면 유지할 수 있습니다. |
| 루틴 누적 진행률/챌린지 없음, 일반 계획 결과와 루틴 활동 분리 | 챌린지/누적 100%는 필수 아닙니다. 일반 계획 결과는 대상 범위를 명시하고 그 범위의 미삭제 할 일을 정확히 집계해야 합니다(C28~C32). 루틴을 포함한 합계인 것처럼 표시하면서 제외하면 안 됩니다. |
| 휴식/중단 합계, 미지정 pause를 중단에 합산 | 허용. 작업/휴식/중단의 구간/시간을 보존하고, 중단 시간으로 막힘 수 또는 이유를 대신하지 않습니다. |
| 휴지통 이동/복원 및 자동 영구 삭제 보류 | 삭제 기능을 제공하는 범위에서 허용. T06에서 30일 자동 삭제를 적용하기로 확정한 상태가 아닙니다. |
| 로그인 없는 공개 단일 다이어리, 인증은 T07 | 과제와 일치합니다. NAS 관리 인증과 앱 사용자 인증은 별개입니다. |
| React/Next.js/Supabase, PC 개발 및 NAS 운영 목표 | 기술 선택은 제한하지 않습니다. 서버 실제 DB와 무인증 외부 결과물 URL은 반드시 필요합니다. 개발 PC 전용/내부망/VPN 전용이면 제출 C01은 충족하지 못합니다. |
| 예시/더미 허용 | 사용자가 지정한 작업 RULE 예외입니다. 계획 1개/소속 할 일 5개/종료 실행 3개와 정상 집계(C78~C81)는 유지합니다. 외부 평가 원문도 변경됐다고 설명하지 않습니다. |

## 실제 앱에 남은 구현 및 검증 — 합의 충돌과 별개

현재 React 앱은 일반 계획/할 일 생성·완료/완료 취소와 첫 조회/저장 API·SQL 트랜잭션 구조만 제공합니다. 계획 수정/원본 이력/우선순위/예상 시간 입력 UI, 할 일 수정/삭제/태그/검색/필터/정렬, 실행 및 이유, 돌아보기 집계/근거/개선점 전달, 전체 단일 파일 내보내기 등이 남아 있습니다. 완료 중복 방지의 로컬 검사와 실제 연결 DB/돌아보기 +1 증거는 구분합니다.

NAS Supabase 설치 기록은 있지만 앱 연결/프로젝트 스키마 적용은 해당 기록에서 미완료입니다. 원격 DB 저장 및 새로고침 ID/날짜/값/단위 일치(C34/C35), 최소 자료/집계(C78~C81), 배포 첫 화면 공개 안내(C82), 무인증 결과물 및 소스 URL(C01), 최종 비밀값/스크립트 저장·재표시 검사(C57/C58), 최종 contracts/pds-schema-v2.json, 확인 방법 4줄/AI와 본인 판단 3줄(C59/C60)도 필요합니다. 아직 제출 완료로 판정하지 않습니다.

## 체크박스 깜박임 재보고

사용자는 02.33에서도 체크 때 깜박임이 남는다고 보고했습니다. 기존 직접 함수 검사와 이번 전체 change listener 모의 실행은 전체 render 0회/저장 1회를 확인했지만 실제 브라우저의 깜박임을 재현한 검사가 아닙니다. ‘깜박임 해결’이라는 이전 표현을 정정합니다. 남은 원인은 현재 확인되지 않았으며 시안에서 해결 불가능하거나 React가 자동 해결한다고 단정하지 않습니다. 이번에는 완료 코드를 추가 변경하지 않고 실제 앱 일간 구현 시 브라우저 재현/불필요한 화면 교체·로딩 UI·레이아웃 이동 검증 항목으로 넘깁니다.

## 다음 순서와 제안 규칙

과제와 합의 충돌 보정안 결정 → 데이터 계약 수정 → DB 적용/앱 연결 및 실제 저장 → 필수 계획/할 일/실행/집계/개선점/내보내기 구현 → 실제 브라우저 및 배포/제출 검증 순서입니다. 이미 합의한 스타일·용어·기록 패널을 다시 결정할 필요는 없습니다.

앞으로 사용자 제안 및 제가 제안할 변경을 과제 RULE에 먼저 대조합니다. 충돌이 있으면 관련 기준 번호/빠지는 기능/기준을 지키는 대안을 변경 전에 알립니다. 지시문에서 벗어나는 기능 제거를 먼저 제안하지 않습니다. 이 규칙은 AGENTS.md에 등록했습니다.
