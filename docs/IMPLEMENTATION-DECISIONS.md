# 구현 결정 — 현행 안내와 승인 이력

요약: 현재 구현 기준은 기능 02.39·디자인 05·기존 NAS Supabase 활용입니다. 과거의 클라우드 생성/제호 검토/필수 보정 승인 대기는 현행 상태가 아닙니다.

## 현행 결정

- T06 공개 단일 다이어리, 서버 DB 기준, 요청 재시도/충돌/실패 초안 보호. 사용자 로그인/소유권은 T07.
- 일반/루틴 모두 계획 기간 필수. 계획 우선순위·독립 예상 선언값, 여러 할 일 태그 유지.
- 회고 날짜 독립·단상 할 일/날짜별 하나·회고만 책갈피·보관함 회고 모음/휴지통.
- 자동 영구 삭제 없음. 실행/단상/회고 및 출처/수정 전 기록 보존.
- C26 실행 이유·C31 막힘 수·C33 다음 계획 개선점 최소 보정 승인 완료. 회고 붙이기 기능으로 대체하지 않음.
- 완료 시 동일 할 일 열린 실행도 같은 저장으로 종료. 완료한 일의 타이머/배치 제한, 수기 정정/단상 유지.
- 수기 구간 직접 HH:mm/공통 시계. 긴 분 단위 드롭다운 폐기, 범위/비중복 검증과 정확한 입력 보존.
- 디자인 05 승인 완료. 조선일보명조/Pretendard/Cormorant Garamond, 날짜 C안·큰 주간 범위 세리프·버건디 가는 펜 선. 새 서체/손글씨 없음.
- 기존 NAS Supabase 연결 기준. 관리자 인증·Studio 하위 경로·기존 DB 보존. 새 클라우드 중복 생성 없음.

## 실제 구현과 다음 작업

main과 첫 저장 브랜치의 범위는 [현재 상태](CURRENT_STATE.md), 상세 규칙은 [데이터 계약](DATA-CONTRACT-v1.md), 후속 작업과 사용자 확인 시점은 [진행 계획](implementation/NEXT-STEPS.md)을 따릅니다. 승인된 전체 범위가 실제 앱에 구현됐다고 판정하지 않습니다.

## 과거 결정의 보존

[정리 전 전체 승인/변경 이력](archive/current-before-consolidation-2026-09-18/docs/IMPLEMENTATION-DECISIONS.md)을 내용 변경 없이 보존합니다. 이력의 미완료·대기·배포 후보는 당시 상태입니다. 최신 승인에 충돌하는 이전 결정을 다시 적용하지 않습니다.

## 2026-09-18 — 로컬 첫 저장 기반과 필수 필드

새 제품 정책 승인 없이 기존 설계의 계획 우선순위/독립 예상 선언값·다중 태그를 구현했습니다. tags/task_tags 다중 연결, 30자/20개 초기 검증, schemaVersion=2, 같은 완료 상태 no-op 및 APP_ORIGIN 설정을 기술 선택으로 기록합니다. 물리 구조/제한은 사용자 인증이나 새 기능 의미를 확정하는 선택이 아닙니다. 초기 계획 화면에 승인한 3가족 웹폰트 역할과 브랜드를 지정했으며 전체 이식/실제 글리프 검증은 후속입니다. [구현·검사 기록](implementation/PLAN-TASK-FIELDS-2026-09-18.md) 참조.

## 2026-09-18 — 백엔드 Supabase 직접 사용

사용자 요청으로 앱 서버/서버 비밀키 중계 방향을 취소했다. 공개 anon SDK→고정 단일 다이어리의 DB 함수로 연결한다. 기존 핵심 SQL을 유지하고 0006에 DB 입력 검증·고정 경계·함수 실행 권한을 추가했다. 브라우저의 검증을 신뢰하지 않으며 내부 테이블 직접 쓰기는 금지한다. 실제 NAS 적용과 검사·미구현 범위는 [구현 기록](implementation/SUPABASE-BACKEND-2026-09-18.md) 참조. 이전 서버용 환경 변수 안내는 현재 앱 연결 방식이 아니다.
