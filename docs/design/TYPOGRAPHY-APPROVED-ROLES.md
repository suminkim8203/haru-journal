# 승인한 서체 적용 기준 — 역할에 따른 배치

요약: 메뉴·주요 제목·서술형 사용자 기록과 해당 편집창은 조선일보명조체, 보조 설명·작은 라벨·일반 조작 요소는 Pretendard를 사용합니다. 기존 영문 제호 Cormorant Garamond를 유지하며 총 세 가족입니다.

## 적용 범위

사용자가 비교 시안을 확인한 뒤 역할을 승인했습니다. 적용 시안 04（로컬 자료: `../outputs/Haru-design-study-04.html`）, 대표 다섯 역할 예시（로컬 자료: `../outputs/Haru-typography-role-example-01.html`）를 작성했습니다. 본 기능 시안 02.39와 실제 React 앱/API/DB에는 아직 이식하지 않았습니다. HTML 검토안의 기능/구조는 유지합니다. 리디바탕은 비교 후보였으며 최종 선택이 없으므로 이번에는 추가하지 않았습니다. Noto Serif KR/손글씨도 없음.

이전 A/B 가설의 ‘작은 메뉴/할 일 목록은 산세리프, 기록 입력은 산세리프’ 부분은 최신 사용자 결정으로 대체됩니다. 글자 크기에 관계없이 주요 제목과 메뉴를 세리프로 유지합니다.

## 실제 적용

| 역할 | 대표 텍스트/영역 | 서체 |
|---|---|---|
| 메뉴 | 일정/계획/돌아보기/보관함, 일간/주간/월간 | 조선일보명조 400 |
| 주요 제목 | 페이지·큰 섹션·계획 제목, 첫 사용 흐름 정리하기, 좁은 주간 칸의 할 일 제목 | 조선일보명조 400 |
| 보조 설명 | 할 일 완료, 플랜두씨 다이어리 만들기 · 예상 1시간, 날짜/시간/우선순위/안내/오류 | Pretendard |
| 작은 항목 라벨 | 단상, 예상 시간, 실행 기록, 예정/실제, 입력 라벨 | Pretendard |
| 기록 본문 | 저장한 단상·회고·사용자가 작성한 실행 이유/할 일 설명/개선점 문장 | 조선일보명조 400 |
| 기록 작성/편집 | 단상/회고/실행 이유/서술형 할 일 설명/개선점 입력 | 조선일보명조 400 |
| 일반 조작 | 기록 시작/저장/수정/삭제, 검색/필터/날짜 선택·제목 입력 | Pretendard |
| 제호 | HaruLeaf | Cormorant Garamond 500 정자체 |

기록 본문 17px/1.9, 기록 textarea 17px/1.8. 일반 입력 16px. 기존 레이아웃/제목 크기/여백은 유지. 지원되지 않는 명조 굵기는 합성하지 않으며 400만 사용합니다. 숫자는 별도 Pretendard/고정 폭 숫자 지정. 다만 숫자가 포함된 주요 제목은 제목 역할을 우선합니다.

## 애매한 요소의 분류와 근거

| 요소 | 이번 분류 | 이유 |
|---|---|---|
| 주간의 작은 할 일 제목 | 주요 제목 → 세리프 | 크기가 작아도 해당 할 일을 식별하는 이름 |
| 상세 제목 아래 소속 계획명 | 보조 정보 → 산세리프 | 독립 계획 제목이 아니라 소속을 설명하는 줄 |
| 계획 선택 select에 표시한 계획명 | 일반 선택 조작 → 산세리프 | 같은 이름이어도 필터/선택 입력의 값 |
| 돌아보기/보관함의 분류 탭 | 메뉴 → 세리프 | 페이지 내부의 보기 전환이므로 메뉴와 동일 |
| 예정/실제/마감 1개 | 작은 구획 라벨 → 산세리프 | 주간 칸 안의 정보 구분 |
| 일간 페이지 제목 ‘9월 18일 금요일’ | 페이지 제목 → 세리프 | 페이지의 주요 제목으로 사용되는 날짜 문구 |
| 요일 옆 날짜/날짜 선택 버튼 | 날짜·조작 정보 → 산세리프 | 조회/집계/일정 배치에 쓰는 실무 정보 |
| 회고 카드의 날짜 제목 | 기록의 주요 제목 → 세리프 | 회고 자체를 식별하는 제목. 부속 수정 시각은 산세리프 |
| 막힌 이유의 라벨/본문 | 라벨 산세리프, 사용자 문장 세리프 | 집계 항목과 기록 원문을 구별 |
| 다음 계획 개선점의 펼침 이름/원문 | 작은 라벨 산세리프, 문장·편집 세리프 | 메모의 안내·출처와 작성한 내용을 구별 |
| 할 일 설명 | 작성한 서술형 원문·편집 → 세리프 | 단순 시스템 안내가 아닌 사용자가 작성한 설명 |
| 성공 기준·태그·예상 시간 등 계획 필드 | 실무 정보/일반 입력 → 산세리프 | 회고/단상 기록과 구별되는 계획 설정 정보로 적용 |
| ‘오늘 마무리’ | 큰 섹션 제목 → 세리프 | 하루 마무리 영역의 의미 구획 |
| ‘이 날짜의 단상 가져오기’ | 작은 펼침 라벨 → 산세리프 | 가져오기 도구의 설명. 안의 원문은 세리프 |

모호한 내용을 새 기능/데이터 계약으로 확정하지 않습니다. 위 표는 현재 화면의 시각 역할 분류입니다.

## 구현 방식과 검증 한계

기존 요소의 클래스/업무 맥락에 명시적 역할 속성을 부여했습니다. 전체 h1/h2/p/textarea를 서체의 근거로 일괄 분류하지 않습니다. 입력의 이름·기능과 제목/설명/기록의 실제 사용 위치로 매핑합니다. 역할 CSS가 과거 비교용 스타일보다 우선합니다. 기본은 산세리프로 두고 명시한 메뉴/주요 제목/기록만 세리프입니다.

일반 렌더 및 부분 업데이트/모달에도 역할이 유지되도록 매핑합니다. 역할 속성은 DOM 표현일 뿐 저장 데이터 필드가 아닙니다. 기존 검토 저장소를 유지하며 데이터·완료·집계·이동 로직 변경 없음. 단상/회고/막힌 이유 같은 기존 관계도 유지합니다.

기존 모의 DOM의 집계 7개/근거/개선점/중복 없는 이유/독립 저장 및 스크립트 구문 점검 통과. 역할 CSS/선언 확인. 직접 브라우저 서체 로딩·실제 글리프·좁은 칸 가독성은 현재 확인되지 않음. 로컬 파일 브라우저 제한을 우회하지 않았습니다. 완료 체크 잔여 깜박임 해결로 설명하지 않습니다.

다섯 역할 대표 예시는 한 화면에서 메뉴/할 일 제목/소속·완료·예상 정보/단상 라벨/기록 본문·입력을 보여줍니다. 이 예시 textarea는 저장되지 않으며 실제 입력 기능은 적용 시안에서 확인합니다. 기능/정보 구조/필수 안내를 삭제하지 않아 과제 RULE과 충돌 없음.

다음은 대표 예시와 주간·단상·회고에서 역할 배치 확인 → 필요한 크기/행간만 보정 → 승인 규칙의 실제 앱 컴포넌트 이식입니다.


## 날짜 역할 예외 승인 — 디자인 검토 05

사용자는 일간 날짜 줄 C안을 선택했습니다. 요일은 메뉴 역할의 조선일보명조, 숫자와 작은 ‘오늘’ 표시는 Pretendard를 유지합니다. 별도 크기 선택이 없으므로 기존 크기·간격을 유지했습니다. 돌아보기 날짜별 시간 사용의 큰 월.일–월.일 범위는 제목 역할로 조선일보명조 400을 적용합니다. 숫자를 일괄 세리프로 바꾸자는 내용은 고민이며 아직 승인이 아닙니다. 캘린더·주간·월간·집계·기록 시간의 다른 숫자는 변경하지 않습니다.

계획 결과의 선택 지표 밑줄은 바랜 버건디 #75444b, 주 획 2.2→1.6으로 약 27% 가늘게 변경했습니다. 보조 획 .8과 기존 곡선 형태·폭·선택 동작 유지. 최신 검토본 outputs/Haru-design-study-05.html이며 04/본 기능 시안 02.39/실제 앱/API/DB는 미변경입니다. 새로운 서체·기능·데이터 결정 없음, 필수 집계·근거 이동·공개 안내 유지, 과제 RULE 충돌 없음. 구문 및 기존 모의 DOM 기능 점검 통과, 실제 브라우저/폰트 로딩/시각 결과 미확인. 다음은 일간 날짜 줄·돌아보기 날짜 범위·선택 밑줄 확인 후 실제 앱 이식으로 진행.

## 디자인 검토 05 — 최종 사용자 승인 (2026-09-18)

사용자가 시안 05를 확인하고 ‘된듯 이렇게 가자’로 승인했습니다. 서체 역할 규칙 및 날짜 예외(C안: 일간 요일 세리프·숫자 산세리프, 돌아보기 큰 날짜 범위 세리프), 버건디 선택 밑줄의 색·굵기를 현재 디자인 기준으로 확정합니다. 이전 날짜 비교의 미확정 상태는 이 승인으로 대체합니다. 숫자를 전체 세리프로 전환하는 추가 변경은 승인하지 않았습니다. HTML 검토본에 적용된 상태이며 실제 React 앱 적용 완료를 의미하지 않습니다. 사용자의 시각 검토 승인과 자동 브라우저/폰트 검증 여부는 별개입니다. 다음은 실제 앱의 구현된 화면과 승인 시안의 차이를 확인한 뒤 역할별 서체·공통 스타일을 이식합니다. 데이터 계약과 미구현 기능을 임의로 확정하지 않습니다.
