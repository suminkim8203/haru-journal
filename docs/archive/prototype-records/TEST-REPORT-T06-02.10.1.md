# T06 02.10.1 점검 보고서

한 줄 요약: 기존 31개와 신규 8개, 총 39개 자동 점검이 통과했습니다. 실제 브라우저 UI 검증은 아닙니다.

## 방법

실제 HTML 스크립트를 Node 독립 실행 환경에서 실행했습니다. 문서 객체와 저장소는 대체했습니다. 검사 전용 접근 지점은 메모리에만 추가했으며 전달 HTML에는 넣지 않았습니다. 버튼/고정 배치 검사는 생성 마크업과 CSS 선언 확인입니다.

## 신규 점검 8개

1. 계획 기간 안의 오늘/내일 빠른 선택으로 반복 생성 성공.
2. 계획 범위를 넘는 종료일을 둔 채 시작일만 바꾸면 기존 공통 오류가 계속되는 사례 재현. 새 버전에서 종료일 문제를 특정하고 보정 후 생성 성공.
3. 종료일이 시작일보다 빠른 경우 두 날짜를 안내하고, 명시적 보정 버튼 전에는 입력을 자동 변경하지 않음.
4. 잘못 직접 입력한 날짜가 이전 숨겨진 날짜로 저장되지 않음. 유효한 직접 입력은 정상화 후 저장.
5. 계획 밖 빠른 선택 비활성화 및 동작 방어. 직접 입력한 계획 밖 시작일에 구체적 안내.
6. 이 날짜만 수정에는 반복 종료일이 불필요함. 이후 반복을 선택하면 종료일 표시·검증. 종료일 변경 중 적용 범위 단계 유지.
7. 종료 확인의 작은 버튼 마크업, 밝은 색 선언, 하단 sticky 유지·입력 패널과 같은 배경·패널 가장자리까지 연결·버튼 정렬 선언 확인.
8. 이전 버전 자료 첫 복사 시 원본 유지 및 이미 있는 수정본 자료를 덮어쓰지 않음.

기존 31개 점검에는 생성·완료·반복 예외 보존·중단·건너뛰기·겹침·실패 복구·회고·수동 기록·주간/월간 생성 등이 포함됩니다.

## 미검증

- 실제 마우스 클릭/드래그, 모바일 렌더링, 스크롤, 색상 인상, 키보드 초점 이동.
- 브라우저별 file URL 저장소 공유와 실제 입력 자료 복사.
- 오류 발생 당시 사용자의 실제 입력값.

브라우저 로컬 파일 접근 제한을 우회하지 않았습니다. 자동 점검 통과를 실제 화면 검증 완료로 해석하지 않습니다.

## 사용자가 확인할 흐름

1. 기록 시작 → 기록 종료 → 종료 확인 버튼의 새 모양 확인.
2. 새 루틴 입력에서 스크롤해 하단 취소/생성 영역이 고정되되, 배경색과 가로 폭이 입력 패널에 자연스럽게 이어지고 버튼 여백이 균일한지 확인.
3. 반복 시작일을 오늘·내일로 선택하고, 화면에 표시된 계획 기간과 종료일을 확인.
4. 기간 오류가 있으면 안내에 나온 날짜 보정 버튼으로 수정 후 생성.
5. 기존 반복 수정에서 이 날짜만/이후 반복을 비교. 이후 반복에서만 종료일 설정이 나타나야 함.
