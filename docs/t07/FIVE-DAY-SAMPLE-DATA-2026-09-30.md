# T07 지난주 과제 작업을 바탕으로 한 5일 예시 기록

요약: 사용자의 명시적 요청에 따라 9월 23~30일 과제 작업 주제를 골라 오전 9시대 계획·수기 실행의 **예시 값**을 구성했다. 작업 주제의 일부는 실제 대화·코드 이력에 근거하지만 아래 오전 시각과 분량은 사용자가 확인한 실제 수행 시간이 아니다. 서비스에 입력하더라도 실측 자료 또는 플랫폼의 당시 자동 작성 시각으로 설명하지 않는다.

관찰 질문은 `높은 우선순위 일반 할 일 하나를 먼저 배치하면 하루 실제 작업 시간이 달라지는가?`로 둔다. 지표는 `하루 작업 시간`, 단위는 `분`, 계산은 종료된 실행의 작업 구간을 Asia/Seoul 날짜별로 한 번만 더하고 휴식·중단을 제외한다. 누락은 0분으로 대체하지 않고 중복은 한 번만 세며 이상값은 근거를 확인한 뒤 유지·정정한다. 원값 합산 후 표시만 소수 첫째 자리로 반올림한다. 주 시작은 일요일이다.

예시의 규칙 변경 위치는 2일차인 9월 24일 뒤, 3일차인 9월 28일 앞이다. **예시상** 9월 27일 20:30으로 두었다. 변경 전에는 할 일을 고르는 순서를 고정하지 않는다. 변경 후에는 하루의 높은 우선순위 일반 할 일 하나를 첫 배치 대상으로 고른다. 이유는 우선순위가 화면에서 잘 드러나지 않아 중요한 일을 뒤로 미루기 쉬웠다는 사용자 피드백이다. 실제 변경 시각은 확인되지 않았다. 사후 작성한 문장을 당시 플랫폼 과정 기록처럼 제출하지 않는다.

예시 작업 시간 합계는 175분, 5일 평균은 35분이다. 변경 전 2일은 65분·평균 32.5분, 변경 후 3일은 110분·평균 약 36.7분이다. 실제로 확인된 9월 28일 15:00–19:00와 9월 29일 15:57–18:15 활동은 별도 기록이며 이 예시 오전 구간과 혼합하지 않는다.

## 서비스 저장·검산

2026-09-30에 사용자 요청에 따라 실제 Haru 계정의 별도 계획 `T07 · 지난주 과제 작업 정리`(9/23–9/30)에 위 할 일 5개, 각 예정 40분, 각 날짜의 오전 예정 배치와 수기 종료 실행 1건을 사후 입력했다. 3~5일차 할 일의 우선순위를 `높음`으로 설정했다. 5개를 완료로 표시했다. 9월 27일의 회고에는 1·2일차 수치, 예시 규칙 변경 시각·이유·변경 전후를 적고 **사후 구성한 예시**임을 명시했다.

새로고침 후 9월 30일의 예정 09:04–09:44와 실제 09:09–09:49가 복원됐고, 돌아보기에서 이 계획만 선택한 결과 `계획한 할 일 5`, `완료 5`, `예상 3시간 20분`, `실제 작업 2시간 55분`, `실제 − 예상 −25분`을 확인했다. 실제 작업의 근거를 펼쳐 9/23 32분, 9/24 33분, 9/28 39분, 9/29 31분, 9/30 40분의 수기 기록 다섯 건을 대조했다. 손계산 32+33+39+31+40=175분=2시간 55분과 일치한다. 플랫폼의 작성 시각은 9월 30일이며, 날짜 필드가 과거인 것은 당시 입력했다는 증거가 아니다.
