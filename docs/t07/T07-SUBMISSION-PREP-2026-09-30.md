요약: 공개 결과물과 인증 구현의 검증된 내용은 제출문으로 사용할 수 있다. 아래의 미래 계획을 실제 5일 사용 결과로 적거나, 확인하지 않은 오전 실행 시간을 만들어 쓰지 않는다. 최신 T07 소스의 공개 저장소 반영과 일부 증거는 제출 전 확인이 필요하다.

## 결과와 확인 방법

- 결과물 URL: https://haruleaf.com/
- 소스 저장소 URL: https://github.com/suminkim8203/haru-journal
- 인증 구현 설명: [AUTH-IMPLEMENTATION-DRAFT.md](AUTH-IMPLEMENTATION-DRAFT.md). 아직 검증 중인 초안이므로 그 문서의 한계를 함께 제출한다.
- 공개 URL의 새 시크릿 창 접근과 최신 배포 소스의 GitHub 일치 여부: **현재 재확인 필요**. 로컬 배포 소스는 `codex/t07-original-design-study`에 있고, 2026-09-30 확인한 GitHub `main` 추적 기준은 이전 T06 커밋이다. 저장소 기본 주소만 적고 T07 최신 소스가 공개됐다고 단정하지 않는다.

짧은 확인 방법 4줄:

1. 어디로 가나요: `https://haruleaf.com/`을 새 시크릿 창에서 열고 위 공개 소스 저장소를 확인한다.
2. 세 단계 안에 무엇을 하나요: 로그인 화면 확인 → 인증 설명서의 가린 요청·응답 기록 열기 → 로그인 전후와 계정 간 거절 결과를 비교한다.
3. 무엇이 보이면 통과인가요: 비로그인 첫 화면에는 개인 기록이 없고, 같은 자료 요청은 로그인 전 401/로그인 후 200이며 다른 계정 자료 요청은 404다.
4. 안 될 때는 무엇이 보이나요: 인증되지 않은 자료 요청은 401, 다른 계정 자료 요청은 404, 유효기간이 지난 세션은 다시 로그인 안내가 나온다.

AI와 내 판단 3줄:

1. AI에게 맡긴 일: 인증·자료 소유권 검사 구현, 화면 연결, 테스트와 요청·응답 증거 정리.
2. 내가 직접 판단한 일: 기존 디자인 유지, 6자리 이메일 코드, 8자 이상·공백 없는 비밀번호, 계정 화면 분리와 7일 탈퇴 유예를 결정했다.
3. AI 말을 따르지 않은 일: 비밀번호 12자 이상 제안은 채택하지 않고 8자 이상으로 바꿨으며, 불필요한 로그인 중 비밀번호 변경 UI도 제거하도록 했다.

## 선택 과정 기록 — 5일 관찰 시작 입력안

과정 기록은 플랫폼 화면상 선택 사항이다. 아래 내용은 **시작 기준**으로만 사용할 수 있고 관찰이 완료됐다는 주장으로 쓰지 않는다. 플랫폼의 자동 작성 시각 이전에 실제로 시작한 것처럼 기록하지 않는다.

- 5일 동안 답할 관찰 질문: `하루 계획에서 높은 우선순위 할 일 하나를 먼저 골라 배치하면 실제 작업 시간이 달라지는가?`
- 측정 지표: `하루 실제 작업 시간`
- 측정 단위: `분`
- 집계·계산 규칙: `Asia/Seoul 날짜별로 종료된 실행 기록의 작업 구간을 초 단위로 합산한다. 휴식·중단·진행 중 기록은 제외한다. 같은 기록은 한 번만 세고, 미기록은 0분으로 대체하지 않는다. 합계와 평균 계산 뒤 소수 첫째 자리에서 반올림한다.`
- 변경 전 계획 규칙: `할 일을 고르는 기존 방식을 사용하고, 높은 우선순위 할 일을 첫 배치 대상으로 정하는 순서는 고정하지 않는다.`
- 예정된 변경 규칙: `2일차 실제 기록 종료 후 3일차 활동 시작 전에 높은 우선순위의 일반 할 일 하나를 먼저 골라 시간을 첫 번째로 배치한다. 변경 시각·이유·1/2일차 참조를 남긴다.`
