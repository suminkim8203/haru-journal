[문서 전체 재검토](../reviews/MD-REREAD-2026-09-18.md) · [차이와 복원·검증 한계](../reviews/APPROVED-DESIGN-RESTORATION-2026-09-18.md). 원본 승인 기준은 Haru-design-study-05.html이며 승인 스타일을 직접 옮겼다. 공개 재배포 전 실제 복원 후보를 확인하고 기능 누락·검증 한계를 해결한다.

## 지면과 구조

넓은 여백·제목 크기 차·드문 가는 구획선으로 위계를 만듭니다. 무채색 종이와 검은 잉크 중심, 노란 선택 강조는 유지하며 버건디는 작은 강조에 제한합니다. 종이 질감은 매우 약하게, 손글씨/갈색 일색/찢은 종이·얼룩/기울인 콘텐츠·불규칙 조작 배치는 사용하지 않습니다. 특정 작품 로고나 소품을 재현하지 않습니다. 따뜻한형은 폐기했습니다.

계획/돌아보기/보관함 최대 콘텐츠 폭 940px, 콘텐츠 내부 왼쪽 정렬. 일정의 넓은 타임라인/주간 구조는 유지합니다. 보관함 탭 위치·크기·간격은 돌아보기와 동일합니다. 필수 정보·집계·근거·공개 안내를 삭제해서 분위기를 만들지 않습니다.

기록 표시: 승인된 300px 두 줄 종이색 패널·드래그·안전 영역·방향키·위치 기억, 펼치기 제거. [기록 표시 검토](RECORDING-UI-STUDY.md) 참조. 일반 UI 선호 저장과 실제 사용자 자료 DB 저장은 별개입니다.

## 2026-09-18 승인 시안 복원 및 실제 DB 보완

공식 Markdown 121개를 다시 읽고 차이를 기록했다. NAS에 0010_improvement_edits.sql까지 적용했다. snapshot 6·테이블 16개·공개 RPC 3개는 유지하며, 가져온 개선점의 독립 수정과 수정 이력을 복구했다. 수정 본문은 원본 문구·원본/대상 계획 연결·중복 판정 키를 바꾸지 않는다. snapshot의 improvementEditing=true로 실제 지원을 확인한다.

적용 전 백업: NAS /opt/supabase/backups/approved-design-recovery-20260918/. 기존 snapshot을 새 선택 필드 제외 후 비교하여 동일함을 확인했고 revision은 15→15였다. anon 권한의 생성/수정 검증은 트랜잭션 rollback으로 영속 자료를 남기지 않았다. 비공개 함수 경계도 유지했다. SDK 읽기 재검증: 계획 1·할 일 5·실행 3·단상 1·회고 1·개선점 0. 관리자 키를 앱에 이전하지 않았다.
