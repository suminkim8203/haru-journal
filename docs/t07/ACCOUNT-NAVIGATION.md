# 계정 화면 구조 정리 — 2026-09-23

요약: 계정 작업을 기록 화면 상단의 3개 버튼과 펼쳐지는 섹션에서 분리한다. 로그인 중 비밀번호 변경은 현행 제품 진입점에서 제거한다.

## 요구와 페이지
- 사용자의 최신 피드백: 로그인 중 변경 버튼이 꼭 필요한지 재검토하고, 계정 탈퇴·로그아웃·변경 버튼의 위치와 한 화면에 펼쳐지는 방식 수정.
- 기록 화면의 메뉴 오른쪽에는 작은 ‘계정’ 링크만 둔다. 누르면 `/account.html`로 이동한다.
- 계정 화면에는 내 기록 내보내기와 로그아웃, 계정 탈퇴 안내로 가는 링크를 둔다. 탈퇴 링크는 `/account/deletion.html`로 이동하고 기존 현재 비밀번호 확인·7일 유예·내보내기 안내를 유지한다. 탈퇴 신청 결과는 완료 화면으로 나타낸다.
- 로그인되지 않은 상태에서 계정 주소를 직접 열면 개인 기록이나 관리 내용 대신 로그인 화면을 보인다.
- 이메일 인증번호로 본인을 확인해 비밀번호를 재설정하는 절차는 로그인 화면에 유지한다. 로그인 중 변경 UI는 제거한다. Supabase Auth의 변경 기능 자체를 비활성화했다는 뜻은 아니다.
- T07-C114 ‘비밀번호 변경 후 이전 인증값 거절’은 비밀번호 재설정 성공 전후 같은 인증값으로 검증해야 한다. 아직 HTTP 증거를 수집하지 않았다.

## 현재 구현 및 검증 상태
- 코드: `web/src/components/journal-app.tsx`, `private-journal.tsx`, `account-home.tsx`, `account-shell.tsx`, `web/src/app/account/`.
- 로컬 타입 검사, 비공개 정적 빌드, 관련 인증 검사 9개 통과. `/`, `/account.html`, `/account/deletion.html`이 로컬에서 HTTP 200. 미인증 상태 `/account.html` 브라우저는 로그인 화면을 표시했다.
- 아래 배포 및 후속 검증 기록이 최신 상태다.

## 배포 및 후속 검증 — 2026-09-23

- release `t07-account-9ebfdfb4c271` 배포. 기존 웹 릴리스만 교체했으며 배포 도구는 DB를 변경하지 않았다.
- 공개 HTML/JS/CSS 21개가 검증한 정적 빌드와 해시 일치. `/account.html`과 `/account/deletion.html`은 공개적으로 200을 반환한다.
- 실제 비로그인 브라우저에서 `/account.html`을 열면 계정 자료와 조작 대신 로그인 화면이 나타났다.
- 사용자가 실제 사이트에 로그인한 뒤, 일정 메뉴의 `계정` 링크 → `/account.html`의 내보내기·로그아웃·탈퇴 안내 → `/account/deletion.html`의 탈퇴 안내·비밀번호 재확인·확인란을 브라우저에서 확인했다. 계정 화면에서 다시 일정으로 돌아왔고 로그인 상태가 유지됐다. 탈퇴 신청/삭제는 실제 사용자 계정으로 실행하지 않았다.
- 로그인 중 비밀번호 변경은 현재 화면에서 제거했고, 이메일 코드로 본인을 확인하는 비밀번호 재설정은 유지한다. 이전 인증값 거절은 별도 검증 과제다.
