# 기록 표시 UI 비교 — 01

## 현재 단계

02.31의 화면 흐름을 사용자가 긍정적으로 평가한 뒤, 기록 표시의 위치와 디자인을 별도로 검토하기로 했습니다. 현재는 기록 표시 UI의 러프 디자인 단계입니다. 본 화면 적용·실제 React 구현은 후속 작업이며 세 안 중 어느 안도 아직 확정하지 않았습니다.

비교 시안: Haru-recording-ui-study-01.html（로컬 자료: `../outputs/Haru-recording-ui-study-01.html`）.

## 공통 제약 및 제안

- 현재 기록의 제목, 경과 시간, 기록 중/잠시 멈춤 상태를 확인할 수 있어야 합니다.
- 사용자가 드래그로 위치를 옮길 수 있어야 합니다. 이동 손잡이는 멈춤/종료/돌아가기 버튼과 분리합니다.
- 손잡이의 방향키 이동 및 드래그를 대신할 네 모서리 위치 선택을 비교 시안에 제공합니다. 이동 중 취소하면 이동 전 위치로 돌아갑니다.
- 표시가 화면 밖으로 사라지지 않게 제한합니다. 크기 변경 및 펼침 시에도 위치를 제한합니다. 강제 가장자리 스냅은 이번 시안에서 사용하지 않습니다.
- 완전히 닫아 기록 상태를 숨기는 기능을 추가하지 않습니다. 접어도 제목·시간·상태는 유지합니다.
- 본문/패널에는 기존 조선일보명조 웹폰트, 가장 큰 제호에는 기존 나눔명조를 유지합니다.
- 안별·비교 화면 크기별 위치 기억은 독립 시안의 로컬 저장소에만 구현했습니다. 제품에 적용할 위치 저장 방식/화면 전환 시 유지/모바일 안전 영역은 실제 적용 시 검토합니다.
- 실제 기록과 연결되는 종료는 기존 확인 흐름을 유지합니다. 비교 시안은 별도 체험 확인창이며 실제 할 일/실행 기록을 저장하지 않습니다.

## 러프 디자인 후보

| 안 | 구성 | 장점 | 검토할 점 |
|---|---|---|---|
| A 지면형 | 가로 종이색 패널, 상단 이중선, 제목/시간, 접이식 조작 | 기존 신문형 화면에 연결되고 제목/시간을 함께 읽기 쉬움 | 가로 폭과 접힌 상태에서 조작까지 한 번 더 눌러야 하는 점 |
| B 여백형 | 세로 종잇장, 큰 시간 표시, 넉넉한 여백 | 시간 확인과 집중감 | 높이와 본문 가림이 커짐 |
| C 미니바형 | 먹색의 낮은 가로 바, 멈춤 상시 노출, 종료 펼침 | 낮은 높이와 명확한 배경 대비 | 긴 제목 생략, 좁은 화면의 조작 밀도와 대비가 강한 외형 |

A를 우선 추천하지만 사용자의 선택은 아직 없습니다. 위치/크기/조작을 함께 보고 다른 안의 요소를 조합할 수 있습니다.

## 레퍼런스 확인

- [Clockify Windows 공식 도움말](https://clockify.me/help/apps/windows-desktop-app): 메뉴의 mini timer와 상시 표시 설정을 확인했습니다. 작은 기록 조작 화면을 참고하는 근거이며 Haru에 해당 서비스 기능을 구현했다는 뜻은 아닙니다.
- [Toggl Windows 공식 도움말](https://support.toggl.com/en-us/article/toggl-track-desktop-app-for-windows-5w1y5/): 간결한 기록 시작/종료, compact/detailed 표시, 다른 창 위 표시 설정을 확인했습니다. 최소한의 기록 조작이라는 방향을 참고했습니다.

공식 도움말의 조작 패턴을 참고했으며 특정 제품 화면을 그대로 복제하지 않았습니다. Haru 디자인 후보는 별도로 구성했습니다. 웹의 페이지 내부 플로팅 표시와 운영체제의 다른 앱 위에 나타나는 데스크톱 창은 다른 기능입니다. 이번 범위는 웹 페이지 내부 표시입니다.

## 검증 및 후속 작업

work/test-recording-ui-study-01.cjs로 시안 스크립트 구문/초기화, 화면 경계 제한, 방향키, 저장된 위치 복원/잘못된 값 거절, 실제 드래그 이벤트 저장/취소, 버튼과 이동 분리, 멈춤/재시작 시간 계산, 종료 확인/취소/재체험, 안/모바일 폭 전환, 독립 저장 키 사용을 검사했습니다. 실제 브라우저 렌더링 및 물리적 터치 기기 검증은 미완료입니다.

다음: 사용자가 후보 또는 조합을 선택하면 해당 안과 드래그 이동을 본 시안에 적용하고, 실제 문맥에서 가림/위치 유지/모달/모바일 안전 영역을 확인합니다. 이후 실제 React 앱에 구현합니다. 현재 본 시안 02.31과 React 앱은 변경하지 않았습니다.

## 후속 단일 시안 — 02

사용자는 미니바형을 바탕으로 높이를 조금 늘리고 지면형 종이색을 쓰는 조합을 제시했습니다. 따라서 위의 A 우선 추천 대신 사용자 구성으로 단일 시안을 만들었습니다. 요청한 구성은 정해졌지만, 본 화면 적용은 시안을 확인한 뒤 승인하기로 했습니다.

파일: Haru-recording-ui-study-02.html（로컬 자료: `../outputs/Haru-recording-ui-study-02.html`）.

- 기본 상태: 손잡이 아이콘 → 기록 중 · 28분, 다음 줄에 할 일 제목과 멈춤/종료 아이콘, 그 아래 펼치기.
- 펼치기: 문자와 아래 화살표를 함께 표시하고 펼치면 접기/위 화살표로 바뀝니다.
- 펼친 상세: 경과 시간을 00시간 28분 00초처럼 표시하고 아래에 기록으로 버튼을 둡니다. 시계의 현재 시각이 아닌 실행한 경과 시간입니다.
- 종이색, 기존 본문 서체, 부드러운 얇은 테두리, 약한 그림자를 사용합니다. 손잡이와 조작 버튼을 분리하고, 기본 상태에서도 멈춤/종료를 숨기지 않습니다.
- 같은 파일 안에서 기본/펼친 모습을 나란히 비교하고 별도 체험 영역에서 드래그, 방향키 이동, 위치 선택, 모바일 폭, 모의 멈춤/재시작/종료를 확인할 수 있습니다.
- 체험 시간은 28분에서 시작합니다. 표시/위치 저장은 독립 시안 전용이며 본 시안 02.31 및 실제 React 앱의 실행 기록은 변경하지 않습니다.

검증: work/test-recording-ui-study-02.cjs 통과. 기존 이동/취소/경계/위치 저장/멈춤·재시작·종료 검사 재사용 및 요청한 단일 구성/접힌 상태의 두 조작/펼친 시간 단위/접기 검사를 추가했습니다. 브라우저 렌더링/실제 터치 기기 검증은 미완료입니다.

다음: 사용자 시각 확인 후 단일 시안의 구성과 드래그 이동을 본 화면에 적용합니다. 후보 추가나 실제 React 포팅을 먼저 진행하지 않습니다.

## 크기 축소 및 펼치기 제거 제안 — 03

사용자가 02의 크기를 크게 느껴 좌우/상하 모두 줄이고 상하를 더 많이 줄이는 방향을 요청했습니다. 펼치기의 필요성도 재검토했습니다. 독립 시안 03（로컬 자료: `../outputs/Haru-recording-ui-study-03.html`）에서 폭을 360px에서 300px로 줄이고 세 줄을 두 줄로 정리했습니다.

- 첫 줄: 손잡이, 상태·경과 분, 우측 작은 기록으로 버튼.
- 둘째 줄: 할 일 제목, 멈춤·종료 아이콘. 글자 크기는 지나치게 줄이지 않고 여백과 버튼 배치를 먼저 줄였습니다.
- 펼치기/접기와 별도 시·분·초 영역을 새 표시 UI에서 제거했습니다. 상태 확인과 조작을 바로 할 수 있으므로 제거를 추천하지만 본 화면 적용은 사용자 시각 확인 후 진행합니다.
- 이전 기본 상태와 축소안을 비교하는 정적 예시 및 새 안의 드래그/모바일 폭 체험을 제공합니다. 터치 환경에서는 멈춤/종료의 버튼 영역을 44px로 확보합니다.
- 기존 종이색·조선일보명조·드래그/방향키/위치 기억을 유지합니다. 본 시안 02.31 및 React 앱은 변경하지 않았습니다.

work/test-recording-ui-study-03.cjs 통과: 기존 이동/경계/저장·취소/키보드/시간 계산/모의 종료와 함께 두 줄 구성, 펼치기 제거, 상시 기록으로/멈춤/종료를 검사했습니다. 실제 브라우저 렌더링 및 실제 터치 기기 확인은 미완료입니다. 다음은 축소안 확인 후 본 화면 적용입니다.

## 사용자 승인 및 본 시안 적용 — 02.32

사용자가 시안 03을 승인하고 본 시안 적용을 요청했습니다. outputs/T06-flow-v2.32.html에 300px 두 줄 종이색 패널과 드래그 이동을 적용했습니다. 실제 작업 시간과 기존 멈춤/종료 확인을 연결하고, 종료 확인 중에는 멈춤을 잠그며 종료 조작으로 기존 확인 화면에 복귀합니다. 다른 화면에서도 위치를 유지하고 브라우저 UI 선호 키로 위치를 기억합니다. 위치 선호는 사용자 자료의 서버 DB 저장과 별개입니다. 안전 영역 밖 이동 제한, 방향키, 터치 버튼 영역 확보를 반영했습니다. React 앱 적용은 후속 작업입니다.
