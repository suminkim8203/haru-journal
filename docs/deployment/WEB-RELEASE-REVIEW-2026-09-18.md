# 공개 웹 배포 검토안

요약: 완성한 정적 React 앱을 기존 NAS에서 제공하고 https://haruleaf.com/의 현재 404를 제품 첫 화면으로 바꾼다. 파일/계획은 준비했으며 실제 공개는 사용자 확인 전이다.

## 검토 가능한 결과

- 로컬 실제 앱: http://127.0.0.1:3217/ — 정적 생산 빌드와 실제 NAS DB 연결. 이전 HTML 시안이나 브라우저 모의 저장이 아니다.
- npm test 48/48, build:static/타입, 정적 HTTP/JS/공개 안내/환경·소스 및 폐기 API 404 검사 통과.
- 승인된 공개 예시 자료는 기존 NAS에 그대로 있다. 공개 과정에서 새 활동이나 루틴 자료를 추가하지 않는다.
- 배포 파일: web/.next-static. 운영 설정 후보: [infra/web](../../infra/web/README.md). 스키마: [pds-schema-v2.json](../../contracts/pds-schema-v2.json).

## 사용자 확인 대상

위 실제 화면을 https://haruleaf.com/에 로그인 없이 공개한다. 현재 T06은 고정 단일 공개 다이어리이며 링크를 아는 사용자는 같은 자료를 열람·수정한다. 앱 사용자 로그인은 붙이지 않는다. Studio 관리자 인증은 별개로 유지한다.

## 실제 변경 순서

1. 소스 revision과 정적 파일 SHA256을 기록하고 새 release 폴더에 파일을 준비한다. .env/소스/서버 비밀키는 배포하지 않는다. 브라우저에 필요한 공개 anon 연결은 검증한 웹 파일 안에 포함된다.
2. 공식 NGINX 이미지 버전/digest를 확인해 내부 컨테이너를 준비하고 설정/health/HTML·JS·공개 안내를 검사한다. 아직 외부 공개 포트를 추가하지 않는다.
3. 기존 Envoy 설정과 라우팅을 백업한다. 현행 관리/API 라우트 뒤의 마지막 루트 direct_response 404만 haru-web:8080으로 연결하고 upstream을 추가한다. 앞선 라우트/관리 인증 및 기존 외부 HTTPS/Caddy 전달은 보존한다.
4. 설정 검증 후 원자적으로 전환한다. 공개 HTTPS 앱→기존 자료→집계 근거 이동/내보내기와 모바일을 검사한다. 사용자 승인 범위 밖의 새 자료는 입력하지 않는다.
5. 실패하면 백업한 Envoy 설정과 이전 release로 되돌린다. 앱 롤백을 이유로 기존 DB를 초기화하거나 적용 SQL을 재실행하지 않는다.

## 직접 확인한 현행 상태와 남은 검사

2026-09-18 현재 HTTP 검사: 루트 404, /supabase/ 무인증 401, 키 없는 /rest/v1/rpc/haru_snapshot 401. 기존 NAS 조회/명령/내보내기는 앱의 anon 연결에서 작동한다. Docker 네트워크 supabase_default와 supabase-envoy 가동을 확인했다.

NAS 현행 Envoy 설정에서 마지막 루트 404만 교체하는 후보를 생성했다. /opt/supabase/backups/haru-web-prepared-20260918/에 현행 백업·후보 LDS/CDS·해시 검토 기록을 보관했다. 기존 7개 upstream을 모두 보존했고 activated:false다. 전환 전에 현행 설정 해시가 검토 기록과 같은지 다시 확인한다. 운영 이미지 digest·NGINX 실행/설정 검사·라우터 전환·공개 HTTPS 제품 URL/별도 기기는 공개 단계의 후속 검사다. 현재 파일 준비를 운영 배포 완료로 설명하지 않는다. 현재 자료/일부 브라우저/대량 반복/백업 한계는 [검증 기록](../implementation/ROUTINES-AND-HISTORY-2026-09-18.md)을 따른다.

## 제출 확인 방법 초안 4줄

어디로 가나요: 승인 후 공개할 haruleaf.com의 계획 → 예시 · Haru 사용 흐름 확인.
세 단계 안에 무엇을 하나요: 돌아보기 → 계획 결과 → 원하는 집계 숫자를 선택합니다.
무엇이 보이면 통과인가요: 계획한 할 일 5, 완료 2, 지연 1, 막힘 1, 예상 105분, 실제 75분, 차이 −30분과 같은 대상의 근거; 새로고침 후 자료 유지.
안 될 때는 무엇이 보이나요: 연결/입력/다른 창 변경 오류와 최신 자료 확인, 불확실한 저장 결과 확인. 입력은 유지합니다.

## AI와 내 판단 초안 3줄

AI에게 맡긴 일: 코드·SQL·검증과 문서 정리.
직접 판단한 일: 단상/회고의 관계, 화면 흐름·서체 역할·기록 표시, Supabase/NAS 운영 방향.
AI 말을 따르지 않은 일: 루틴 누적 진행률과 손글씨를 사용하지 않고 날짜별 루틴과 세리프/산세리프 역할 구분을 선택.

공개 배포 후 실제 제품 URL/소스 revision·검증 시점/기준 날짜를 확인해 제출 초안을 확정한다. 지연 값은 검사 날짜에 따라 바뀐다. 사용자 지정 더미 허용 예외는 외부 평가 원문이 바뀌었다는 뜻이 아니다.
