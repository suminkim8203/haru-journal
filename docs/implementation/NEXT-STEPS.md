# 다음 구현 순서와 사용자 확인

요약: 현재 승인한 핵심 앱 코드와 실제 Supabase 연결은 진행됐고, 루틴·UI 보완→실제 영속 자료 검증→공개 배포·제출 검증 순서로 계속한다.

1. 승인 루틴 계약에 따라 기간 필수·반복 규칙/발생·예외 보존·범위 변경 구현. 기존 일반 계획 집계에 루틴 발생을 섞지 않는다.
2. 배치 편집/실행·배치 삭제 UI, 자료가 있는 화면·타이머·오류 복원·데스크톱/모바일 검사. 승인 기능/서체/정보 관계를 유지한다.
3. 검토 가능한 공개 자료로 실제 NAS 영속 저장·새로고침·기기 간 복원·최소 자료 수·집계/근거/개선점·JSON 내보내기 확인. 예시 허용을 자동 업로드 허가로 해석하지 않는다.
4. 최종 schema JSON, 확인 방법/AI와 내 판단, 소스/비밀값/삽입·백업 복구 검사.
5. 실행 가능한 공개 웹 배포안을 준비한 후 사용자 확인으로 배포. Studio 관리자 인증·기존 Supabase API 경로 유지.

합의한 가역적 구현/로컬 검사는 반복 확인 없이 계속한다. 새로운 제품 결정·공개할 실제 자료·공개 웹 배포처럼 실제 확인이 필요한 결과를 준비했을 때 구체적으로 알린다. 사용자에게 비밀번호·관리용 API 키를 채팅으로 추가 요청하지 않는다.
