# 로그인 중 비밀번호 변경 — 2026-09-23
> 2026-09-23 후속 결정: 사용자가 로그인 중 변경 버튼의 필요성과 기존 상단 3버튼 배치를 재검토했다. 아래 내용은 당시 구현·배포 이력이다. 현행 UI에서는 이 버튼을 제거하고, 로그인 불가 시 이메일 인증을 통한 비밀번호 재설정으로 변경한다. T07-C114의 과거 인증값 거절은 재설정 흐름에서 별도로 입증한다.


요약: 당시 로그인 중 비밀번호 변경을 구현·배포했고 사용자가 동작을 확인했다. 이후 화면을 재검토해 현행 UI에서는 제거했다. 변경 전 인증값의 서버 거절은 별도 HTTP 증거가 필요하다.

## 실제 흐름
- 가입/이메일 확인/이메일 인증을 통한 비밀번호 재설정과 별개로, 로그인한 사용자의 변경 화면이다.
- 사용자는 현재 비밀번호·새 비밀번호·확인값을 입력한다. 앱은 Auth getUser로 현재 계정을 확인하고 signInWithPassword로 현재 비밀번호를 재확인한다. 계정 ID가 같아야 updateUser를 호출한다.
- 8자 이상·공백 없음·한글/붙여넣기 허용·조합 강제 없음. UTF-8 72바이트 상한도 검사한다. 확인란은 실시간 비교한다.
- 같은 비밀번호 오류는 입력 수정으로 처리하고 이메일 인증부터 다시 하도록 안내하지 않는다.
- 성공하면 global signOut을 요청하고 개인 화면 상태를 비운다. 로그아웃 요청 실패는 변경 자체의 실패로 표시하지 않는다.
- 현재 비밀번호 확인은 이 화면의 흐름이다. Supabase의 모든 비밀번호 변경 API가 현재 비밀번호 재입력을 서버에서 요구한다는 뜻은 아니다. 기존 서버의 비밀번호 변경 시각 검사와 자료 접근 차단은 유지한다.

## 검증과 미확인
- 타입 검사 및 비공개 정적 빌드 성공. 기존 인증·비밀번호·서버 접근 경계 검사 11개 통과.
- release t07-password-dbacc4f168cc 배포, 공개 파일 19개 빌드 일치. DB 변경 없음. 근거 evidence/password-change-http.json.
- 실제 사용자가 입력하는 변경 성공, 변경 이전 인증값 재사용 HTTP 거절은 아직 확인 전이다. 자동 검사 통과로 이 증거를 대신하지 않는다.
- 소스: web/src/components/password-change.tsx, private-journal.tsx. 이메일 복구 화면은 auth-form.tsx로 별도 유지.
