# 일정·계획·돌아보기·보관함 동선 재검토 — 2026-09-29

요약: `Haru-navigation-study-01.html`은 폐기한다. 제호는 스크롤되는 꾸밈부로 두고, 네 주 메뉴만 한 줄로 고정한다. 일간·주간·월간은 일정이 선택된 때에만 같은 줄 오른쪽에 둔다. 나머지는 기능을 지우지 않고 정보의 첫 노출량과 이동 횟수를 줄이는 방향이다. 이 문서는 실제 코드 대조와 사용자 피드백에 따른 **정보 구조·와이어프레임 전 검토**이며 화면 개편의 구현·배포 기록이 아니다.

## 현재 구현과 즉시 수정

- `journal-app.tsx`: 네 주 메뉴, 사용 안내, 계정 링크가 같은 메뉴줄에 있고 스크롤 고정이 아니다. `schedule.tsx`: 일정 보기 전환은 일간 제목 옆에 있으며 날짜 이동 도구와 7일 띠가 연속해 날짜를 중복 표시한다.
- 일간 왼쪽 목록의 `할 일 찾기`는 계획 화면의 작업 검색과 겹친다. 보조 그룹 토글은 목록 뒤에 있지만 그룹을 펼치면 행이 원래 계획 순서에 나타나 상태가 섞인다.
- 선택된 할 일 상세는 메타 정보·버튼·기록 접힘 섹션이 한 상자를 크게 차지한다. 타임라인은 시작 시 06시 위치부터 보여 주며 현재 시각으로 초기 이동하지 않는다. 현재 시각선은 1px 선과 5px 점이다. 타임라인 아래 설명과 `오늘 마무리` 위 선도 별도로 있다.
- 계획 화면은 검색과 290px 높이의 내부 스크롤 목록이 본문 위에 먼저 나온다. 새 계획 편집기는 목록과 선택 계획의 제목 아래에 열린다. 계획 수정 편집기와 월간 색 편집기는 같은 React 자식 식별값을 사용하여, 운영 화면에서 편집기 영역이 반복 증식하는 현상을 재현했다. 두 자식의 식별값을 분리하는 소스 수정을 했으며 타입 검사와 75개 기존 검사가 통과했다. **운영 배포 및 실제 브라우저 재검증은 아직 하지 않았다.**
- 돌아보기의 계획 결과는 이미 계획명별로 묶이고 각 할 일은 개별 접힘이다. 그러나 계획 그룹 전체는 접히지 않아 항목이 많은 화면은 길다. 보관함의 회고는 전문이 모두 펼쳐진 카드로 순서대로 표시된다.

## 과제 조건과 충돌하지 않게 할 점

- 일간 검색창 제거는 계획 화면의 할 일 검색(T06-C18)이 남을 때 가능하다. 계획 페이지의 검색·필터·정렬 자체는 제거하지 않는다. `정렬 기준` 토글을 없애도 사용자가 실제 정렬 기준을 알 수 있어야 한다(T06-C20).
- 돌아보기의 근거를 달력으로만 치환해서 숫자→기록 이동을 끊을 수 없다. 계획별 접힘으로 먼저 정리하고 달력은 보조 탐색으로 검토한다.
- 계획 명시적 종료 조작과 할 일 완료율은 다른 값이다. 종료를 체크해도 5/10 완료가 10/10으로 바뀌면 안 된다.
- 화면 재구성은 T07 인증·개인 자료 보호, 5일 실제 관찰의 사실성/계산 규칙, 계정 내보내기·삭제를 변경하지 않는다.

## 9월 29일 후속 결정과 검토 시안 03

- 사용자는 위 표의 데스크톱 동선 개편에 동의했다. **이번 검토에서는 모바일 화면을 설계·비교하지 않는다.** 기존 서비스의 모바일 동작을 삭제한다는 뜻은 아니다. 위 문서에 남은 좁은 화면 관련 문장은 이전 제안의 이력이다.
- 대표 데스크톱 시안은 [Haru-navigation-study-03.html](studies/Haru-navigation-study-03.html)이다. 로그인 서비스의 자료나 DB와 연결되지 않는 화면 비교 파일이며, 실제 서비스에 배포된 화면이 아니다.
- 타임라인 추가 검토: 사용자의 제안에 따라 하나의 시간축에 예정 시간을 연한 회색 점선 블록으로, 실제 실행을 그 위의 진한 블록으로 겹쳐 표시한다. 좌측의 돌출 인덱스와 호버·키보드 포커스 설명으로 두 기록을 구별한다. 예정 블록의 위치 이동은 15분 단위 드래그·방향키로 시연한다. 실제 기록은 증거 자료라 드래그 수정 대상에서 제외한다. 서버 저장·겹침 확인·오류 복구·다른 날짜로 이동하는 경계 규칙은 시안 승인 후 설계해야 한다.
- 운영 화면의 ‘부산 여행’은 6/6, ‘부산 여행 종이 다이어리 꾸미기’는 1/1 완료이며 계획 페이지의 ‘마친 계획’에 들어가 있다. 그런데 일간 목록 본문에도 남는 현상을 읽기 전용으로 확인했다. `completedPlanHidden()`은 계획의 종료일이 아니라 마지막 할 일의 `completed_at` 다음 날부터 숨기는 반면, 계획 페이지는 완료가 모두 확인되면 곧바로 ‘마친 계획’으로 분류한다. 따라서 과거 기간의 할 일을 선택 날짜에 완료 체크하면 그날은 두 화면의 분류가 달라진다. 선택된 할 일을 예외로 본문에 남기는 조건도 있다. 실제 타임스탬프 원문은 별도 조회하지 않았지만 현재 두 화면의 값과 코드 조건은 확인했다.
- 구현 시에는 완료된 계획을 선택 날짜 기준으로 일간 왼쪽 **‘마친 계획’ 아래에만** 표시한다. 종료일이 지났지만 미완료이면 **‘기한 경과 · 미완료’ 아래에만** 표시한다. 두 접힘 영역은 진행 계획의 원래 순서 안에 재삽입하지 않고 목록 맨 아래에서 연다. 계획을 명시적으로 종료한 시각과 할 일 완료 개수는 분리해 보존한다.
- T06의 예정 배치와 실제 실행 기록, 숫자→근거 이동은 남긴다. 한 축으로 그리는 것은 표시 방식 변경이며, 예정과 실제를 데이터에서 합치지 않는다.
