# 6. 아키텍처 및 데이터 흐름

## 프론트엔드 구조

단일 HTML 파일의 정적 셸과 전역 함수형 렌더 구조입니다.

```text
브라우저 이벤트
  → document 단위 이벤트 위임
  → handleAction / change / input / drag handlers
  → ui 초안 변경 또는 commit(...)
  → data 깊은 복제 후 mutate
  → revision 증가
  → localStorage JSON 전체 덮어쓰기
  → render()
  → #app innerHTML 재생성
```

컴포넌트 프레임워크는 없습니다. `renderSchedule`, `renderPlans`, `renderReview`, `renderEditor` 같은 함수가 HTML 문자열을 반환합니다. 버전별 변경을 위해 이전 함수를 변수에 보관하고 새 함수로 다시 할당하는 래퍼가 여러 층 있습니다. 이 방식은 시안 보존에는 유용했지만 실제 개발 기반으로 그대로 확장하기에는 유지보수 위험이 큽니다.

- 재현 방법: 브라우저가 서로 다른 로컬 파일을 다른 저장 출처로 취급하는 환경에서 버전 파일을 각각 엽니다.
- 추정 원인: `file:` URL의 저장소 정책이 브라우저 구현에 따라 다를 수 있습니다.
- 확인된 사실: 코드와 변경 기록이 이 가능성을 명시합니다.
- 아직 확인되지 않은 사실: 사용자 개인 Pro 환경의 브라우저 정책과 기존 localStorage 이전 여부.
- 다음 조사 방법: 기존 시안 자료가 필요하면 현재 브라우저에서 별도로 내보내는 도구를 먼저 만들거나, 예시 자료는 새 서버 seed로 다시 구성합니다. 실제 증거로 간주하지 않습니다.

## 14.6 첫 화면 문구가 제출 요구와 다름

- 증상: 현재는 “서버·DB에 연결되지 않은 검토용 시안” 안내입니다.
- 재현 방법: 최신 HTML 첫 화면 상단을 확인합니다.
- 추정 원인: 프로토타입을 실제 서비스로 오인하지 않도록 의도적으로 바꾼 문구입니다.
- 확인된 사실: 프로토타입 단계에는 현재 문구가 정확합니다. 제출 앱에는 과제 지정 공개 안내 문구가 필요합니다.
- 아직 확인되지 않은 사실: 최종 앱의 배치 위치와 추가 설명.
- 다음 조사 방법: 서버 앱 완성 시 정확한 지정 문구를 첫 화면에 넣고 새 시크릿 창에서 확인합니다.

## 14.7 Archive/Settings 기능의 일부만 존재

- 증상: 보관함은 실질 기능이 없고 설정은 휴지통만 제공합니다.
- 재현 방법: 상단 보관함/설정 메뉴를 엽니다.
- 추정 원인: 시안 범위를 계획·시간·루틴·삭제 흐름에 우선 배분했습니다.
- 확인된 사실: 계획 보관/재개, 사유 관리, 전체 백업은 미구현입니다.
- 아직 확인되지 않은 사실: 각 기능의 최종 화면 세부 구성.
- 다음 조사 방법: 최신 승인 문서의 세 화면 묶음 순서로 필요한 화면만 검토합니다.

## 14.8 루틴 진행률 표시 정책 미확정
