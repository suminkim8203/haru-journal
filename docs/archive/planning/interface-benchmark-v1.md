# PlanDoSee Diary — 실제 서비스 구성 비교 및 화면 방향 v1.0

- 작성일: 2026-09-11
- 상태: 공식 제품·도움말 자료를 비교해 와이어프레임 방향을 판단한 문서. 앱 구현 완료 문서가 아니다.
- 비교 목적: 사용자가 화면을 보지 않고 사용성을 상상해 결정해야 하는 부담을 줄이고, 검증된 구성 원칙을 Plan–Do–See 목적에 맞게 선별한다.

## 1. 확인한 실제 서비스

## 2. 그대로 유지할 방향

1. 첫 화면은 `일정 > 오늘`의 세로 타임테이블이다.
2. 시간은 위에서 아래로 흐르고 계획과 실제는 좌우 두 열로 비교한다.
3. 화면 상단의 기록 진행 상태는 어느 메뉴에서도 확인한다.
4. 타임테이블 블록을 누르면 상세·수정 화면을 연다.
5. 일간을 기본으로 하고 주간·월간은 탐색과 개요에 사용한다.
6. 정확한 시각을 정하지 않은 일도 오늘 할 일 목록에 남긴다.
7. 하나의 할 일을 여러 시간 블록으로 나누어도 할 일 수는 하나다.

## 3. 수정할 방향

### 3.1 ‘미배치 할 일’을 ‘오늘 할 일’로 확대

오른쪽 영역에는 오늘의 할 일을 모두 보여준다.

- `시간 배치됨`: 타임테이블에 있는 오늘 할 일. 작업 시작·상세 열기 가능
- `미배치`: 오늘 하기로 했지만 시작 시각을 정하지 않은 일. 타임테이블에 배치 가능

시간표에 배치한 순간 목록에서 사라지지 않게 한다. 목록은 ‘무엇을 할지’, 타임테이블은 ‘언제 할지’를 빠르게 확인하는 서로 다른 역할을 가진다.

### 3.2 회고 통계와 하루 마감 분리

- `돌아보기`: 기간별 계획 결과·시간 사용·근거 기록·과거 회고를 조회
- `오늘 마무리하기`: 오늘 일정을 정리하는 짧은 단계형 화면

하루 마감 순서:

1. 오늘 미완료·열린 기록 확인
2. 선택적 회고 질문. 기록하지 않기와 질문 없이 마감 가능
3. 다음 계획 전에 다시 볼 문장 선택 또는 넘기기

돌아보기 화면에 빈 회고 입력란을 항상 노출하지 않는다. 회고 작성 부담을 줄이고 분석과 작성의 목적을 구분한다.

### 3.3 탐색 단순화

- 주요 메뉴: 일정, 계획, 돌아보기, 보관함
- 관리: 상단 설정 아이콘 안에서 휴지통·중단 사유·전체 백업으로 이동
- 데스크톱은 왼쪽 메뉴, 좁은 화면은 아래쪽 또는 간결한 탭 구조를 와이어프레임에서 검증

관리 기능은 매일 쓰는 기능이 아니므로 주요 메뉴와 같은 강조로 두지 않는다.

### 3.4 날짜 이동 강화

일간 화면 제목 아래에 가까운 날짜 띠를 두고 오늘로 돌아오는 동작을 제공한다. 월간은 전체 작업 편집 화면보다 날짜 찾기와 기록 유무 확인에 집중한다.

## 4. 채택하지 않을 구성

- 자동 일정 추천·자동 재배치: 제품 합의와 비용 범위에 맞지 않음
- 외부 캘린더 연동: 과제 6 범위 밖
- 앱·웹 사용 활동 자동 수집: 민감성과 구현 범위가 커서 제외
- 색상별 프로젝트를 전면에 두는 화면: 최소 포인트 색상 방향과 맞지 않음
- 모든 통계와 회고 입력을 첫 화면에 배치: 오늘의 실행 흐름을 방해함
- 시간표만 제공하고 할 일 목록을 숨김: 시각 미정 작업을 놓치기 쉬움

## 5. 와이어프레임 판단 기준

수정본은 다음 질문에 화면만 보고 답할 수 있어야 한다.

1. 지금 무엇을 기록 중인지 모든 메뉴에서 알 수 있는가?
2. 오늘 할 일이 시간표에 배치되었는지 목록에서 알 수 있는가?
3. 계획과 실제 시각을 같은 축에서 비교할 수 있는가?
4. 작업 상세에서 분 단위 시간과 막힘 이유를 확인할 수 있는가?
5. 숫자를 눌러 근거 기록으로 이동할 수 있는가?
6. 회고를 쓰지 않아도 하루를 마칠 수 있다는 점이 분명한가?
7. 루틴과 일반 할 일의 차이가 보이는가?

## 6. 현재 판단

일간 세로 타임라인과 오른쪽 할 일 목록을 함께 두는 데스크톱 구성을 유지한다. 목록은 배치 여부와 관계없이 오늘의 모든 일을 보여준다. 모바일에서는 목록을 타임라인 아래 또는 별도 Today 목록으로 전환한다. 돌아보기는 읽기 중심, 회고는 하루 마감 흐름으로 분리한다. 관리 기능은 설정으로 낮춘다.

이 판단은 실제 서비스의 구성 원칙을 참고한 제품 설계 결정이다. 해당 서비스 기능이 현재 프로젝트에 구현되어 있다는 뜻이 아니다.
