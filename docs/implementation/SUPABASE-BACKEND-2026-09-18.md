# Supabase 백엔드 전환·일정 및 기록 구현

요약: 실제 앱은 공개 anon 연결로 NAS Supabase의 제한된 DB 함수를 직접 호출한다. 기존 앱 서버 중계·관리용 비밀키 의존을 제거했고 NAS에 0001~0006을 적용했다. 전체 제품 완성·공개 웹 배포·저장 자료의 새로고침 복원 완료와 구분한다.

## 최신 사용자 결정과 구조

2026-09-18 사용자 지시: 백엔드는 Supabase의 기능으로 구현한다. 이전에 준비한 서버 전용 키 전달은 취소했으며 비밀키는 전송하지 않았다. React는 입력·표시·검색·필터·집계 표시를 담당하고 Supabase PostgreSQL은 입력 검증, 자료 관계·시간 제약, 쓰기 트랜잭션, 중복 요청/충돌 방지와 이력을 담당한다. 별도 Spring 서버나 Next 저장 API는 없다. Next.js는 현재 화면 빌드/로컬 제공에 사용한다.

앱은 haru_snapshot(), haru_command(requestId, expectedRevision, command, payload), haru_export()만 호출한다. 이 함수는 T06의 고정 단일 diary ID를 내부에서 사용하며 다른 diary를 요청하는 인자가 없다. journal 스키마의 테이블과 내부 함수에 anon/authenticated 직접 접근은 허용하지 않는다. 전체 NAS DB 권한, 관리자 인증, 사용자 소유권을 공개하지 않는다.

기존 SUPABASE_SECRET_KEY 및 APP_ORIGIN 중계 설정은 현재 앱에서 사용하지 않는다. 공개 연결 변수는 NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY다. 현재 자체 호스팅의 기존 anon JWT를 사용하며 role=anon임을 확인했다. service_role/비밀키는 화면에 넣지 않는다. 공개 키를 생성·회전한 작업이 아니다. 로그인 없는 공개 단일 다이어리라는 T06 조건을 유지한다.

## 실제 앱에 구현한 범위

- 일반 계획/할 일 생성·편집, 기간·성공 기준·우선순위·독립 예상 시간·여러 태그·수정 전 이력, 검색/필터/정렬.
- 일간/주간/월간 일정, 예정 배치 생성, 타이머·수기 실행 추가/정정, 휴식·중단 구간, 현재 시각 재계산.
- 완료 시 같은 할 일의 열린 실행을 원자적으로 종료. 완료 취소는 실행을 재개하지 않는다. 완료한 일은 라이브 기록/배치 금지, 수기 정정 허용.
- 수기 시간 직접 HH:mm/공통 시계, 부모 시간 범위와 비중복 검증. 막힌 이유는 실행 저장과 함께 명시적으로 저장한다.
- 실제 활동이 있는 할 일/날짜의 단상 1개. 날짜 독립 회고, 가져온 단상 당시 출처 스냅샷, 생략 가능한 하루 마무리.
- 보관함 회고 모음/휴지통, 회고만 책갈피·필터, 회고 안에서 편집, 날짜 일간 이동, 묶음 삭제/복원.
- 일반 계획 결과의 수·예상/실제/차이·같은 근거 이동, 날짜별 작업/휴식/중단 집계, 다음 계획 개선점 전달 및 새 계획과 함께 원자적 복사.
- DB 전체 자료 JSON 내보내기. 삭제 자료·수정 전 기록 포함, 요청 영수증·비밀값 제외. 실패 시 오류 파일을 내려받지 않고 오류 표시.
- 공통 앱 상태·요청 ID 재시도·revision 충돌·실패 입력 보존, 부분 완료 표시 갱신, 드래그 가능한 기록 미니바.

서체는 기존 3가족만 사용한다. 조선일보명조는 메뉴·주요 제목·사용자 기록, Pretendard는 조작·보조 정보·숫자, Cormorant Garamond는 직립 제호다. 모바일 빈 화면에서 역할별 CSS와 가로 넘침을 확인했으나 모든 폰트 실제 로딩/글리프와 자료가 많은 모든 화면 검증을 완료했다고 주장하지 않는다.

## 실제 NAS 적용과 검증

- Studio 인증된 SQL 관리 API에서 PostgreSQL 17.6, 기존 journal 스키마/앱 함수 없음 확인.
- NAS 내부에서 pg_dump -Fc로 적용 전 DB 백업. pg_restore --list로 백업 목록 확인. 실제 복원 시험은 미완료.
- SQL 0001~0006 적용: journal 테이블 15개, 앱용 공개 함수 3개, snapshot schemaVersion 4/revision 0. 기존 Studio 하위 경로·관리 인증·다른 서비스 라우팅 보존.
- 새 모델 적용 전 구간 복원 시 열린 다른 실행도 겹침으로 차단하도록 0004의 미적용 로컬 SQL을 보정했다. 이 버전이 처음 NAS에 적용됐다.
- 실제 anon SDK로 조회·내보내기 성공, 내부 스키마 조회/이전 중계 API 차단, 조작된 입력 거절 후 revision/자료 불변 확인.
- 실제 PostgreSQL에서 anon 역할로 생성→라이브 기록→원자적 완료→동일 요청 재시도→단상→회고→내보내기 검사. 하나의 트랜잭션을 rollback하여 자료를 남기지 않았다.
- 검사 후 plans/tasks/runs=0, revision=0 확인. 임시 공개 설정 가져오기 함수/컨테이너 파일 제거. 관리 비밀키를 개발 PC로 보내지 않았다.
- 실제 로컬 앱의 브라우저→NAS 직접 조회 성공. 390px 모바일 계획 입력·일간·회고 모음 달력·돌아보기 빈 화면 가로 넘침 없음.

## 로컬 검사와 한계

타입 검사·공식 프로젝트 생산 빌드 통과. 로컬 PGlite 테스트 36개 통과. SDK→임시 HTTP 어댑터→anon SQL 통합 검사 통과. 로컬 어댑터를 실제 PostgREST 증거로 대체하지 않는다. 실제 NAS 검사는 위 항목만 해당한다.

로컬 실행은 http://127.0.0.1:3217 이며 공개 웹 서비스 배포가 아니다. 모든 자료의 영속 저장/새로고침/기기 간 복원, 과제 최소 계획 1·할 일 5·종료 실행 3·0 아닌 집계는 DB에 실제 자료를 넣어 추가 검증해야 한다. 예시 허용은 자동 업로드 권한으로 해석하지 않는다.

## 남은 구현

루틴 규칙·일별 발생과 변경 범위/예외 보존, 승인 루틴 계획 기간 보정은 아직 미구현이다. 예정 배치 편집과 실행/배치 삭제의 UI도 후속이며 DB 명령은 있다. 자료가 있는 데스크톱/모바일 UI, 타이머 포커스·상세 편집·네트워크 실패의 브라우저 검사는 추가 필요하다. 최종 contracts/pds-schema-v2.json·제출 증거·백업 복구·공개 웹 배포는 미완료다.

Supabase Auth/Realtime/Storage/Edge Functions는 현재 앱 기능으로 사용하지 않는다. 가입·초대·이메일 확인·계정 활성화·최초 비밀번호 설정·변경·재설정은 앱 흐름에 없다. 관리자 로그인과 앱 사용자 인증은 별개다.

참고: [Supabase DB 함수](https://supabase.com/docs/guides/database/functions), [API 키 역할](https://supabase.com/docs/guides/getting-started/api-keys).
