# 현재 프로젝트 상태

요약: 일반 계획/할 일·일정/실행·단상/회고·보관함·집계/개선점·내보내기의 실제 React 코드와 NAS Supabase 백엔드를 연결했다. 승인한 공개 예시 자료의 실제 저장·새로고침·집계·내보내기를 검증했다. 루틴·일부 UI·공개 웹 배포는 아직이다.

## 실제 구현

- 기본 폴더 D:/workspace/haru-journal, GitHub suminkim8203/haru-journal.
- 로컬 작업 브랜치 codex/plan-task-fields. main과 원격 첫 저장 브랜치는 과거 범위이며 이번 코드가 main에 통합됐다고 설명하지 않는다.
- 기능 범위 및 검증은 [Supabase 전환·일정/기록 구현](implementation/SUPABASE-BACKEND-2026-09-18.md)을 따른다.
- 기존 Next 저장 API/관리 키 의존을 제거했다. 브라우저 Supabase SDK가 공개 anon 연결로 고정 다이어리 DB 함수를 호출한다. SQL 검증·트랜잭션·이력·요청 재시도와 RLS 내부 접근 차단 유지.
- 기존 NAS에 SQL 0001~0007 적용. 실제 테이블 15개와 앱용 함수 3개. 관리용 비밀키 PC 전송 없음. Studio 관리 인증 유지.
- 실제 NAS 조회/내보내기/잘못된 요청 차단, anon DB 트랜잭션 검사 후 rollback 확인. 이후 사용자 승인으로 공개 예시 계획 1개·할 일 5개·종료 실행 3개·단상 1개·회고 1개를 영속 저장했다. [검증 기록](implementation/PUBLIC-NAS-VERIFICATION-2026-09-18.md)을 따른다.
- 로컬 빌드·타입·37개 테스트·직접 SDK 임시 어댑터 통합 검사 통과. 실제 앱은 NAS 직접 조회를 확인했다.

## 미구현·검증 대기

- 루틴 계획 기간 필수 보정·반복 규칙/발생/예외·범위 변경 UI/API.
- 예정 배치 편집·실행/배치 삭제 UI, 자료가 있는 모든 화면/타이머/실패 복원 브라우저 검사.
- 별도 기기 간 복원 및 최종 제출 증거. 같은 PC의 새 SDK 연결·앱 새로고침 복원은 검증했다.
- 최종 schema JSON, 공개 웹 앱 배포, main 통합/원격 갱신, 백업 실제 복구 시험.

## 플랫폼 지원과 미사용

Supabase 사용자 Auth·Realtime·Storage·Edge Functions는 현재 앱에 사용하지 않는다. T06은 로그인 없는 공개 단일 다이어리다. 회원가입·초대·이메일 확인·계정 활성화·최초 비밀번호 설정·비밀번호 변경·재설정은 구현하지 않았다. 관리자 인증과 구분한다.

## 불확실한 부분

백업 생성·목록 검사는 실제 복구 성공 증거가 아니다. 롤백 검사는 영속 자료의 새로고침 복원 증거가 아니다. 공개 예시 5개가 있는 모바일 검사를 대량 자료·모든 UI·별도 기기 검증으로 확대하지 않는다. 현재 변경은 공개 웹 앱 배포가 아니다.

다음 순서는 [진행 계획](implementation/NEXT-STEPS.md)을 따른다. 과제 RULE·승인 제품/데이터/디자인 기준은 계속 유지한다.
