# T06 — Haru 제출 자료

계획(Plan) → 실제로 한 일(Do) → 돌아보기(See)를 연결하는 다이어리입니다. React/Next.js 화면과 자체 운영 Supabase를 사용하며, 자료는 서버 DB에 저장합니다.

## 주소

- 결과물: https://haruleaf.com/
- 소스: https://github.com/suminkim8203/haru-journal

## 짧은 확인 방법 — 4줄

1. 어디로 가나요: 결과물의 돌아보기 → 계획 결과로 이동합니다.
2. 무엇을 하나요: ‘Haru 기능 사용 기록’ 선택 → ‘막힘 1’ 선택 → 근거 할 일의 일간 상세를 엽니다.
3. 무엇이 보이면 통과인가요: 막힘 1과 근거 할 일 1개가 일치하고, 연결된 실행 시간·막힌 이유가 보이며 새로고침 후에도 같은 자료가 유지됩니다.
4. 안 될 때는 무엇이 보이나요: 입력·연결 오류 안내가 나타납니다. 입력값을 수정하거나 ‘최신 자료 확인’을 누르고, 저장 결과가 불명확하면 ‘이전 저장 결과 확인’으로 재확인합니다.

## AI와 내 판단 — 3줄

1. AI에게 맡긴 일: 화면·DB 구현, 과제 기준 대조, 자동 검사와 배포·문서 정리를 맡겼습니다.
2. 내가 직접 판단한 일: 신문과 개인 기록장 분위기, 서체의 역할, 제호 위치, 단상·회고 구분과 일정 화면의 사용 흐름을 직접 결정했습니다.
3. AI 제안을 따르지 않은 일: 루틴 누적 진행률과 불필요한 이동·중복 기록 표시를 줄였으며, 승인 시안과 다른 구현은 그대로 수용하지 않고 원래 디자인으로 복원하도록 했습니다.

## 입력 자료 설명

- ‘Haru — 6번 과제 구현과 제출 준비’에는 실제 대화에서 확인되는 검토·결정 활동을 할 일 5개로 사후 정리했습니다. 당시 미리 입력한 계획이나 실행 시간으로 제시하지 않습니다. 이 계획의 예상 시간은 미확인으로 0(미입력)이며 실행 기록은 없습니다.
- 직접 타이머로 남긴 종료 기록은 전체 3건입니다. ‘Haru 기능 사용 기록’, ‘계획 생성 테스트’, ‘SKT ALEPH’에 각각 1건씩 있습니다. 사후 정리 계획의 5개 할 일과 별도 자료입니다.
- 기능 검증용 예시 자료는 휴지통으로 옮겼으며, 실제 활동 3건에 포함하지 않았습니다. 첫 화면의 공개 안내에 따라 로그인 없이 자료를 볼 수 있습니다.
