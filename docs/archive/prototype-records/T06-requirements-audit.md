# T06 과제 기준·합의 누락 정정

> 후속 결정: T06-decisions-post-audit.md 참조. 사용자는 영구 삭제 시 실행 기록 등 하위 자료까지 삭제하는 범위와 나머지 단계 제안을 승인했습니다. 아래의 해당 ‘결정 필요’ 표시는 당시 감사 상태입니다. 루틴 별도 진행률은 스트레스 우려로 수정안 검토 중이며 과제 7은 보류합니다.

한 줄 요약: 누락이 있습니다. 과제 전문과 인계 요구사항을 기준으로 기획 기준표를 정정합니다. 앱·DB 구현 완료 보고서가 아닙니다.

## 근거와 적용 순서

- 과제 6 전문: 사용자가 이번 작업에 첨부한 pasted-text.txt 전체.
- 최초 인계 ZIP의 docs/requirements-v1.md(v1.5): 공개 편집, 서버 DB, 내보내기, 계획 상태, 삭제 정책 등이 이미 합의돼 있었습니다.
- 이후 사용자 승인: 일간 책임 분리, 루틴 규칙 목록, 삭제 후 실행 기록 보존, 기간 없는 루틴 묶음 및 한 달 기본 기간.
- 과제 필수 기준을 먼저 충족하고, 추가 합의 기능을 누락하지 않습니다. 최신 합의가 이전 합의를 대체한 항목은 따로 표시합니다. 대체 여부가 불분명한 파괴적 정책은 임의로 시행하지 않습니다.
- REQUIREMENTS-T06-baseline-02.13.md의 사용자·공개 편집 미정 및 저장 방식 선택 대기는 잘못된 안내였습니다. 하나의 공개 다이어리를 로그인 없이 보고 편집하고 서버에 유지한다는 기존 합의를 복원합니다.

| 계획 진행/마무리/보관/재개 및 계획 전체 삭제 | 요구사항 목록에 복원. 02.12의 할 일 삭제만으로 완료 아님 |
| 사용자 사유 목록 생성·선택·이름 변경·보관 | 자유 메모/멈춤 유형 변경과 별도 기능. 관리 화면·저장 관계 검토 대기로 복원 |

## 지금 수정하는 기획 원칙

1. 로그인·브라우저 전용 저장은 이번 과제 완성 방향이 아닙니다. 서버 저장과 공개 편집을 기준으로 합니다.
2. 과제의 일반 계획에는 기간·성공 기준·예상 시간·우선순위를 유지합니다. 기간 없는 루틴은 추가 기능인 ‘루틴 묶음’으로 분리하는 수정안입니다. DB와 화면 변경은 후속 반영이며 아직 구현하지 않았습니다.
3. 기본 돌아보기는 과제 C28~C32 공식을 따릅니다. 건너뛰기·중단 제외 완료율은 별도 이름의 루틴 보조 지표로만 제공합니다. 미삭제 항목을 기본 수치에서 몰래 제외하지 않습니다.
4. 삭제한 할 일의 실행 기록 보존은 최신 합의를 유지합니다. 기본 계획 결과에서 삭제 할 일을 제외하는 것과 별도 날짜별 실제 시간 이력 보존을 구분합니다. 30일 정책으로 무엇을 영구 삭제할지는 실행 기록 보존 범위와 함께 정해야 합니다.
5. 과제 최소 실제 자료는 완료 증거 없이 채워 넣지 않습니다. 계획 초안과 실행 사실을 분리합니다.

## 서비스가 지원하지만 현재 사용하지 않는 기능

외부 서비스 미선정·미연결. 이 문서는 특정 제품의 기능 보장이 아닙니다.

## 확인이 필요한 불확실한 부분

- 기존 사유 관리·계획 상태·PDF 등의 완전한 화면 흐름은 아직 검증되지 않았습니다.
- 30일 만료 대상과 최신 기록 보존 정책의 경계는 결정 필요입니다. 기존 합의를 통째로 삭제하거나 임의로 영구 삭제를 추가하지 않습니다.
- 과제 7은 주제 설명만 받았으며 전문·통과 기준·5일의 산정 방식은 미확인입니다.
- HTML 변경이나 DB 작업은 이번 감사 문서 작성으로 완료되지 않습니다. 기존 02.13은 보존했습니다.

## 우선순위

과제 필수/추가 합의/폐기 정책 구분 → 충돌 2건(루틴의 구분, 집계) 화면·데이터 수정 → 실제 DB·중복 제약·내보내기 → 사용자 실제 자료와 검증 → 추가 합의 기능의 미구현 항목 완성 → 제출 증거. 변경마다 과제 ID와 증거를 함께 기록합니다.
