# Haru 사용 흐름 재구성 검토 — 2026-09-29

요약: 기능이 부족해서가 아니라 같은 계획·할 일·기록을 화면마다 다시 찾아야 해서 사용이 복잡하다. 이번 문서는 실제 코드의 동선을 기준으로 한 개편안이다. 전체 화면 재설계나 운영 적용을 승인·완료로 표시하지 않는다.

## 현재 화면에서 확인한 문제

- 주 메뉴는 일정·계획·돌아보기·보관함 네 개다. 일정 안에는 일간·주간·월간이 있고, 계획·할 일 선택과 기록 편집은 여러 화면에서 반복된다. `journal-app.tsx`, `schedule.tsx`, `plans.tsx`에 각각 이동과 선택 상태가 있다.
- 평소 행동인 **오늘 할 일 고르기 → 시간 잡기 → 실제 기록 → 확인** 중 계획/할 일 수정은 계획 페이지, 배치는 일간, 기간 확인은 월간, 결과 근거는 돌아보기로 흩어진다. 작업 중 계속 화면을 오가게 된다.
- 일간에는 할 일 목록·선택 상세·타임라인·기록 이력·하루 마무리가 동시에 있다. 모든 정보가 중요해 보여 첫 행동이 불명확하다. 완료·기한 경과 계획도 같은 긴 목록에 섞였었다.
- 주간과 월간은 기간 개요인데 한때 할 일/시간을 반복 나열해 상세 화면과 중복됐다. 현재 계획 중심으로 바뀌었으나, 어디서 계획을 관리할지와 어떤 날에 실제로 일했는지의 구분이 더 명확해야 한다.
- 돌아보기의 집계·근거 이동은 T06 필수이므로 유지해야 한다. 숫자를 확인하다 일간으로 이동한 뒤 원래 맥락을 잃는 문제는 링크 뒤 화면 상태를 보존하는 방식으로 풀 수 있다.
- 보관함의 회고는 날짜 기준 기록이고 휴지통은 관리 작업이다. 둘 다 보관함에 놓여 있지만 주 사용자 행동의 일부로 보이지 않게 둬도 접근 경로는 유지해야 한다.

## 개편 원칙과 제안할 화면 역할

1. **오늘:** 오늘 할 일/현재 기록/간단한 시간 배치를 한 흐름으로 둔다. 첫 화면은 오늘의 우선 할 일과 진행 중인 기록을 먼저 보이고, 시간표·세부 필드는 필요할 때 연다. 드래그는 보조 수단이며 클릭으로도 같은 배치를 할 수 있어야 한다.
2. **계획:** 계획을 찾고 만들고 종료하는 관리 장소다. 최근/진행 계획 우선, 기한 경과/마친 계획은 접고 검색한다. 선택한 계획의 할 일과 수정 이력은 한 상세 안에 둔다. 월간 형광펜은 계획의 기간 개요이되 계획 편집의 대체물이 아니다.
3. **돌아보기:** 계획 결과, 날짜별 시간, 숫자의 근거, 다음 계획 개선점에 집중한다. T06의 집계 수식·근거 기록 이동·개선점 전달은 그대로 유지한다. 근거는 계획별로 묶고 필요한 기록만 펼친다.
4. **기록 찾기/보관:** 회고·지난 실행·휴지통·내보내기는 명확한 검색/관리 경로로 제공한다. 사용 빈도가 낮은 작업이 오늘 첫 화면을 차지하지 않게 한다.

## 한 작업의 동선 예시

| 의도 | 현재 | 제안 |
|---|---|---|
| 오늘 중요한 일 실행 | 일간 목록에서 계획 찾기 → 할 일 선택 → 상세 → 기록 시작 | 오늘 첫 화면의 우선 할 일 선택 → 같은 자리에서 기록 시작 |
| 시간을 바꾸기 | 목록에서 드래그 또는 상세의 배치 → 타임라인 재확인 | 선택한 할 일에서 시간 입력/드래그를 같은 편집기로 연결하고 저장된 위치를 즉시 보여줌 |
| 이미 끝난 계획 찾기 | 계획 선택기 전체 펼치기/일간 완료 토글/월간 탐색 | 계획 검색 또는 월간 기간 표시 → 하나의 계획 상세 |
| 숫자의 이유 확인 | 돌아보기 집계 → 근거 목록 → 일간 상세 | 집계 바로 아래 계획별 근거를 먼저 보여주고 일간 연결 시 선택 날짜·할 일 유지 |

## 기기별 원칙

- 데이터·상태·명령·권한은 웹/Windows/Mac/휴대폰에서 동일하게 쓴다. 화면을 그대로 축소해 앱으로 옮기지 않는다.
- 데스크톱은 목록과 선택 상세를 나란히 두되, 처음부터 둘 다 전체 길이로 펼치지 않는다. 시간표는 선택한 날의 핵심 작업에 보조적으로 붙인다.
- 휴대폰은 같은 정보를 한 화면씩 순서대로 보여주고, 현재 기록 제어를 접근하기 쉬운 곳에 유지한다. 드래그에 의존하지 않고 탭/입력으로 모든 기능을 완료할 수 있어야 한다.
- 기록·근거·필수 집계는 어떤 크기에서도 삭제하지 않는다. 깊이를 조절하고 한 작업에서 필요한 정보만 먼저 제시한다.

## 선행 순서

이번 승인 변경(계획 상태/색/완료 수/드래그 시간)을 안정화한 뒤, 실제 사용 과제를 3~4개 정해 현재 화면에서 클릭·스크롤·왕복 횟수를 기록한다. 그 결과로 오늘 화면과 계획 상세의 와이어프레임을 먼저 비교하고, 사용자가 확인한 뒤 시각 디자인·구현으로 넘어간다. 로그인/개인 정보 보호와 T06의 데이터·집계·근거 기능은 유지한다.

## 이번 단계에서 구현한 것과 구분

계획 선택기를 검색·상태별 목록으로 바꾸고 계획 종료/색 저장 규칙을 코드에 추가하는 작업은 이번 승인 범위다. 위의 **전체 내비게이션/첫 화면 개편은 아직 검토안**이며, 현재 사이트에 이미 반영됐다고 설명하지 않는다.
