# 계획 탐색·종료·월간 색/완료 수 운영 배포 — 2026-09-29

요약: 승인된 계획 사용성 변경과 배치 확인 수정을 기존 로그인 서비스에 배포했다. 운영 DB는 적용 전 HDD 백업을 남겼고, 현재 사용자의 기록은 변경하지 않았다.

## 적용 범위

- 기존 개인 인증·자료 격리 경로를 유지하며 계획 `marker_color`, `closed_at` 필드와 전용 명령을 추가했다. 새 계획의 색은 5색을 순환하고 기존 계획에도 생성 순서로 고정색을 배정했다.
- 계획 페이지를 검색·상태별 목록으로 바꾸고 계획 종료/다시 열기, 색 선택을 연결했다. 종료 후 새 할 일·시간 배치·실시간 기록 시작은 DB 명령에서도 차단한다. 기존 완료 수는 종료와 별도로 보존한다.
- 일간은 기한 경과·마친 계획을 접어두고, 월간은 계획명과 `완료/전체` 수를 표시한다. 예상 시간이 0분인 할 일의 드래그 배치는 저장 전 시간을 확인·편집하도록 바꿨다.

## 배포 순서와 근거

1. 기존 DB와 웹 상태, 외장 HDD `/backup` 연결, 정적 아카이브 해시를 읽기 전용으로 검사했다. 기존 웹은 `t07-palette-auth-f96719b`였고, 새 DB 필드 두 개는 아직 없었다.
2. `/backup/haru-operations/releases/t07-plan-ee1cd19/before-plan-lifecycle.dump`에 DB 전체 백업을 만든 뒤 `09_plan_lifecycle_marker.sql`을 트랜잭션으로 적용했다. 적용 후 새 두 필드와 전용 함수가 있는지 재검사했다.
3. 정적 웹 아카이브 SHA-256 `6a0b1343fc8afbbff6408bb1485b86b5ebe0022da77bd83652ffffe2c598fc5f`를 `/opt/haru-web/releases/t07-plan-ee1cd19/web`에 배치하고 기존 NGINX 설정을 유지했다. `haru-web` Compose 웹 컨테이너만 교체했다. 기존 릴리스는 복구용으로 남겼다.
4. 새 컨테이너 `healthy`, `https://haruleaf.com/`와 `/auth` HTTP 200을 확인했다. 로그인된 실제 브라우저에서 기존 할 일 15/16, 계획 검색·기한 경과·마친 계획 목록, 월간 계획명 옆 완료 수를 확인했다.

## 검증 한계와 다음 작업

- 실제 사용자 자료를 임의로 수정하지 않았다. 운영에서 새 계획 종료/재열기, 색 변경, 0분 예상 할 일의 새 드래그 배치 쓰기 동작은 별도 시험 자료로 확인해야 한다. 이 문서의 화면 확인만으로 쓰기 동작이 검증됐다고 해석하지 않는다.
- 독립된 격리 DB에서는 타 계정의 계획 종료 거절과 종료 후 새 작업 거절, 색 영속성, 완료 수 보존을 확인했다. 운영에서 다른 계정의 자료를 건드리지 않았다.
- T07의 실제 5일 사용자 관찰·사용 규칙 변경은 이번 UI 배포와 별개이며 아직 완료되지 않았다. 전체 내비게이션/첫 화면 재구성은 [사용 흐름 검토](USABILITY-RESTRUCTURE-REVIEW-2026-09-29.md) 단계다.
