# 일정 구조·우선순위 검토 — 2026-09-28

요약: 사용자 피드백에 따라 일간 목록의 높은 우선순위 표시, 주간·월간의 계획 중심 요약, 여러 날짜에 걸친 계획 띠, 월간 날짜→상세 이동, 돌아보기 근거의 계획별 묶음을 독립 시안으로 검토한다. **실제 앱과 DB에는 아직 적용하지 않았다.**

- [독립 시안](studies/Haru-schedule-structure-study-01.html): 예시 자료만 사용한다. 이 HTML은 서비스 화면이나 과제의 실제 5일 사용 기록이 아니다.
- 한 일반 계획의 할 일이 모두 완료되면 다음 날부터 일간 기본 목록에서 접는다. 검색·계획 상세·지난 기록에서 접근할 수 있는 경로는 보존한다. 루틴 누적 완료율은 추가하지 않는다.
- 높은 우선순위 할 일은 제목 앞 작은 붉은 점과 텍스트 `높음`을 함께 둔다. 색만으로 뜻을 전달하지 않는다. 보통·낮음의 기존 정보는 숨기지 않는다.
- 주간과 월간에는 계획명과 일반 할 일 완료 수/전체 수 및 그 비율을 먼저 보인다. 예: 10개 중 5개 완료 → 50%. 이는 계획 소속 일반 할 일의 비율이며 루틴 진행률·실행 시간 비율이 아니다. 실제 시간과 개별 예정/실제 기록은 일간 상세 및 기존 근거에서 유지한다.
- 월간의 계획 띠는 시작일~종료일을 나타낸다. 해당 날짜마다 실제로 실행했다는 뜻이 아니다. 날짜 경계와 주 경계에서 시각적으로 이어지되 각 날짜를 선택할 수 있어야 한다. 월간의 선택 날짜 상세에는 관련 계획과 그 안의 시간 미배치 할 일을 포함한 전체 할 일을 접고 펼쳐 보여준다. 날짜 선택 시 상세 제목으로 스크롤하고 키보드 초점을 이동한다.
- 여러 계획이 겹치는 날은 계획마다 별도 줄을 사용해 제목을 숨기지 않는다. 모바일 7열 달력에서는 글자가 매우 작아질 수 있으므로 실제 기기에서 확인하고 필요하면 월간 하단의 날짜별 계획 목록을 병행한다. 모든 계획명을 무조건 한 줄에 욱여넣지 않는다.
- 돌아보기 집계의 계산과 근거→상세 이동은 유지하고, 근거 목록만 계획별로 묶는다. 손으로 그은 숫자 밑줄은 기존보다 조금 두껍고 덜 휘게, 예상/실제 시간 밑줄도 선명하게 보정한다. 실제 SVG/이미지의 해상도와 모바일 렌더링은 구현 단계에서 확인한다.

## 구현 전 확인할 의미

과거 날짜에 보이는 완료율은 `현재 상태 기준`인지 `그날 종료 당시 기준`인지 사용자가 명시적으로 결정하지 않았다. 현재 비율을 과거 사실처럼 보이면 오해가 생기므로, 구현 시 `현재 완료율`로 표시하거나 종료 당시 값을 정확히 재구성할 수 있는지 코드와 저장 이력을 먼저 확인한다. 계획의 날짜는 예정 기간이며 실제 작업일은 실행 기록이 결정한다. 이 차이를 UI 문구로 유지한다.

과제 T06의 할 일 우선순위 저장·검색/필터/정렬(C15, C18–20), 집계 근거 이동과 C26/C31/C33, T07 개인 자료 접근 보호는 이 UI 변경으로 삭제하거나 축소하지 않는다. T07 실제 5일 관찰용 `하루 일반 할 일 최대 3개` 규칙 변경은 UI 우선순위 표기와 별개이며 소급하지 않는다.

현재 코드의 `monthly.tsx`는 날짜 셀에 할 일 최대 2개를 표시하고 `month-preview.ts`는 배치/마감 중심으로 항목을 추린다. `schedule.tsx`의 일간 목록에는 높은 우선순위 표시와 완료 계획의 다음날 접힘이 없다. `review.tsx`의 근거는 평면 목록이다. 이 문서의 내용은 구현 완료 보고가 아니다.
