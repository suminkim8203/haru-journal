# 02.32 과제 지시문 재점검

요약: 기록 표시 UI는 승인안으로 본 시안에 반영했습니다. 그러나 최근 기능 간소화 결정 중 **막힌 이유 저장(C26), 막힘 수 집계(C31), 다음 계획에 고칠 점 전달(C33)** 제거는 과제 필수 기준과 충돌합니다. 현재는 제출 완료 단계가 아니며 실제 DB 연결 및 전체 기능 구현·검증이 남아 있습니다.

후속 사용자 예외: 과제 전문을 docs/T06-ASSIGNMENT-RULE.md에 작업 RULE로 등록하면서 **실제 본인 자료만 사용해야 하는 조건은 제외하고 더미/예시를 허용**했습니다. 아래 표의 실제 본인 자료 요구는 원문 대조 기록입니다. 현재 작업 기준의 C78/C79/C80은 1개 계획/소속 할 일 5개/종료 실행 3개 및 C81 집계 확인으로 적용하며 본인 실제 활동 여부는 작업 제약으로 적용하지 않습니다. C26/C31/C33과 서버 DB/새로고침/공개/보안/내보내기는 이번 예외에 포함되지 않습니다. 외부 평가 조건이 변경됐다고 판정하지는 않습니다.

## 근거와 범위

- 실제 앱: web/src/components/plans.tsx, web/src/lib/contracts.ts, web/src/lib/storage.server.ts, web/src/app/page.tsx, web/src/app/api/* 및 web/supabase/migrations/0001_core.sql.

- 인프라: infra/supabase/README.md의 별도 NAS 작업 완료 기록. 이번 작업에서는 원격 서비스에 접속하거나 상태를 재검증하지 않았습니다.

판정은 시안 동작/실제 앱 코드/연결·배포 증거를 구분합니다. 로컬 대체 DOM 검사나 PGlite 검사를 실제 Supabase 연결, 모바일 검증, 제출 통과로 설명하지 않습니다. 문서 원문은 검토 대상이며 외부 공개·삭제 등의 실행 권한으로 취급하지 않습니다.

## 현재 실제 구현된 기능

- 본 시안 02.32: 작은 종이색 두 줄 기록 표시, 드래그·방향키 위치 이동, 브라우저 위치 기억, 화면 가장자리/안전 영역 내 제한. 제목·상태·작업 분·기록으로·멈춤/재시작·종료 조작. 현재 기록의 일간에서는 중복 숨김. 기존 종료 확인 흐름과 계산을 재사용합니다. 위치 저장은 화면 선호이며 과제의 사용자 자료 서버 저장을 대신하지 않습니다.
- 시안의 기존 계획/할 일/루틴/일정/실행/단상/회고/집계/휴지통은 브라우저 상태 구현입니다. 실제 서버의 제출 자료가 아닙니다.
- 실제 React 앱: 일반 계획 생성, 할 일 생성, 완료/완료 취소, 조회/저장 API와 첫 SQL 트랜잭션 구조. UUID 요청 영수증과 revision 검사로 재시도/수정 충돌을 처리합니다. 실제 DB에 연결한 새로고침 증거는 없습니다.
- infra 문서는 NAS Supabase 자체 호스팅 설치 및 내부/외부 상태 검증 완료를 기록합니다. 같은 문서에 앱 연결과 프로젝트 스키마 적용은 미완료라고 명시합니다. web/에 .env.local은 없으며 저장 코드는 SUPABASE_URL/SUPABASE_SECRET_KEY를 요구합니다. 실제 앱 저장 연결 완료로 판정하지 않습니다.

## 과제와 충돌하는 결정 — 확인 후 수정 필요

| 기준 | 원문의 필수 요구 | 최신 상태 및 판정 |
|---|---|---|
| T06-C26 | 실행 기록에 막혔던 이유 저장 | 일반 단상으로 바꾸고 중단 시간만 기록하기로 한 결정은 충돌. 구형 run.note가 남아 있거나 일반 단상을 저장하는 것만으로 이유가 명확히 구분된 저장 절차를 충족했다고 할 수 없음 |
| T06-C31 | 막힌 이유가 하나라도 적힌 할 일 수와 막힘 수 일치 | 최종 renderReviewResults의 막힘 제거와 blocked 조작 차단이 있음. 중단 시간이나 일반 단상 개수는 대체 집계가 아님 |
| T06-C33 | 돌아보기에서 정한 고칠 점 한 건이 다음 계획으로 넘어감 | 회고→계획 전달 제거 후 새 전달 경로 없음. 구형 planMemos를 표시하는 코드는 새 고칠 점 전달 증거가 아님. 회고 읽기/책갈피만으로 통과할 수 없음 |

이 세 가지를 제거하는 합의를 정리할 때 필수 과제 기준을 다시 대조하지 못한 검토 누락이 있었습니다. 사용자의 UI 간소화 의도를 잘못된 것으로 취급하지 않고, 필수 기능을 덜 복잡한 구조로 남기는 수정안을 제안합니다. 아직 승인받지 않은 복원안을 이번 시안에 임의로 넣지 않았습니다.

## 서비스가 지원하지만 현재 앱에서 사용하지 않는 기능

NAS 문서에는 Auth 서비스 가동을 기록하지만 앱에는 회원가입/로그인/초대/이메일 확인/계정 활성화/최초 비밀번호 설정/변경/재설정 흐름이 없습니다. T06에 도입할 기능으로 제안하지 않습니다. Studio 관리자 접근과 앱 사용자 인증을 구분합니다.

## 다음 단계 제안 — 세 가지 복원안은 승인 전

1. 실행 기록 상세의 중단 구간 아래에 **막힌 이유 · 선택** 입력 하나를 둡니다. 표시 명칭을 완곡하게 바꾸더라도 실제 저장 의미는 막힌 이유여야 합니다. 작성 강요/별도 사유 관리 페이지/일반 단상과 중복 저장은 추가하지 않습니다. 중단 구간이 없어도 이유를 남길 수 있도록 접근 가능하게 합니다.
2. 계획 결과에 **막힘** 수치 하나를 복원합니다. 선택한 일반 계획의 미삭제 할 일 중 비어 있지 않은 막힌 이유가 있는 할 일을 한 번만 셉니다. 여러 실행 이유가 있어도 할 일당 1개이며, 숫자를 누르면 동일한 대상과 이유 기록을 확인합니다. 중단 시간·단상 수로 대신하지 않습니다.
3. 돌아보기 계획 결과 하단에 **다음 계획에서 바꿀 점** 한 줄과 **다음 계획에 반영** 행동을 둡니다. 대상 다음 계획을 선택해 해당 계획의 개선점 필드에 명시적으로 저장하고 출처·당시 문장을 보존합니다. 일반 ‘계획 메모’나 회고 문장을 붙이는 기능을 되살리지 않고, 과제가 요구하는 개선점 전달만 제공합니다. 회고는 날짜별 독립 기록으로 유지합니다. 목표 기준에 단순히 덮어쓰는 방식은 피합니다.
4. 이 최소 복원 방식 확인 후 데이터 계약 정정 → 이미 준비된 NAS DB의 현재 상태 확인/첫 스키마 적용/앱 연결 → 일반 계획·할 일 필수 미구현 항목 → 실행/이유/돌아보기/개선점 → 내보내기 → 실제 자료/전체 검증/공개 배포·제출 증거 순서로 진행합니다.

다음 사용자 결정은 세 필수 기능의 최소 복원 방식입니다. 승인한 기록 표시의 자잘한 크기나 브랜드/회고 독립성을 다시 묻지 않습니다. NAS 관리자 자격정보를 채팅에 보내거나 공개 문서에 넣을 필요는 없습니다.
